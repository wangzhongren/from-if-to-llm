# 第 30 章：回到第一行代码

## 本章的问题

这是全书的最后一章。按这本书的规矩，每一章都要从上一章留下的问题开始，
但这一章不留下问题了——所以它要做的只有一件事：**回头看看起点。**

全书的第一行代码是第 2 章写的：

```python
if "手机" in words:
    print("科技")
```

那时候我们的问题是："几万个词，难道写几万个 if？"

于是我们一路往下走：把 if 变成数字、让程序自己调权重、加中间层、加激活函数、
自己写自动求导、让词变成向量、平均上下文、Attention、Q/K/V、多头、位置编码、
残差、LayerNorm、MLP、Transformer Block、因果掩码、语言模型、自回归生成、
换引擎、真分词、GPT 的选择、规模、对齐……

这一章把两头放在一起：**第 2 章那个 if/else 分类器，和 29 章之后这个模型，
做同一个任务。**

## 最简单的尝试

任务还是第 1 章那件事：给句子分类（科技 / 食品）。

**第 2 章那边的做法**（`before.py`）：切词，然后一串 if。

```python
TECH_WORDS = ["手机", "芯片", "电脑", "发布", "华为", "小米"]
FOOD_WORDS = ["好吃", "很甜", "甜", "香蕉"]

def classify(words):
    for word in words:
        if word in TECH_WORDS:
            return "科技"
        if word in FOOD_WORDS:
            return "食品"
    return "食品"      # 一个关键词都没碰上，先猜食品
```

**第 30 章这边的做法**（`after.py`）：把语料写成"句子 + 类别"的样子，
然后让语言模型去预测类别那两个字的概率。

```text
苹果发布新手机分类：科技。
苹果很甜分类：食品。
```

测试的时候，把"句子分类："当成提示，看后面接"科技"和接"食品"哪个概率高——
这就是第 20 章那句话：**分类就是下一 token 预测。**

**打平了。**

花了 30 章造出来的东西，在这个测试上没有赢过那 4 行 if/else。
这一点应该老老实实说清楚，而且它值得想一想：

**这批句子本来就是照着那堆规则写的。** 规则是人写的，写规则的人知道答案；
模型是从数据里学的，而数据也是我们照着规则造的。
在自己的考卷上，规则当然满分。

所以差距不在这张成绩单上。差距在下面两处。

### 一、把规则的词删掉几个

假设写规则的时候，我们没想到"华为"和"小米"这两个品牌：

```text
规则表                    成绩
------------------------------------------------------------------------------
完整规则                  14/14
删掉'华为''小米'          13/14
再删掉'发布'              12/14
再把'甜'删掉              12/14
```

只掉了 1 分、2 分——这和"规则很脆弱"的直觉不太一样。原因是我们的规则是**冗余**的：
"小米发布新手机"里，"小米""发布""手机"三个词都在科技词表里，删掉一个还有两个兜底。
人手写规则就是会这么写：多写几条，互相兜着。

但看清楚掉的是哪一句：删掉"小米"之后，"小米直播带货"直接掉进最后那句
"一个关键词都没碰上，先猜食品"。**规则的知识就是那张词表本身，一个字都不多。**

### 二、把模型的训练数据删掉一部分

做同样的事：训练语料里把所有带"华为"和"小米"的句子都删掉，重新训练。

```text
模型                          完整数据    删掉'华为''小米'
------------------------------------------------------------------------------
苹果发布新手机                科技（1.00）科技（1.00）
华为发布新电脑                科技（1.00）科技（1.00）
小米发布新手机                科技（1.00）科技（1.00）
苹果很甜                      食品（1.00）食品（1.00）

完整数据训练：14/14
删掉两个品牌的句子之后：12/14
```

模型也掉了分，但没有像规则那样直接崩掉，而且它**仍然认得出"华为发布新电脑"**——
因为它在语料里学到的不只是"华为""小米"这两个词，还有"发布""新""电脑"这些片段
以及它们之间的关系。**规则的知识写在规则里，模型的知识写在参数里**，
前者删了就没了，后者是一个整体的、互相支撑的东西。

## Python 实现

最后一章的代码只有两个新东西，都很小。

**一、怎么用语言模型做分类。** 把类别当成"下一个要预测的东西"：

```python
def label_probabilities(model, sentence):
    prompt = sentence + "分类："
    ids = encode(prompt)
    scores = {}
    for label in LABELS:
        label_ids = encode(label)
        # 把"句子分类：科技"整段喂进去，只把最后两个字（标签）的对数概率加起来
        logprobs = model(torch.tensor([ids + label_ids]))[0].log_softmax(dim=-1)
        total = sum(logprobs[len(ids) - 1 + offset, token].item()
                    for offset, token in enumerate(label_ids))
        scores[label] = total
    # 归一化成概率
    values = torch.tensor([scores[label] for label in LABELS])
    probabilities = values.softmax(dim=-1)
    return {label: probabilities[i].item() for i, label in enumerate(LABELS)}
```

注意这里的每一行，都能在之前的章节里找到出处：
`encode` 是第 1 章的分词，`log_softmax` 是第 5 章的概率，
把对数概率加起来是第 20 章的"整段序列的概率"，
`softmax` 归一化是第 5 章同一个函数。

**二、生成。** 就是第 23 章那件事，一行不多：

```python
@torch.no_grad()
def continue_text(model, prompt, n_new=24, seed=0):
    generator = torch.Generator().manual_seed(seed)
    tokens = encode(prompt)
    for _ in range(n_new):
        window = tokens[-model.block_size:]
        logits = model(torch.tensor([window]))
        next_token = sample(logits[0, -1], generator=generator)
        tokens.append(next_token)
    return decode(tokens)
```

`before.py` 那半边的代码更简单——它就是第 2 章的那几行。两边的代码量差着三个数量级，
而在这个测试上的分数是一样的（14/14 对 14/14）。

## 它解决了什么

这一章没解决新问题。它做的是**结算**。

30 章之前，我们手上是 4 行 if，它的规则是人写的，知识在词表里，改一次要人手改，
遇到没想到的说法就没辙。

30 章之后，我们手上是 109,312 个参数（真到了 GPT-3 是 1750 亿个），
它的规则是学出来的，知识在参数里，改一次要重新训练，
遇到没想到的说法还能靠上下文猜。

而中间那 30 章，我们**没有从任何地方抄来一个模块**。每一个零件都是在前面某一章里，
因为"上一章的做法不够用"被逼出来的。这就是这本书想让你看到的事：

> **LLM 不是从天而降的复杂机器。**
> 它可以被看作一个极其庞大的、能够学习内部表示和上下文关系的
> **连续条件分类系统**——连续，是因为它给的是概率而不是一个是非；
> 条件，是因为它每输出一个 token，都以前面所有 token 为条件。

一句话说清楚：**它做的事和我们第 2 章做的是同一件事——
看着一段文字，给出一个判断。只是它把"判断"拆成了几十亿次概率输出，
把"规则"换成了参数，把"人写"换成了"学"。**

## 它还解决不了什么

这本书到此结束了。所以这一节不引出下一章，而是把**它没讲的东西**列出来——
它们都是真实存在的、重要的、我们刻意绕开的东西。

**一、真正的预训练数据。**

我们的语料最多 16 万字，而且是我们自己造出来的。真实的预训练数据是几万亿个 token，
从网页、书籍、代码、论文里爬来，然后要经过一整套清洗流程：去重、去广告、
去有害内容、按质量分层、按领域配比。**这一步对最终模型的影响，比很多架构选择都大**，
而这本书里一行都没写。

**二、分布式训练。**

我们全程在一台笔记本的一个 CPU 上跑。GPT-3 级别的训练要用几千张 GPU，
通过数据并行、张量并行、流水线并行拼在一起；要处理通信、容错、断点续训、
混合精度、梯度累积、激活重计算……这些工程问题里，任何一个都可能让训练失败。
这本书里提到的"`.to("cuda")` 一行就好了"，在真实规模下只是万里长征第一步。

**三、对齐的细节。**

第 29 章我们用一个 20 行的 DPO 讲完了偏好对齐。真实世界里它是：
几万到几十万条人类标注的偏好数据、训练好的奖励模型（reward model）、
带 KL 约束的强化学习（PPO）、一堆防止模型"钻空子"的技巧（reward hacking）、
以及"安全对齐"那一整个方向。而这本书只讲了它的骨架。

**四、多模态。**

我们从头到尾只处理文字。今天的模型看图片、听声音、跑代码。
输入形式变了以后，模型的结构、训练目标、数据的构造方式都会变——
这本书里的每一个零件都要重新想一遍怎么接。

**五、会"想"的模型。**

第 23、24 章我们观察过"它为什么看起来像在思考"，结论是它只是在预测下一个 token。
但最近几年出现了一类模型：先把推理过程写出来，再给答案；
用强化学习奖励"想对了"的过程；推理时多花算力换更好的答案。
它们在训练目标和推理方式上，都和我们这本书里做的东西不一样。

**六、而最重要的一样，是我们始终没能解决的那个问题：**

> 它到底"理解"了什么？

这本书一直绕开这个问题。我们只看输入输出、只看 loss 数字，
因为那是我们唯一能测量的东西。一个 loss 0.46 的模型能背下整首诗、
能答对 14 道分类题——但它"懂"苹果是什么吗？它知道苹果是能吃的、
长在树上的、会腐烂的东西吗？还是它只是知道"苹果"后面常常跟着"很甜"？

这个问题在 30 章里没有被回答，也不在这本书能回答的范围内。

但至少现在，你知道它是由什么做成的了：不是魔法，是一堆你亲手写过的东西，
和一个足够大的、能装下这些规律的容器。
