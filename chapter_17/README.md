# 第 17 章：层数多了反而学不会

## 本章的问题

第 16 章结束时，我们的模型长这样：

```text
词向量 + 位置编码 → 一层多头 attention → 输出
```

一层。位置编码解决了"谁在前谁在后"，这一层 attention 也干得不错。

但第 16 章的模型有个特点：**它没有"学习"这一步。** 那一章的注意力权重是我们直接算出来看的。要问"堆起来会怎样"，光看前向是看不出来的 —— 得让它真的训一训。所以这一章我们先把这些零件串成一个能训练的模型，再往上堆。

上一章最后留下了一个问题：**"把两层注意力直接首尾接起来，训练会发生什么？"**

这一章我们就来回答它。而且答案比"会出问题"更奇怪一点：**两层还行，四层就不行了。**

在第 7 章，我们的答案是"中间加一层"；在第 15 章，我们的答案是"多几个头"。**"不够就加"是这本书里最常用的招数**，所以我们很自然地会想：堆就是了。

我们先老老实实试了一下。请打开 `before.py`：它把第 13–16 章一路搭出来的零件（词向量、位置编码、多头 attention）串成一个能训练的模型，然后**把这个模型复制了 4 份**，一层接一层。除了层数，什么都没改。

任务是我们在这一部分一直用的那两句话：

```text
我 昨天 在 商场 看到 苹果 刚刚 发布 的 新 手机
小王 把 书 给了 小李 因为 他 明天 考试
```

我们把其中**一个词**换成 `<空>`，让模型把整句话还回来。这个任务不难，甚至有点笨：最省事的解法就是"照抄一遍，只在空位上补一个词"。这也正是我们要的 —— 如果连"照抄"都学不会，问题就很明显了。

## 新机制

到这里我们必须先想清楚一件事：**为什么"多堆一层"会让模型变差？**

一层 attention 做的事是：每个位置看看所有位置，按相似度把它们的 `V` 取回来加权平均，然后交给下一层。那么第 2 层拿到的是什么？**是第 1 层产出的、已经被"重新混合"过的向量。** 第 3 层拿到的是第 2 层的产物……

问题就出在"拿到的是产物"这五个字上。

我们可以这样想：如果每一层都**用一个新算出来的东西，把上一层的结果整个替换掉**，那么第 8 层的输入，已经被替换了 8 次。原来那个词的信息还在不在？全看这 8 次替换里每一次有没有恰好把它留下。

而我们的任务，最省事的解法是什么？是**照抄**。也就是说，我们其实希望这个模型学会一件事：

> 这一层，请什么都不做，把输入原样传给下一层。

可是在一个"替换"式的网络里，"什么都不做"是最难学的一件事 —— 每一层都得用自己的参数（一次矩阵乘法加一次加权平均）去凑一个恒等映射。层数越多，越难凑。

所以新机制是：

**不要替换。加。**

```python
x = x + layer(x)
```

我们不再让这一层"产出下一层的输入"，而是让这一层**产出"要改动的东西"**。它的含义完全不同了：

- 在"替换"式里，这一层必须学会"我要输出什么"。
- 在"加上"式里，这一层只需要学会"我要改什么"。如果不需要改，把输出趋近于 0 就行了 —— **这才是"什么都不做"的正确表达方式。**

这条从 `x` 直接连到后面、绕过这一层的线，我们叫它**残差连接**（residual connection），那个加上去的分支叫**残差**。"残差"这个词的意思是"剩下的、没被解释的那部分" —— 这一层不需要解释整个输出，只需要解释"相对于输入还差了点什么"。

还有一个更实在的好处。第 9 章我们讲过，反向传播是沿着原路把梯度倒着送回去的。在"替换"式里，梯度要穿过一层又一层的矩阵乘法和 softmax，每穿一层都要乘一个系数，穿 8 层就可能被乘成 0。而在"加上"式里，`x = x + layer(x)` 这条路上的导数是

```text
d(x + layer(x))/dx = 1 + layer'(x)
```

那个 **1** 就是一条直通车道：梯度可以不走任何矩阵乘法，原封不动地回到最前面几层。

## Python 实现

打开 `after.py`。它和 `before.py` **只有一个字的差别**：

```python
def forward(self, tokens):
    x = embedding(self.p["tok"], tokens) + self.p["pos"]
    for layer in self.layers:
        # before.py 里是这一行：
        #   x = self.attention(x, layer)
        # after.py 里是这一行：
        x = x + self.attention(x, layer)
    return x @ self.p["Wout"]
```

`self.attention(x, layer)` 一整个函数（拆头、算分数、softmax、加权平均、合并、输出投影）一个字没改，就是第 14、15 章那个。改的只是"算完之后怎么用它"。

另外注意初始化那一行：

```python
s = 1.0 / np.sqrt(d_model)
```

每个权重都是一个标准差 `1/sqrt(d)` 的随机数。这不是新东西，从第 8 章起我们一直这么干。之所以要在这里提一句，是因为下一章你会发现：加了残差以后，这条规矩已经不够用了。

还有一件事值得注意：**第 0 步的 loss 反而变大了**（旧的 3.15，新的 9.39）。这不是 bug，是残差连接的另一面 —— 每一层都往上加一点东西，加 4 次，数值自然更大。这个"变大"在 4 层的时候还不要紧，但它是一颗定时炸弹，下一章我们就会踩到它。

## 它解决了什么

回到那张表，把两半合起来看：

| 层数 | 无残差 | 有残差 |
|---|---|---|
| 1 | 0.0096，20/20 | 0.0096，20/20 |
| 2 | 0.0030，20/20 | 0.0027，20/20 |
| 4 | **2.0343，2/20** | **0.0014，20/20** |
| 8 | **2.3451，1/20** | 数值炸了 |
| 16 | **2.3460，0/20** | 数值炸了 |

1 层和 2 层的时候，两种写法都行 —— 所以第 16 章的模型一直是好的，这个毛病要"堆起来"才暴露。

从 4 层开始分家了：**旧写法彻底学不动（loss 2.03 卡死），新写法 20 个空位全填对。**

一句话总结这一章的收获：**残差连接让"深"变得可能。** 不是让模型变得更聪明，而是让"堆 8 层"这件事不再等于"把输入搅烂 8 次"。新加的一层从"我要输出什么"变成了"我要改什么"。

## 它还解决不了什么

现在再看表的下半张：`有残差` 那一列。

8 层 —— `nan`。16 层 —— `nan`。

不是"学得慢"，是训练**当场就炸了**。而且注意第 1 步的 loss：1 层是 4.52，4 层是 9.39，8 层是 **29.77**，16 层是 **446**。模型还没开始学，数值就已经涨上去了。

原因很直白，就在我们刚写下的那一行里：

```python
x = x + self.attention(x, layer)
```

每过一层，就往上加一个新的向量。如果每一层加进来的东西和原来差不多大，那么过 8 层以后，`x` 的长度就会涨好几倍；再过 16 层，就是几十倍。第 8 章的初始化规矩（每个权重 `1/sqrt(d)`）是**按一层**设计的，它管不了"加 8 次"。

所以下一章的问题很具体：

> **加了残差以后，每一层都在往 `x` 上叠东西。8 层叠下来，`x` 里的数已经涨到没法训练了 —— 我们怎么让每一层拿到手的数，不管在第几层，尺度都差不多？**

带着这个问题，我们进入第 18 章。
