# 第 2 章：用 if/else 教机器分类

## 本章的问题

上一章最后留下了一个问题：

> 词拆出来了，怎么知道一句话属于什么类别？

先把"类别"这件事说清楚。我们手上有一批句子，每一句都已经标好了类别：

```text
科技：苹果发布新手机 / 苹果发布新芯片 / 华为发布新电脑 / 小米发布新手机 / 苹果芯片很强
食品：苹果很好吃 / 苹果很甜 / 香蕉很好吃 / 这个苹果真甜 / 苹果做成派
```

一共 10 句，5 句科技，5 句食品。我们要写一段程序：**输入一句话，输出它属于哪一类。**

第 1 章给了我们什么？每句话变成了一串编号：

```text
苹果发布新手机   -> [0, 1, 2, 3]
苹果发布新芯片   -> [0, 1, 2, 4]
华为发布新电脑   -> [6, 1, 2, 5]
...
苹果很好吃       -> [0, 9, 8]
苹果很甜         -> [0, 9, 10]
```

编号是有了，但程序看着这 10 串数字，看不出前 5 串和后 5 串有什么区别。
它不知道 `3` 号（手机）和 `8` 号（好吃）意味着什么——**编号本身不说明任何事**。

## 最简单的尝试

既然程序已经能认出"这句话是第几句"，那最直接的做法就是：**把答案也一起背下来。**

```python
KNOWN_LABELS = {
    (0, 1, 2, 3): "科技",
    (0, 1, 2, 4): "科技",
    # ... 一共 10 条
}

def judge_by_lookup(sentence):
    ids = tuple(to_ids(split_sentence(sentence)))
    return KNOWN_LABELS.get(ids, "不知道")
```

跑 `before.py`：

```text
语料里的 10 句话
  [对] 苹果发布新手机     答：科技
  [对] 苹果发布新芯片     答：科技
  ...
  正确 10/10

语料之外的 4 句话
  [错] 苹果发布了新手机     答：不知道   真实：科技
  [错] 苹果发布新电脑       答：不知道   真实：科技
  [错] 香蕉很甜             答：不知道   真实：食品
  [错] 机器人发布新手机     答：不知道   真实：科技
  正确 0/4
```

背过的 10 句全对，没背过的 0 句对。

这不是"没背够"。就算我们把语料扩大到 10 万句，也还是这样：
**只要句子里的块对不上，它就一个字都说不出来。**
"苹果发布新电脑"和它背过的任何一句都不是同一串编号，所以它不知道这是科技。

## 实验

跑 `experiment.py`。

**实验一：规则是补出来的，不是想出来的。**

```text
==================================================================
实验一：补丁史
==================================================================
  第 1 版  只有一条规则  正确  2/10   答错 8 句：苹果发布新芯片、华为发布新电脑、苹果芯片很强……
  第 2 版  补上科技词    正确  5/10   答错 5 句：苹果很好吃、苹果很甜、香蕉很好吃……
  第 3 版  补上食品词    正确 10/10   答错 0 句：无

  补到第 3 版才全对。注意每一版之间隔着的不是'思考'，是'跑一遍看看错在哪'。
```

**实验二：一条规则都不改，只调换两条规则的位置。**

```text
  after.py 里的顺序      正确 10/10
  调换两条之后           正确  6/10

  调换之后答错的句子：
    苹果很好吃         答：科技   真实：食品
    苹果很甜           答：科技   真实：食品
    这个苹果真甜       答：科技   真实：食品
    苹果做成派         答：科技   真实：食品
```

规则一条没多、一条没少，只是把两条规则从后面挪到了前面。10/10 掉到 6/10。
**顺序，也是规则的一部分。**

**实验三：拿语料之外的句子考它。**

```text
  [错] 苹果好香             答：科技     真实：食品
  [对] 电脑好贵             答：科技     真实：科技
  [对] 香蕉派很好吃         答：食品     真实：食品
  [错] 苹果配奶油           答：科技     真实：食品
  [对] 机器人发布新手机     答：科技     真实：科技
  正确 3/5
```

5 句里对 3 句。看起来还行，但答错的两句错法完全不一样：

- 「苹果好香」——"香"不在词表里，规则根本看不见它；
- 「苹果配奶油」——一个关键词都没有，只剩"苹果"，兜底规则猜了"科技"。

## 新机制

这一章没有新公式。它只有一个转变：

> **把"记住答案"换成"记住判据"。**

背答案的做法是：这句是科技，那句是食品。
写规则的做法是：**句子里有"手机"，就是科技。**

看起来只是换了个说法，但性质完全不一样了。规则看的是"句子拆开之后，里面有没有某个词"。
于是：

- 句子长一点、短一点，无所谓——只看词在不在；
- 词序变了，无所谓——只看词在不在；
- **句子里的其他词我全都不认识**，也无所谓——只要我的关键词还在。

这就是为什么实验三里「机器人发布新手机」能答对：句子里的"机器人"三个字，
一个都不在词表里，全变成了 `<UNK>`，但规则看的是"发布"，它还在。

代价是，规则得我们自己写。写完长这样（`after.py` 里就是这些）：

```python
def judge(words):
    if "手机" in words:
        return "科技"
    if "芯片" in words:
        return "科技"
    if "电脑" in words:
        return "科技"
    if "华为" in words:
        return "科技"
    if "小米" in words:
        return "科技"
    if "发布" in words:
        return "科技"
    if "好吃" in words:
        return "食品"
    if "很" in words:
        return "食品"      # 这条很危险，见下面的注释
    if "甜" in words:
        return "食品"
    # ...
    if "苹果" in words:
        return "科技"      # 光看见"苹果"，猜一个
    return "不知道"
```

从上往下试，**谁先命中就返回谁**。所以顺序是有意义的：

- `if "很" in words` 这条规则很危险——"很"也出现在「苹果芯片很强」里。
  它现在没出错，纯粹是因为"芯片"那条排在它前面，先把这句拦下了。
- `if "苹果" in words` 这条是整个规则堆的兜底。"苹果"在两个类别里都出现，
  它自己决定不了任何事。放在后面，前面的规则能先说话；放到前面，
  它就会把「苹果很甜」这种句子抢过去——实验二里 10/10 变成 6/10，就是这么来的。

## Python 实现

完整代码在 `after.py`。它做两件事：

```python
# 第一步还是第 1 章那套：把句子拆成词
words = split_sentence("苹果芯片很强")     # ['苹果', '芯片', '很', '<UNK>']

# 第二步：交给规则去判
judge(words)                              # '科技'
```

`judge` 本身没有任何技巧，就是一堆 `if` 从上往下试。值得看的只有两处：

```python
if "很" in words:
    return "食品"
```

这一行是整份代码里最脆弱的地方。

它是补第 3 轮补丁时，和"甜""香蕉""派"一起加进去的。当时的想法很朴素：
"很"出现在「苹果很甜」「苹果很好吃」里，那它看着像食品那边的线索，加上吧。

加的时候没注意到：「苹果芯片很强」里也有个"很"。

它能用，纯粹是运气加顺序——因为"芯片"那条排在它前面，先把那句拦下了。
哪天有人把"芯片"那条往后挪一格，它立刻就坏。

（顺带说一句：这条规则其实是**多余的**。练习 2 会让你把它整行删掉，看看正确率变不变。）

```python
if "苹果" in words:
    return "科技"
```

这条更直白：**我们压根没解决"苹果"的问题，我们只是猜了一个。**
猜"科技"是因为前面 5 句科技里"苹果"出现得多。这不是判断，这是押注。

这份代码读起来是什么感觉，你翻一眼 `after.py` 就知道了：8 条补丁，一层套一层，
每条后面都有一句"这条是补的"。**它的样子就是它的出身。**

## 它解决了什么

它第一次让程序答出了语料之外的句子：

| | 背句子（`before.py`） | 写规则（`after.py`） |
|---|---|---|
| 语料里的 10 句 | 10/10 | 10/10 |
| 语料之外的句子 | 0/4 | 3/5 |

更具体地说，是实验三里的这一句：

```text
  [对] 机器人发布新手机     答：科技     真实：科技
```

"机器人"这三个字，词表里一个都没有，全变成了 `<UNK>`。
第 1 章的程序拿这种句子毫无办法——编号序列对不上任何一句背过的话。
写规则的程序答对了，因为规则只关心"有没有'发布'"。

这是这 10 句话里第一次出现**从没见过的词，但答案仍然正确**。

代价在实验一里写得很清楚：我们补了三轮才到 10/10。

## 它还解决不了什么

看实验一那张表：第 1 版 2/10，第 2 版 5/10，第 3 版 10/10。

每一版的进步，都对应着"我们亲眼看到它错了一次，然后加了一条规则"。

那么，这个做法能撑多大？

- 现在的词表是 **16 个词**，我们写了 **8 条规则**。
- 如果词表是 **5 万个词**呢？规则要写多少条？
- 就算写完了，加一个新词"香"，我们要改两个地方：词表加一个词，规则加一条。
  那加 1 万个新词呢？
- 而且实验二告诉我们：这些规则的**顺序**还是一条都不能错。

所以问题很具体：

> **几万个词，难道写几万个 if？**

一定有别的办法。下一章我们试试：**把规则变成数字。**
