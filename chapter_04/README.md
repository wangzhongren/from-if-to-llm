# 第 4 章：让程序自己修改权重

## 本章的问题

上一章最后留下了一个问题：

> 这些 1.2、0.8、1.5 谁来决定？

第 3 章那张表里有 32 个数字，全是我们手填的。填法也很不体面：跑一遍，
看哪句错了，改一个数字，再跑一遍，改到 10/10 为止。

`before.py` 把这件事摆出来给你看：

```text
  表 A（人填的）    正确 10/10
  表 B（随便填的）  正确 4/10

表 A 是怎么来的？我们跑一遍、看哪句错了、改一个数字、再跑一遍……
改到 10/10 就停手。也就是说：这 32 个数字是我们'看着答案'调出来的。

程序在这件事里干了什么？它只负责算分数和比大小。
哪个数字该改成多少，它一点想法都没有。
```

表 B 是随机填的，形状和表 A 一模一样，也是 16 行、每行两个数。
程序看不出这两张表有什么不同——**它连"表 B 比表 A 差"都不知道。**

我们想要的是一件事：**让程序自己去改这些数字。**

## 最简单的尝试

先想一下：我们改数字的时候，脑子里的依据是什么？

看「苹果很甜」被答成了"科技"，我们会想："'甜'明明该是食品那边的证据，
往上调一点；'苹果'在科技那边掺和太多了，往下调一点。"

这个思路不需要任何数学，它只有一个前提：**我们知道正确答案是什么。**
错了就朝正确答案的方向挪一点点。

所以规则可以写得非常直白：

> 这句话答错了，就把正确答案那一类的数字往大调一点，
> 把答错那一类的数字往小调一点。

答对了呢？**什么都不做。** 已经对了，没有理由动它。

比如「苹果很甜」被答成了"科技"，真实答案是"食品"：

```text
苹果：科技 -1    食品 +1
很：  科技 -1    食品 +1
甜：  科技 -1    食品 +1
```

句子里出现过的每个词，都朝"食品"挪一步、从"科技"退一步。
这句话里没出现的词（"芯片""香蕉"），一个都不动。

## 实验

跑 `after.py`，起点是**一张全 0 的表**——我们一个数字都不填：

```text
==================================================================
起点：所有词的权重都是 0
==================================================================
  正确：5/10
  解释：全 0 的时候两个分数都是 0，按规矩先算科技——
        5 句科技正好被蒙对了，5 句食品全错。

==================================================================
训练：错了就改，对了不动
==================================================================
  轮次   答错    正确
    1     1      7/10  #
    2     4      9/10  ####
    3     2     10/10  ##
    4     0     10/10
```

4 轮就全对了。训出来的表长这样：

```text
  苹果     科技  -1.0   食品   1.0
  发布     科技   1.0   食品  -1.0
  新       科技   1.0   食品  -1.0
  手机     科技   1.0   食品  -1.0
  芯片     科技   2.0   食品  -2.0
  电脑     科技   0.0   食品   0.0
  华为     科技   0.0   食品   0.0
  小米     科技   0.0   食品   0.0
  好吃     科技  -2.0   食品   2.0
  很       科技   0.0   食品   0.0
  甜       科技  -1.0   食品   1.0
  香蕉     科技   0.0   食品   0.0
  这个     科技  -1.0   食品   1.0
  真       科技  -1.0   食品   1.0
  做成     科技  -1.0   食品   1.0
  派       科技  -1.0   食品   1.0
```

有几件事值得停下来看：

- **第 2 轮的错句数比第 1 轮还多**（1 -> 4）。因为它在同一轮里一边改一边判：
  前半轮改过的权重，会影响后半轮的判断。这件事不奇怪，只是要习惯。
- **一半的词是 0。**「电脑」「华为」「小米」「香蕉」「很」都被调过，又回到了 0。
  原因很简单：程序只在**答错**的时候才动手。等它轮到这几句时，权重已经够用了，
  这几句一次都没错过——**没错过，就没被调整过。**
- 「芯片」是 2.0，「很」是 0.0。手填的表里，「芯片」是 1.5、「很」是 0.3。
  两张表长得完全不一样，但都答对了 10 句。

再看 `experiment.py` 里那件我们没料到的事。第 4 章开头，我们随手把"每次改多少"
定成了 1.0。那就试试别的数：

```text
  每次改多少    每轮答错的句数                                        最终正确率
  0.01           1  4  2  0  0  0  0  0  0  0      10/10
  0.1            1  4  2  0  0  0  0  0  0  0      10/10
  1.0            1  4  2  0  0  0  0  0  0  0      10/10
  10.0           1  4  2  0  0  0  0  0  0  0      10/10
```

四行一模一样。0.01 和 10.0 差了 1000 倍，训练轨迹一个字都不差。

原因不难想：我们判断类别靠的是**两个分数谁大**。把所有权重同时乘以 100，
两个分数也同时乘以 100，谁大谁小根本没变。

所以在第 4 章的规则下，"每次改多少"**不影响对错**。它只影响一件事：权重的大小。

## 新机制

这一章要引入的东西，其实上面已经写完了。现在给它两个名字。

**第一个名字：权重。**

第 3 章那些数字，我们一直叫它"系数"。从这一章起，叫它**权重**（weight）。
换名字是因为它的地位变了：

- 第 3 章它是"我们填进去的知识"；
- 第 4 章它是"程序自己维护的东西"。

**第二个名字：训练。**

"答错了就按规则改一遍权重"这个动作，我们叫**训练**（train）。
每把整个语料走一遍，叫**一轮**（round）。这个叫法会一直用到全书结尾。

那条规则本身，完整写出来是这样的：

```python
def adjust(words, correct_category, wrong_category, step):
    for word in words:
        WEIGHT_TABLE[word][correct_index] += step
        WEIGHT_TABLE[word][wrong_index] -= step
```

它为什么合理？可以这样理解：

**每个词都是两份证据。**"甜"这个词出现，就是"这句话是食品"的一份证据，
同时是"这句话是科技"的一份反向证据。答错了，说明我们高估了一部分证据、
低估了另一部分，那就把高估的往下压一点、低估的往上抬一点。

值得注意的是它**不需要任何数学**。我们不知道"错得有多离谱"，
也不知道该往哪个方向调多大——我们只知道**答案是什么**，以及**错的是哪一句**。
就凭这两条信息，32 个数字自己长出来了。

## Python 实现

完整代码在 `after.py`。核心是三个东西。

```python
WEIGHT_TABLE = {word: [0.0, 0.0] for word in VOCABULARY}
```

一张全 0 的表。两个数字的排列顺序固定：[科技, 食品]。所以
`WEIGHT_TABLE["芯片"] = [2.0, -2.0]` 的意思是"芯片给科技 2.0、给食品 -2.0"。

```python
def predict(words):
    scores = score(words)
    return CATEGORIES[0] if scores[0] >= scores[1] else CATEGORIES[1]
```

判断规则没变，还是"分数高的赢"。两个分数一样高时先算科技——
这个"打平怎么办"的小规矩，在训练刚开始的时候会天天遇上（全 0 的表里，
每一句都是 0 : 0），所以它值得写清楚。

```python
def train_one_round(corpus, step):
    wrong_count = 0
    for sentence, label in corpus:
        words = split_sentence(sentence)
        answer = predict(words)
        if answer == label:
            continue
        wrong_count += 1
        adjust(words, correct_category=label, wrong_category=answer, step=step)
    return wrong_count
```

一轮就是"把语料从头到尾走一遍"。走的过程中，权重一直在变——
所以同一轮的前半段和后半段，程序用的其实不是同一张表。

## 它解决了什么

第 3 章那张表，32 个数字是我们填的。这一章的表，**我们一个都没填**：

```text
  起点         5/10
  4 轮之后     10/10
```

而且它找到的答案和我们填的**不一样**：

| 词 | 我们填的 | 程序训出来的 |
|---|---|---|
| 苹果 | 科技 0.2 / 食品 0.9 | 科技 -1.0 / 食品 1.0 |
| 芯片 | 科技 1.5 / 食品 0.0 | 科技 2.0 / 食品 -2.0 |
| 很 | 科技 0.0 / 食品 0.3 | 科技 0.0 / 食品 0.0 |

两张表数字完全不同，成绩一样。**这说明"能全对的表"不止一张**——
记住这一点，下一章要用。

另一个变化是程序的身份。第 3 章的程序是这样工作的：
我们改数字，它算分数。这一章的程序：**它自己改数字**。

我们只提供了三样东西：

1. 一批标好答案的句子；
2. 一条"错了就改"的规则；
3. 一个数：每次改多少。

## 它还解决不了什么

三样东西里，第 3 样最可疑：**每次改多少？**

我们随手定成了 1.0。实验一做下来，发现它居然**不影响对错**——
0.01 和 10.0 的训练轨迹一模一样。那它影响什么？

```text
  每次改多少        正确率      权重最大的绝对值
  0.01         10/10    0.02
  0.1          10/10    0.20
  1.0          10/10    2.00
  10.0         10/10    20.00
```

它影响权重的大小。可"权重的大小"意味着什么？我们答不上来。

更要命的是这个：

```text
  第 3 章手填的表                科技    1.7 / 食品    1.2
  训练出来的表（每次改 1.0）     科技    1.0 / 食品   -1.0
  训练出来的表（每次改 10.0）    科技   10.0 / 食品  -10.0
```

三张表都是 10/10。你要问"哪一张更好"，我们手上**没有任何东西**能回答你。

我们唯一的尺子是"10 句里对了几句"。它只有 0 到 10 这 11 个取值，
而三张表都是 10。尺子到头了。

所以问题很具体：

> **每次到底应该改多少？**

所以问题很具体：

> **每次到底应该改多少？**

要回答它，我们得先能说出"这句话错得有多离谱"——
不是"错了"，是"错到什么程度"。现在我们对错误的全部认知，
就是"苹果芯片很强被答成了食品"。
