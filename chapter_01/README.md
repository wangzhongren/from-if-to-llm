# 第 1 章：先把一句话拆开

## 本章的问题

我们先不去想"分类"，也不去想"学习"。先问一个更笨的问题：

**计算机拿到「苹果发布新手机」，它看到的到底是什么？**

打开 Python 看一眼：

```python
sentence = "苹果发布新手机"
print(len(sentence))                            # 7
print(sentence[0], sentence[1], sentence[2])    # 苹 果 发
print(sentence == "苹果发布新手机")               # True
print(sentence == "苹果发布了新手机")             # False
```

```text
7
苹 果 发
True
False
```

这就是全部真相：**在计算机眼里，「苹果发布新手机」是 7 个字排成的一根字符串。**

它能数出 7，能取出第 0 个字是"苹"，能比较两根字符串是否一模一样——就这些。

它不知道"苹果"是一个东西。在它那里，`苹` 和 `果` 的关系，跟 `苹` 和 `机` 的关系完全一样：
都是"两个挨着的字"。

而"苹果"和"发布"这样的单位，恰恰是我们要讨论的东西。所以第一个问题就是：

> **怎么把一句话，变成程序真正能操作的单位？**

## 最简单的尝试

最直觉的做法是：不拆。

句子是字符串，那我们就直接拿字符串当钥匙，把它整条记下来。

```python
KNOWN_SENTENCES = [
    "苹果发布新手机",
    "苹果发布新芯片",
    # ... 语料里的另外 8 句
]

def has_seen(sentence):
    return sentence in KNOWN_SENTENCES
```

这是我们能写出的最小的一段程序了：一个清单，一次 `in` 判断。

它的表现（`before.py`）：

```text
语料里的 10 句原话：
  [听过] 苹果发布新手机
  [听过] 苹果发布新芯片
  ...

同样意思、只是换个写法的 5 句话：
  [没听过] 苹果发布了新手机
  [没听过] 苹果发布新手机。
  [没听过] 苹果发布新手机！
  [没听过] 苹果 发布 新手机
  [没听过] 苹果即将发布新手机

------------------------------------------------------------
原话命中：10/10
换个写法命中：0/5
------------------------------------------------------------
```

对原话 100%，换个写法 0%。

这不是"程序太笨"，而是**它根本没有可以操作的单位**。整句话是一个不可分割的原子；
只要有一个字不一样，就是另一个原子。多一个"了"，多一个空格，都等于换了一句话。

## 实验

跑 `experiment.py`，我们做三件事。

**实验一**：确认上面那个失败（原话 10/10，换个写法 0/5）。

**实验二**：把句子拆开，看看它变成什么。

```text
============================================================
实验二：拆开之后，一句话变成了什么
============================================================
  苹果发布新手机
      苹果 | 发布 | 新 | 手机
      [0, 1, 2, 3]
  苹果发布了新手机
      苹果 | 发布 | <UNK> | 新 | 手机
      [0, 1, 16, 2, 3]
  苹果芯片很强
      苹果 | 芯片 | 很 | <UNK>
      [0, 4, 9, 16]
  这个苹果真甜
      这个 | 苹果 | 真 | 甜
      [12, 0, 13, 10]
  苹果配香蕉
      苹果 | <UNK> | 香蕉
      [0, 16, 11]

  说明：词表里没有的块（'了'、'强'、空格……）都换成了 <UNK>。
```

**实验三**：拆开之后，"像不像"第一次可以数出来。拿「苹果发布了新手机」和语料里的每一句比：

```text
    苹果发布新手机     共享 4 个：苹果 发布 新 手机
    苹果发布新芯片     共享 3 个：苹果 发布 新
    华为发布新电脑     共享 2 个：发布 新
    小米发布新手机     共享 3 个：发布 新 手机
    苹果芯片很强       共享 1 个：苹果
    苹果很好吃         共享 1 个：苹果
    苹果很甜           共享 1 个：苹果
    香蕉很好吃         共享 0 个：
    这个苹果真甜       共享 1 个：苹果
    苹果做成派         共享 1 个：苹果

  5 句「换个写法」的最像的一句：
    苹果发布了新手机         最像 -> 苹果发布新手机   共享 4 个词
    苹果发布新手机。         最像 -> 苹果发布新手机   共享 4 个词
    苹果发布新手机！         最像 -> 苹果发布新手机   共享 4 个词
    苹果 发布 新手机         最像 -> 苹果发布新手机   共享 4 个词
    苹果即将发布新手机       最像 -> 苹果发布新手机   共享 4 个词
```

实验一里"完全不认识"的那 5 句，现在全都和最像的一句共享了 4 个词。
多出来的那个"了"不再让它变成陌生人——因为它已经被切掉了，剩下的部分对得上号。

## 新机制

只有一件事：**把句子拆成词，再把词换成编号。**

具体三步。

**第一步：定一份词表。**

词表就是"我们认识的所有词"的清单。这份清单是我们自己定的，全书都用这一份：

```text
苹果 发布 新 手机 芯片 电脑 华为 小米 好吃 很 甜 香蕉 这个 真 做成 派
```

一共 16 个词。

**第二步：拿词表去切句子。**

从左往右扫句子，每到一个位置，**尽量切下最长的、词表里有的词**。

以「苹果芯片很强」为例：

```text
苹果芯片很强
^^                 "苹果" 在词表里 -> 切走，指针往后挪 2 格
  苹果芯片很强
  ^^^^             "芯片" 在词表里 -> 切走，指针往后挪 2 格
      苹果芯片很强
      ^^           "很强" 不在词表里，"很" 在 -> 切走，指针往后挪 1 格
        苹果芯片很强
        ^^         "很强" 不在，"强" 也不在 -> 词表里没有这个字
```

最后那个"强"怎么办？词表里没有它，但它是句子里真实存在的一个字，不能装看不见。
我们给它一个统一的占位符：`<UNK>`（unknown，不认识的）。

**第三步：给每个词一个编号。**

程序只会做数字运算，不会做"字符串相等"以外的字符串运算。所以每个词要有一个编号。
编号就是它在词表里的位置：

```python
WORD_TO_ID = {word: index for index, word in enumerate(VOCABULARY)}
UNKNOWN_ID = len(VOCABULARY)        # <UNK> 排在所有词后面
```

那个编号，就是这个词的 token id。词表里的每个词都有一个，`<UNK>` 也有一个。

于是「苹果发布新手机」变成了：

```text
苹果 | 发布 | 新 | 手机        ->        [0, 1, 2, 3]
```

一串数字。程序终于有东西可以操作了。

## Python 实现

完整代码在 `after.py`，核心是这两个函数。

```python
def split_sentence(sentence):
    words = []
    position = 0
    while position < len(sentence):
        matched_word = None
        for length in range(MAX_WORD_LENGTH, 0, -1):
            piece = sentence[position:position + length]
            if piece in WORD_TO_ID:
                matched_word = piece
                break
        if matched_word is None:
            words.append(UNKNOWN_WORD)
            position += 1
        else:
            words.append(matched_word)
            position += len(matched_word)
    return words
```

几个要注意的地方：

- `for length in range(MAX_WORD_LENGTH, 0, -1)`：先试最长的（2 个字），不行再试短的（1 个字）。
  这就是"最长匹配"。少了它，「苹果」会被切成「苹」和「果」——而这两个字根本不在词表里。
- 切到词的时候 `position += len(matched_word)`：切走几个字，指针就往后挪几格。
- **切不到词的时候 `position += 1`**：这一行很容易写错。如果切不到词就把指针停在那里，
  程序会卡死在这里转圈。而且只挪 1 格，是为了保证原句里的每个字都被处理到一次，
  一个都不丢——`test_chapter_01.py` 里专门测了这一条。

```python
def to_ids(words):
    return [WORD_TO_ID.get(word, UNKNOWN_ID) for word in words]
```

`to_ids` 把词换成编号。`WORD_TO_ID.get(word, UNKNOWN_ID)` 的意思是：词表里有就用它的编号，
没有就给 `<UNK>` 的编号。我们故意不写 `try/except`——查不到就让 `get` 的默认值接手，
因为"这个词我不认识"本来就是一种正常情况，不是错误。

## 它解决了什么

这一章只做了一件事：**让程序第一次看得见句子里的"块"。**

用实验三的数据说话。加了"了"的「苹果发布了新手机」，整句比较的命中率是 0；
拆开之后，它和语料里的「苹果发布新手机」共享 4 个词——4 个里包括"苹果""发布""新""手机"，
全都在。多出来的那个"了"被单独切成一个 `<UNK>`，不再污染其余的部分。

再看实验二里的一句话：`苹果配香蕉 -> [0, 16, 11]`。
"配"从来没在语料里出现过，程序照样把它处理成了一个编号。整句比较做不到这一点——
它对没见过的字毫无办法，因为它比较的单位是整根字符串，不是一个一个块。

具体到程序里，能力是这样的：

| 之前 | 现在 |
|---|---|
| 句子的单位是"整根字符串" | 句子的单位是"一个个词" |
| 比较只有"相等/不相等" | 每句话是一个编号列表，可以逐个位置看 |
| 多一个字 = 全都不一样 | 多一个字 = 多一个 `<UNK>` |

## 它还解决不了什么

现在程序能说出「苹果发布了新手机」里有 `[0, 1, 16, 2, 3]` 这几个块了。

但它不知道这些块意味着什么。

把它拿到语料的 10 句话上，它看到的只是 10 串编号。它不会知道
带「手机」「芯片」「电脑」的那几句是一伙的，带「好吃」「甜」「香蕉」的那几句是另一伙。
**这两伙句子之间的区别，对现在的程序来说根本不存在。**

所以：

> **词拆出来了，怎么知道一句话属于什么类别？**

下一章我们就试着让它回答这个问题。做法会很笨——判断的条件，全部由我们自己手写。

## 练习

1. 把 `MAX_WORD_LENGTH` 强行改成 1，跑一遍 `after.py`，看看「苹果发布新手机」被切成了什么。

3. 现在的切法是"尽量切长的"。找一句词表里的词能有两种切法的话，说说两种切法各有什么问题。

   手写还行得通吗？
