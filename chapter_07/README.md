# 第 7 章：一条直线不够用了

## 本章的问题

第 6 章把训练这件事做完了：前向算分 → 用损失衡量错得多离谱 →
用梯度决定往哪边改 → 改。10 句话全部分对，损失 0.0179。

上一章最后留了一个问题：

> 梯度是我们人推出来的。这个模型只有一层，推一次就够。层数一多呢？

要回答它，我们得先有一个"值得推两层"的理由。
所以我们先不急着解决梯度的事，先回头看看：

**现在这个模型，够用吗？**

它在做什么？把一句话里每个词的权重加起来，得到两个分数，比大小。
每个词有两个数，一个给"科技"加分，一个给"食品"加分 ——
换成图上的说法：**它在两个类别之间画一条直线**，
线的一边判科技，另一边判食品。

（更准确地说，如果拿"每个词出现了几次"当坐标，分数就是这些坐标的加权和，
画出来正是一张平面上的直线。第 3 章那个"分数"，说的就是这件事。）

所以很自然的问题：这条线，够用吗？

我们先给语料换一个新任务。还是那 10 句话，还是那个词表。
我们把每句话压成一个数字：科技类的句子记 1，食品类的句子记 0。
然后问一个更简单的问题：

**给两个这样的数字，它们是不是一样的？**

一样 = 两句同类，记 1；不一样 = 记 0。4 种组合，每种配一对真实的句子：

```text
第一个数  第二个数  答案   来自哪两句
   0        0      1     苹果很好吃 / 香蕉很好吃
   0        1      0     苹果很好吃 / 苹果发布新手机
   1        0      0     苹果发布新手机 / 苹果很甜
   1        1      1     苹果发布新手机 / 苹果发布新芯片
```

## 最简单的尝试

最省事的做法是：**模型一个字都不改，直接拿第 6 章的代码去训。**

反正是两个数进、两个类别出，用的还是同一个梯度公式 `(预测概率 - 正确答案) × 输入`。
换个数据而已，代码原样搬过去就行。`before.py` 就是这么干的。

结果不难猜，但值得亲眼看一遍：

```text
   初始值       训练后的 loss     科技类的 w[0]     食品类的 w[0]
     0        0.693147        0.2650        0.2650
     1        0.693147       -0.1019       -0.1019
     2        0.693147        0.0126        0.0126
     3        0.693147       -0.3921       -0.3921
     4        0.693147       -0.3679       -0.3679
     5        0.693147        0.4181        0.4181
     6        0.693147        0.2784        0.2784
     7        0.693147       -0.0252       -0.0252
     8        0.693147       -0.6470       -0.6470
     9        0.693147       -0.3985       -0.3985
```

10 个不同的初始值，训了 5000 步，loss 全都停在同一个数上：**0.693147**。

它等于 `-log(1/2)`，也就是"每个类别各猜一半"的分数。
再看最后两列：两个类别的权重长得一模一样。
模型把所有输入都判成了"哪一类都行" —— 它放弃了。

## 实验

跑 `experiment.py`。我们要把"一条直线不行"这件事，从感觉变成证据。

### 第 1 步：先把 4 个点摆出来

```text
  x2=1 |   (0,1) 答案 0        (1,1) 答案 1
       |
  x2=0 |   (0,0) 答案 1        (1,0) 答案 0
       +--------------------------------------
            x1=0                 x1=1
```

从左下角 (0,0) 走到右上角 (1,1)：两个角都是答案 1。
从左上角 (0,1) 走到右下角 (1,0)：两个角都是答案 0。

**两条对角线上的答案正好相反。** 这就是问题的全部形状。

### 第 2 步：把所有直线都试一遍

一条直线的全部可能，就是三个数：`w1`、`w2`、`b`。

我们让它们各自从 -3 走到 3，每隔 0.1 取一个值，三个循环套起来：

```text
一共试了 226981 条直线。
其中最好的一条，准确率是 0.75（3/4）。
没有一条能到 1.00。

挑三条有代表性的直线看看：
     w1     w2      b      准确率   判对了第几个   判错了第几个
    1.0    1.0   -1.5     0.75   [1, 2, 3]       [0]
    1.0    1.0   -0.5     0.25   [3]             [0, 1, 2]
   -1.0   -1.0    0.5     0.75   [0, 1, 2]       [3]
```

22 万条直线，没有一条能全分对。准确率的天花板是 3/4 ——
每一条直线都会错掉至少一个点。

这不是"我们没搜到"，也不是"训练方法不够好"。
**这是直线这个东西本身的极限**：它只能把平面切成两半，
切不出"两条对角线上答案相反"这种形状。

### 第 3 步：那用第 6 章的办法训练呢

```text
   初始值       训练后的 loss     科技类的 w[0]     食品类的 w[0]
     0        0.693147        0.2650        0.2650
     ...
10 次，一次例外都没有，全都停在 0.693147。
```

不管是暴力搜索还是梯度下降，结论一样：**0.693147，一步也降不下去。**

### 第 4 步：那加一层呢

直觉告诉我们：一层不够，那就加一层。

在输入和分数之间塞进一层中间结果 —— 先算 `h`，再由 `h` 算分数：

```text
h = w1 * x + b1        （一层中间结果）
分数 = w2 * h + b2      （再由它算分）
```

这就是"两个加权求和串起来"。跑出来的结果：

```text
模型                       训练后的 loss            两个类别的分数最大差
一层（一条直线）                  0.693147              4.44e-16
两层（中间 1 个）                0.693147              1.05e-15
两层（中间 4 个）                0.693147              1.68e-16
两层（中间 16 个）               0.693147              1.52e-16
两层（中间 64 个）               0.693147              1.53e-16
```

一层、两层、中间层加宽到 64 个 —— loss 全是 0.693147，一模一样。

我们辛辛苦苦加的那一层，**什么也没改变**。

## 新机制

这一章引入的东西，叫**中间层**。

> 原来的模型只有一次加权求和：输入 → 分数。
> 现在中间多了一次：输入 → 中间结果 → 分数。
> 中间这一层不直接面对输入，也不直接给出答案，我们叫它**隐藏层**。
>
> 把好几层这样的加权求和串起来，就是一个**神经网络**。

名字是新的，代码是新的一截，梯度也是重推的（多了一段链式法则：
输出层的误差要先乘上 `w2`，才传得回中间层）。

但它的效果是：**零。**

这一步值得停下来想一下。我们不是因为"加了一层"失败了才要引入新东西，
而是因为**加了一层也失败了**，才被迫去找别的原因。
如果加层就能解决，第 8 章就不存在了。

## Python 实现

`after.py` 里，中间层是这么算出来的：

```python
def forward(params, x):
    h = []
    for j in range(hidden_size):
        total = params["b1"][j]
        for i in range(NUM_FEATURES):
            total += params["w1"][j][i] * x[i]
        h.append(total)

    scores = []
    for c in range(NUM_CLASSES):
        total = params["b2"][c]
        for j in range(hidden_size):
            total += params["w2"][c][j] * h[j]
        scores.append(total)
    return h, scores
```

`h` 就是中间层。它和输入之间没有任何别的东西 —— 这一步很关键，
记住这句话，下一章会回来找它。

梯度也长了一截。输出层那一段还和上一章一样：

```python
dscore = [(p[c] - (1.0 if c == label else 0.0)) / n for c in range(NUM_CLASSES)]
```

中间层是新加的：输出层的误差，按 `w2` 的大小分回每一个中间结果：

```python
dh = []
for j in range(hidden_size):
    total = 0.0
    for c in range(NUM_CLASSES):
        total += dscore[c] * params["w2"][c][j]
    dh.append(total)
```

这一段是**人推的**。推错一个下标，程序不会报错，
它只会安静地越学越差。所以我们用第 6 章的数值梯度回头验了一次
（`tests/test_chapter_07.py::test_hand_written_gradient_matches_numeric_gradient`）：
两边对得上。

## 它解决了什么

老实说：**这一章没有解决前面那个问题。**

XOR 还是分不开。loss 还是 0.693147。准确率还是半点没涨。

它解决的是另一件事：**我们有了"堆层"这个结构。**

- 从"输入直接到分数"，变成了"输入 → 中间结果 → 分数"。
- 代码从写死一层，变成了 `hidden_size` 想填几就填几。
- 链式法则也走通了一次：中间层的梯度是输出层的误差乘上 `w2` 传回去的。

这三点都是后面所有内容的地基。但地基不是房子 ——
它现在一点都不好住。

## 它还解决不了什么

把实验第 4 步的那张表再看一遍：

```text
两层（中间 1 个）                0.693147
两层（中间 4 个）                0.693147
两层（中间 16 个）               0.693147
两层（中间 64 个）               0.693147
```

一层是一条直线。加了一层中间层之后，loss 一点没动，
**说明它还是那条直线。**

可是中间层明明多了一整排可以调的权重，它凭什么一点用都没有？

这个问题有两种可能的答案，而且它们的后果完全不同：

- 如果答案是"中间层太窄/太浅，还学不动" —— 那我们堆宽一点、堆深一点就好了。
- 如果答案是"中间层天生就做不了这件事" —— 那堆多少层都是白堆。

这两种可能，我们必须分清楚，不能靠感觉猜。

**下一章要做的第一件事，就是让中间层自己招供：
它到底有没有改变模型能画出来的形状。**
