# 第 6 章：机器怎么知道参数往哪边改

## 本章的问题

上一章我们做成了一件事：给一句话，模型会输出两个概率，
我们用交叉熵把它压成一个数字 —— 损失。

现在盯着这个数字，问一个很实际的问题：

**损失大了，我该改哪个参数？**

我们的参数表有 32 个数（16 个词 × 2 个类别）。
损失只告诉我们"总分"是多少，不告诉我们每一分的来源。
这就像考试只发总分，不发卷子 —— 你知道自己考砸了，但不知道该复习哪一章。

第 5 章用的办法是挨个试：把某个参数挪一点点，重新算一遍损失。
`before.py` 把这套办法从头到尾跑了一遍，结论是：

```text
       每次挪多少        达到损失 < 0.001 要几轮         用掉的前向次数
       0.005        200 轮还没到（0.0396）           13001
        0.01        200 轮还没到（0.0052）           13001
        0.05                      57            3706
         0.5                       6             391
         5.0                       1              66
```

同一个办法，同一个模型，唯一的变化是"每次挪多少"——
结果从"200 轮都到不了"到"1 轮就搞定"，差了几百倍的工作量。
而这个数填多少，事先没有任何依据。

## 最简单的尝试

把"试着改"这个办法做到极致，就是 `before.py`。

它的逻辑简单到不需要解释：给一个参数加一点，算一遍损失；
变小了就留下，变大了就试试减一点。对所有 32 个参数都这么做一遍，
就算走完一轮。它确实能跑，也确实能把损失降下去 —— 但有三条绕不过去的毛病。

**一、每次挪多少，靠猜。**

就是上面那张表。0.005 挪了两百轮还差得远，5.0 一轮就到位。
我们不是"找到了好办法"，我们只是把五个值都试了一遍。
换一个模型、换一批数据，这个数还得重新试。

**二、它一次只能动一个参数。**

挪「发布」的时候，另外 31 个参数一动不动地干等着。
可它们之间明明有关系 ——「手机」和「新」得一起使劲，
才能把「苹果发布新手机」这种句子推到科技那一边。

那让 32 个参数一起动呢？每个参数有"加""减"两个选择，
合起来是 2³² ≈ 43 亿种组合。一个一个试过去，试到宇宙末日也试不完。

**三、它要跑的次数，是"参数个数的两倍"。**

我们只有 32 个参数，一轮 64 次，还撑得住。
参数要是一百万个呢？一轮两百万次。
今天最大的那些模型，有几千亿个参数 —— 这条路走不通。

三条其实是同一件事：

> 我们现在只会问"这次分错了"，
> 不会问"**每一个参数**该往哪边挪、挪多少"。

第 5 章结尾留下的话就是这个意思。

## 实验

跑 `experiment.py`。我们分六步把问题拆开看。

### 第 1 步：先盯住一个参数看

```text
               「发布」的科技权重          损失       比 0 的时候
                   -0.05    0.703272     +0.010125
                   -0.01    0.695152     +0.002005
                    0.00    0.693147     +0.000000
                    0.01    0.691152     -0.001995
                    0.05    0.683272     -0.009875
```

很清楚了：这个参数往正方向挪，损失就变小。
"往哪边改"是有答案的，而且这个答案可以量出来 ——
不只是"变好变坏"，连"变好多少"都有。

### 第 2 步：把 32 个方向一次全算出来

一个一个试太慢，但"挪一点点看变化"这件事本身可以写成一个公式：

```text
(损失(参数 + h) - 损失(参数 - h)) / (2h)
```

正负两边各挪一次再相减，两边的一阶误差互相抵消，比只挪一边准得多。
把它对 32 个参数全跑一遍：

```text
  词              科技类的梯度        食品类的梯度   出现在几句科技句 / 食品句
  苹果           0.05000      -0.05000        3 / 4
  发布          -0.20000       0.20000        4 / 0
  新            -0.20000       0.20000        4 / 0
  手机          -0.10000       0.10000        2 / 0
  芯片          -0.10000       0.10000        2 / 0
  电脑          -0.05000       0.05000        1 / 0
  华为          -0.05000       0.05000        1 / 0
  小米          -0.05000       0.05000        1 / 0
  好吃           0.10000      -0.10000        0 / 2
  很             0.10000      -0.10000        1 / 3
  甜             0.10000      -0.10000        0 / 2
  香蕉           0.05000      -0.05000        0 / 1
  这个           0.05000      -0.05000        0 / 1
  真             0.05000      -0.05000        0 / 1
  做成           0.05000      -0.05000        0 / 1
  派             0.05000      -0.05000        0 / 1
```

这张表可以当报表读：

- `发布` 是 -0.20，最大的一个负数 → 该把它往上加。
- `好吃`、`甜` 是 +0.10 → 该往下减。
- 最后一列解释了大小：`发布` 在 4 句科技句里出现、0 句食品句，所以它的梯度最大；
  `电脑` 只出现过 1 次，梯度就只有 0.05。

### 第 3 步：这个方向，和一次一次试出来的方向对得上吗

```text
  把「发布」的科技权重往右挪 0.001：损失 0.693147 -> 0.692947
  把「发布」的科技权重往左挪 0.001：损失 0.693147 -> 0.693347

  往右挪损失变小了 —— 所以要往右改，也就是给这个参数加一点点。
  数值法给出的梯度 = -0.20000
```

梯度是负的，往右改。梯度是负的，公式里却是**减号**。
负负得正 —— 这就是为什么更新公式里写的是减号，不是加号。

### 第 4 步：数值法 vs 手推的公式

数值法很实在，但它有一个硬伤：每算一个参数的梯度，都要把整个模型重跑两遍。
32 个参数，一轮 64 次前向。

所以我们针对这个具体的模型，把梯度手推了出来。结果简单得有点意外：

```text
  词               数值法          公式           差
  苹果        0.048482    0.048482    1.91e-10
  发布       -0.152213   -0.152213    3.75e-09
  新         -0.152213   -0.152213    3.75e-09
  ...
  32 个参数里，最大的差是 3.75e-09。
```

两边是同一个东西。区别只在于：数值法要跑 64 次前向，公式只要 1 次。

### 第 5 步：花掉同样的计算，各走了多远

```text
  方法            步数      前向次数         最后的损失     正确率
  数值法           30      1920      0.105704      10/10
  公式法          960      1920    0.00370599      10/10
```

同样 1920 次前向，公式法把损失又往下压了 28 倍。而且这个差距会越拉越大 ——
因为数值法每走一步都要把模型重算 64 遍，公式法只要 2 遍。

注意这两行的更新规则一模一样，都是 `w = w - 学习率 × 梯度`。
差别只在梯度是怎么算出来的。

### 第 6 步：学习率选多大

```text
         学习率         200 步后的损失       正确率         参数最大绝对值
      0.0005          0.663841         9/10            0.02
        0.05          0.147115        10/10            0.63
         0.5          0.017895        10/10            1.96
         5.0          0.001740        10/10            3.43
        20.0          0.000284        10/10            4.50
      1000.0          0.000000        10/10          200.00
```

0.0005 太小：200 步走完了，损失还剩 0.66，还有 1 句分错。

1000.0 那一行的 0.000000 不是"学得完美"。概率被推到了 1.0，
`-log(1)` 正好是 0 —— 尺子到顶了，量不出差别。看最后一列：参数已经涨到 200。

为什么学习率大不会像别处那样"炸掉"？因为我们的 10 句话本来就是能分开的：
参数越大，模型越有把握，损失就越小，所以它根本没有一个"最低点"可以停，
它会一直往上走。**损失一路降下去，并不总是好消息。**

我们选 0.5。这个数字没有公式，只能试。

## 新机制

### 梯度

第 2 步那张表里的东西，我们给它一个名字：**梯度**。

> 梯度是一张和参数一一对应的表。表里的每个数字告诉你两件事：
> 这个参数往正方向挪一点，损失会变大还是变小，以及变得有多快。

有了它，"我该改哪个参数"这个问题就有了完整的答案：
**每个参数都知道自己该往哪边改，而且知道改的劲有多大。**

数值法和公式法算出来的是同一个梯度。数值法是"试"出来的，
公式法是"推"出来的。前者通用但慢，后者快但需要针对模型推一次。

### 学习率

梯度只说方向，不说走多远。走多远由我们自己定，这个数叫**学习率**。

于是第 4 章那条更新规则，长成了它最终的样子：

```text
w = w - 学习率 × 梯度
```

为什么是减号？因为梯度指向的是损失**上升**最快的方向。
我们要往下走，就得反着来。

那一行 `w = w - lr * grad`，就是"学习"这两个字在代码里的全部含义。

## Python 实现

`after.py` 里最关键的两段。

先是数值法，它是这一章所有道理的老家：

```python
def numeric_gradient(table, corpus, h=1e-3):
    """数值法求梯度：把每个参数单独挪一点点，看损失怎么变。

        (损失(参数 + h) - 损失(参数 - h)) / (2h)
    """
    for word in VOCABULARY:
        for category_index in (0, 1):
            original = table[word][category_index]

            table[word][category_index] = original + h
            plus = average_loss(corpus)
            table[word][category_index] = original - h
            minus = average_loss(corpus)
            table[word][category_index] = original

            result[word][category_index] = (plus - minus) / (2 * h)
```

再把"词权重加起来 + softmax + 交叉熵"这一串整体推一遍，得到公式版：

```python
def gradient(table, corpus):
    """每个样本贡献的梯度 = 预测概率 - 正确答案。"""
    for sentence, label in corpus:
        words = split_sentence(sentence)
        probabilities = softmax(score(words))
        correct_index = CATEGORIES.index(label)

        for category_index in (0, 1):
            difference = probabilities[category_index] - (1.0 或者 0.0)
            difference /= n
            for word in words:
                if word in result:
                    result[word][category_index] += difference
```

`p - y` 就是"模型以为的概率减去它应该是的概率"。
模型对某一类太有信心了，这个差值就是正的，权重就要往下压；
太没信心，差值就是负的，权重就要往上抬。**符号本身就带着方向。**

训练循环则是：

```python
def train(steps=200, lr=0.5):
    for _ in range(steps):
        grads = gradient(WEIGHT_TABLE, CORPUS)
        for word in VOCABULARY:
            for category_index in (0, 1):
                WEIGHT_TABLE[word][category_index] -= lr * grads[word][category_index]
        history.append(average_loss(CORPUS))
```

`after.py` 跑完是这样的：

```text
  训练结束：损失 = 0.01789499，正确率 = 10/10
```

它学到的参数表里，`发布` 是 1.035（4 句科技句、0 句食品句），
`苹果` 是 -0.342（3 句科技句、4 句食品句，两边几乎抵消）：

```text
  词            科技      食品   出现在几句科技句 / 几句食品句
  苹果      -0.342   0.342        3 / 4
  发布       1.035  -1.035        4 / 0
  芯片       1.957  -1.957        2 / 0
  电脑       0.267  -0.267        1 / 0
  好吃      -1.275   1.275        0 / 2
  甜        -1.188   1.188        0 / 2
```

我们从来没告诉过它哪个词属于哪一类 —— 它是自己从损失里读出来的。

## 它解决了什么

- 损失从 0.6931 降到 0.0179，10 句话全部分对。
- 一次前向就能拿到全部 32 个梯度，不用再跑 64 遍。
- "参数往哪边改、改多少"从一个要靠手试的问题，变成了一个可以算出来的数。

更重要的是：**到这里，机器学习训练这件事已经被我们完整实现了。**
前向算分 → 用损失衡量错得多离谱 → 用梯度决定往哪边改 → 改。
今天所有的模型，包括 GPT，训练的时候跑的都是这四步，一步都没多。

## 它还解决不了什么

回头看看 `after.py` 里那段最值钱的代码：

```python
difference = probabilities[category_index] - (1.0 或者 0.0)
for word in words:
    result[word][category_index] += difference
```

这个 `(p - y)` 不是天上掉下来的。它是我针对"词权重求和 → softmax → 交叉熵"
这**一条链**推出来的。推一次，只能用在一条链上。

可我们的模型只有一个加权求和。如果模型变复杂一点呢？

比如这样：先算一个中间结果，再用中间结果算分数：

```text
中间 = 各个词的权重加起来（再来一遍）
分数 = 中间结果再乘一遍权重
```

链变长了，链式法则就得多乘一段。再复杂一点，就得多推一遍。
每一层都要人推一次，推完还要用数值法回头验证一次 ——
毕竟公式推错了，程序不会报错，它只会安静地越学越差。

我们这个模型只有一层，推一次可以接受。那要是十层、一百层呢？

**这就是下一章的问题：中间加一层，梯度该怎么推？**

见 `exercises.md`。这里挑三条最关键的：

1. 把 `numeric_gradient` 的 `h` 分别设成 `1.0`、`1e-6`、`1e-12`，和公式对一对。

3. 从"分数、softmax、-log(正确答案的概率)"三个式子出发，自己推一遍 `(p - y)`。
   softmax 和交叉熵各自求导都很麻烦，凑在一起却短得吓人 —— 这不是巧合。
