# 第 24 章：它为什么看起来像在思考

## 本章的问题

上一章我们拿到了两个旋钮，能控制它写出来的东西有多"野"。

但有一件事我们从头到尾都没做过：**检验它。**

我们一直在做的判断只有一句："它写出来的东西像中文。"

这一章不加新零件，不改架构，不重新训练。只做一件事：**去问它几个问题，然后把答案记下来。**

先跑 `before.py`。它做的事情就是我们一直在做的事情——让它写，我们看。

```text
第一印象：它学会了
  开头：床前
  它写：床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿

  开头：鹅鹅鹅
  它写：鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月光疑是地上霜举头望明月

  开头：白毛浮绿水
  它写：白毛浮绿水红掌拨清波床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项
```

三段都通顺。字对，顺序对，连诗的节奏都对。

看到这个，第一反应一定是：**它学会了中文。**

再换几个语料里没有的开头。用的还是那 33 个字：

```text
  开头：故乡故乡故乡故乡故乡故乡故乡故乡
  它写：故乡故乡故乡故乡故乡故乡故乡故乡鹅曲项项项天歌白毛浮绿白毛浮绿水红掌拨清波床前明月前

  开头：水水水水水水水水水水水水水水水水
  它写：水水水水水水水水水水水水水水水水红红地红白红掌红前前故浮前掌项掌拨前疑地地项项前拨乡

  开头：月月月月月月月月月月月月月月月月
  它写：月月月月月月月月月月月月月月月月光疑地上乡鹅鹅鹅鹅曲曲向曲项向鹅白波举浮绿掌拨掌拨掌
```

前面还像话，越写越乱，最后完全散了。

看到这个，第一反应也一定是：**它根本什么都没学会，只是在复读训练数据。**

同一批权重、同一个模型。换个开头，我们的判断就从"学会了"变成"什么都没学会"。

问题出在"我们自己读一读"这个办法本身：它一次只给我们一个样本，我们手里没有一把尺子，只有一双眼睛。

## 最简单的尝试

换一把尺子。这把尺子不读它写出来的东西，而是直接问它：**下一个字，你觉得是哪一个？** 然后跟正确答案比。

这把尺子的名字叫**困惑度**（perplexity）。

```
困惑度 = e 的 loss 次方
```

它可以读成"**模型心里大概有几个候选在打架**"：

- 困惑度 = 1，它心里只有一个候选，笃定得很
- 困惑度 = 2，它在两个候选之间犹豫
- 困惑度 = 33（也就是 `e^ln33`），它在 33 个字符里完全瞎猜——这正是我们这个模型的词表大小

困惑度的好处是，它不需要我们"读"输出的东西。它只需要一段**有标准答案的文字**：把这段文字喂给模型，让它一个字一个字地猜下一个，然后把每个位置的 loss 平均起来。

一段文字越"合它的胃口"，困惑度越低。

那我们的模型，对什么文字最有胃口？

## 实验

`after.py` 做了六组探测。第一组就是上一节那把尺子。

### 探测一：它有多确定

```text
  这段文字                     loss            困惑度      猜对比例
  -------------------------------------------------------
  语料原文                   0.0162           1.02    99.49%
  每 2 个字打乱一次             9.9164       2.03e+04    47.21%
  每 4 个字打乱一次            16.0393       9.24e+06    21.75%
  每 8 个字打乱一次            19.5929       3.23e+08     8.16%
  整段打乱                  21.4704       2.11e+09     3.92%
```

第二列开始，全都只是"把同一批字换个顺序"而已。字的种类、每个字出现的次数，一个字都没变。

- 原文：困惑度 **1.02**。它几乎不犹豫。
- 整段打乱：困惑度 **2.11e+09**，猜对比例 **3.92%**——而瞎猜正好是 3.03%。

**顺序一乱，它掉回瞎猜的水平。**

### 探测二：它错的时候，自己知道吗

```text
  语料原文一共 8704 个「猜下一个字」的位置。
  它猜错了 44 个（0.51%）。

  它猜对的时候，给正确答案的概率平均是  0.9976
  它猜错的时候，给正确答案的概率平均只有 0.1681
  但它猜错的时候，给**自己选的那个答案**的概率平均有 0.8293
```

最后一行才是要看的：**它错得很自信。**

它不是"不确定，随便挑了一个"，而是"我非常确定——确定错了"。

而且它一共只错了三种：

```text
    正确答案 '光'，它猜 '低'，而且给了自己 98.13% 的把握
    正确答案 '思'，它猜 '望'，而且给了自己 98.99% 的把握
    正确答案 '鹅'，它猜 '曲'，而且给了自己 56.45% 的把握
```

这三个字恰好就是语料里**有歧义**的那几个：

```text
'月' 后面有时是 '光'（床前明月光），有时是 '低'（望明月低头…）
'头' 后面有时是 '望'（举头望明月），有时是 '思'（低头思故乡）
'鹅' 后面有时还是 '鹅'，有时是 '曲'
```

### 探测三：它的错误发生在哪里

```text
  窗口里第几个位置        0, 1
  这个位置上错了几个      29, 15

  全部 44 个错误，都发生在窗口的第 0 个和第 1 个位置上。
```

也就是说，模型每次被迫只在一两个字的上下文里做判断时，就会出错。上下文一长，它再没犯过错。

### 探测四：它最没把握的字，是最有意思的字

```text
  它最不确定的 5 个字             它最有把握的 5 个字
  ----------------------------------------------------
  '光'  0.9336                '月'  0.9999
  '鹅'  0.9624                '项'  0.9999
  '思'  0.9694                '上'  0.9998
  '曲'  0.9855                '前'  0.9998
  '低'  0.9959                '天'  0.9997
```

最不确定的 `光` `鹅` `思` `曲` `低`，全部出现在有歧义的位置上。

最有把握的 `月` `项` `上` `前` `天`，在语料里只有一种下文，没有任何别的可能。

**它的不确定，不是随机的。** 它恰好在自己该不确定的地方不确定。

### 探测五：上下文有多长，它才敢确定

```text
  给它的上下文长度                   下一个字的损失      猜对比例
  ----------------------------------------------
  1                           0.2336    88.64%
  2                           0.1739    95.35%
  3                           0.0006   100.00%
  4                           0.0008   100.00%
  8                           0.0017   100.00%
  16                          0.0093   100.00%
  32                          0.0007   100.00%
```

给它两个字，它下一个字就有 95% 猜对。给它 32 个字，也没有变得更好。

**这个模型其实不太需要上下文。** 因为我们的语料太规整，每个字的下文几乎只由前面一两个字决定。

### 探测六：它会不会背整句

```text
    '床前明月光疑是地上|' -> '霜'   （语料里是 '霜'）
    '举头望明月低头思|' -> '故'   （语料里是 '故'）
    '白毛浮绿水红掌|' -> '拨'   （语料里是 '拨'）
```

三个都对。但这说明不了太多——这三个片段，模型在训练里**见过 8 遍**。

它到底是在"接诗"，还是在"回忆"？这一章给不出答案。因为我们的语料里，从来就没有出现过一句"它没见过但合语法"的中文。

### 那，再做一个对照实验

`experiment.py` 里有一个更狠的：

```text
  原文：  床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿
  打乱后：掌望项绿明霜光前清明床前思床头鹅明清天地地头浮鹅拨是歌绿地月月月

                                考它原文          考它打乱文本
  --------------------------------------------------
  用原文训练的模型                  0.0162         21.4704
  用打乱文本训练的模型             14.0036          0.1286
```

两段文字用的字**完全一样**，只是顺序不同。模型结构、训练步数、随机种子全都一样。

**对角线上的两个数字很小，另外两个很大。**

每个模型都只认得自己训练时看过的那套顺序。换到另一套顺序上，它立刻变回瞎猜。

这条对角线是这一章最硬的一个证据：

> **它学的是「这 304 个字按什么顺序排」，不是「中文的字按什么顺序排」。**

因为打乱的那段文字里，没有一个片段符合中文的习惯，可它照样学得和原文一样好——只是它学的是那套乱序的规矩。

再把它练久一点：

```text
      训练步数       原文上的 loss         打乱文本上的 loss
  ----------------------------------------------
       200          0.0180             17.6676
       500          0.0111             19.1756
      1000          0.0162             21.4704
      2000          0.0167             23.9451
```

原文本上的 loss 一直待在 0.01 到 0.02 之间，早就到底了。打乱文本上的 loss 不但没降，还从 17.7 一路涨到了 23.9。

（瞎猜的水平是 `ln33 = 3.50`。比它大得多，说明模型是在"自信地答错"。）

**练得越久，它越会背这一段，但一点也没有变得更懂中文。它甚至越练越不会应付陌生顺序。**

## 新机制

**这一章没有新机制。**

没有新层，没有新算子，没有改一行模型代码。多出来的只有两样东西：

1. **一把尺子**：困惑度。它不需要我们"读"输出，它只需要有标准答案的文字。
2. **一组对照**：把语料打乱再训一个模型，看它到对方的地盘上还能不能活。

这就是这一章的全部。它不产生任何新能力，它只是**让我们知道前面造出来的东西到底是个什么**。

## Python 实现

尺子本身只有几行：

```python
def perplexity(loss):
    return float(np.exp(loss))


def evaluate_text(model, tokenizer, text):
    ids = tokenizer.encode(text)
    inputs = [ids[s:s + CONTEXT] for s in range(len(ids) - CONTEXT)]
    targets = [ids[s + 1:s + CONTEXT + 1] for s in range(len(ids) - CONTEXT)]
    with no_grad():
        logits = model(np.array(inputs)).data
        loss = cross_entropy(model(np.array(inputs)), np.array(targets)).item()
        correct = logits.argmax(axis=-1) == np.array(targets)
    return {"loss": loss, "perplexity": perplexity(loss),
            "accuracy": float(correct.mean()), ...}
```

打乱器也只有几行：

```python
def shuffle_whole(text, seed):
    characters = list(text)
    np.random.default_rng(seed).shuffle(characters)
    return "".join(characters)
```

`shuffle_blocks` 是它的温和版：只在每个小块内部打乱。块越大，破坏得越彻底。

这两个函数加起来不到十行。但它们让我们第一次能给模型做**对照实验**。

## 它解决了什么

这一章没有让模型变得更强。它做的是另一件事：**让我们不再自欺。**

我们现在知道了这些：

| 我们看到的 | 数字 |
|---|---|
| 语料原文上的困惑度 | 1.02（心里只有一个候选） |
| 整段打乱后的困惑度 | 2.11e+09（掉回瞎猜） |
| 它的错误总数 | 8704 个位置里错了 44 个 |
| 它的错误类型 | 只有三种，全在语料有歧义的位置 |
| 它错的时候的把握 | 平均 82.93% |
| 它的错误位置 | 全部在窗口的第 0、1 位 |
| 交叉评估的对角线 | 0.0162 / 0.1286 对 21.47 / 14.00 |

而且它推翻了一个我们本来会得出的结论。

如果只做打乱实验，结论会是"它就是个复读机"。但探测四和探测三说了另一件事：

**一个纯粹的查找表，不会"在某个位置格外犹豫"。**

它最不确定的五个字，恰好是语料里真正有歧义的那五个。它在两个字的上下文里会错，在三个字的上下文里就不会错。这些事情，一个单纯背下 304 个字符的模型是不需要做的。

所以：

- **说法 A**：它就是一个复读机。语料外的东西它一点都不会，连顺序打乱都认不出来。
- **说法 B**：它确实从这 304 个字里学到了一些结构——它知道哪些位置有歧义、哪里该犹豫、两个字够不够它做决定。

**这一章不替你选。** 两组观察同时成立，而且都说得通。

## 它还解决不了什么

有一件事是确定的：**我们提的这些问题，用现在这个规模，问不出结果。**

304 个字符，两首诗来回八遍。15 万个参数配 304 个字符，比例是 1 比 500。它当然背得下来。要让它非学结构不可，就得让它背不下来——**语料得大到记不住**。

那就把它做大？

要让它真的学会中文，参数量至少要到亿这个量级，语料至少要到几十亿个字符。

这两件事都不是"改几个常数"能解决的。但在动手之前，先撞上的是另一堵墙：

**第 9 章我们写的那个 toygrad，太慢了。**

它每一次运算都要用 Python 记一遍账，每一步都要把计算图从头走一遍。我们这个 15 万参数的小模型，跑一步要十几毫秒。再大 1000 倍呢？

**其实我们还有一个更基本的问题没解决。**

我们在这一章里量了这么多数字，靠的是**我们自己手写的每一行代码**：手写 attention、手写 LayerNorm 的梯度、手写 Adam、手写整个训练循环。这些东西，PyTorch 里全都有现成的，而且快得多。

我们的模型现在没法变大。第一个原因不是没有显卡，是**我们这套工具跑不动**。

下一章我们换一套工具。但先记住一件事：**换工具不会改变任何原理。** 你今天写下的每一行，在 PyTorch 里都有一个一模一样的对应物。
