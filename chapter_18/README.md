# 第 18 章：数据越传越乱

## 本章的问题

上一章我们用 `x = x + layer(x)` 把"堆层数"这件事救回来了。但那张实验表还有半截是坏的：

```text
   8      有     29.770        nan        nan        nan    1/20    1.2s
  16      有    446.262        nan        nan        nan    1/20    2.5s
```

不是"学得慢"，是**第 1 步还没走完，数值就已经大得离谱**：8 层 29.77，16 层 446.26。而 1 层的时候只有 4.52。

这一章我们先把这件事看清楚。打开 `before.py`，它就是第 17 章的模型，一个字没改，只是层数变成了 8 层。它先不训练，只做一次前向，然后把**每一层"拿到手的那个张量"的均值和标准差**打出来：

```text
==============================================================
一、只看一次前向：每一层拿到手的数有多大？
==============================================================
  层                           拿到手：均值       标准差       交出去：标准差
  ----------------------------------------------------------
  输入（词向量+位置编码）                -0.130     1.435         1.435
  第 1 层                       -0.130     1.435         1.790
  第 2 层                       -0.138     1.790         2.376
  第 3 层                       -0.144     2.376         3.059
  第 4 层                       -0.196     3.059         4.139
  第 5 层                       -0.077     4.139         5.502
  第 6 层                       +0.280     5.502         7.804
  第 7 层                       +0.268     7.804        10.743
  第 8 层                       -0.412    10.743        15.036
```

看"标准差"这一列：**1.435 → 1.790 → 2.376 → 3.059 → …… → 15.036。**

每过一层，下一层拿到手的数就大一圈。第 8 层拿到的数，比第 1 层大了 10 倍。

## 最简单的尝试

最直觉的想法是：**把数拉回来不就行了？**

怎么拉？一批数据一起看，把每个维度的均值和标准差算出来，然后减掉均值、除掉标准差。这个做法有个好处：它是"数据自己告诉你的"，不需要我们拍脑袋定一个缩放系数。我们把同一批里所有样本、所有位置的数倒进一个大盆，逐维算一遍：

```python
def dumb_normalise(x):
    mu = x.mean(axis=(0, 1), keepdims=True)   # 把整批倒在一起算
    sd = x.std(axis=(0, 1), keepdims=True)
    return (x - mu) / sd
```

能不能用？`experiment.py` 第三节把它跑了一遍。结论是：有三个绕不过去的问题。

**二、训练 8 层，400 步**：

  无归一化：第 0 步 29.77  第 1 步 2.541e+09  第 10 步 nan  第 50 步 nan  第 200 步 nan  第 399 步 nan

无归一化那个：第 0 步的 loss 是 29.8，**走一步就涨到 25 亿**，第 10 步变成 `nan`。

**三、把"最笨的做法"实际跑一遍**：

```text
  同一个样本，换一批邻居，归一化之后拿到的东西就变了：
    这一批里有谁                                    第 0 个位置的头 4 个数
    ------------------------------------------------------
    只它自己一批（1 个样本）             +0.748  +0.307  +0.277  -0.673
    跟第 6 个样本一批（2 个）           +0.765  +0.275  +0.224  -0.584
    跟另外两个一批（3 个）              +0.749  +0.260  +0.195  -0.538
    跟全部 20 个一批                +0.702  +0.300  -0.231  -0.490

    最大差异：0.508    （同一句话、同一个位置，只是邻居换了）
```

同一句话、同一个位置，只因为"跟谁凑成一批"，输出就差到了 0.508。这个"最笨的做法"有三个绕不过去的问题：

**问题一：同一个样本，换一批邻居，结果就变了。**

**问题二：一批只有一个样本的时候，这个统计量就是它自己。**

我们真的用起来的时候是什么样？用户发来一句话，模型就得答。这时候"整批的均值"是没有意义的 —— 一批里就它一个。

**问题三：训练和用的时候，走的是两套逻辑。**

训练时手里有一整批，可以用"这一批的均值和标准差"；用的时候没有"一批"了，只能把训练时攒下来的统计量存起来用。两套东西对不上，就是一个说不清的隐患。

## 新机制

我们换个方向想。

那个"最笨的做法"之所以出问题，是因为它**看别人**：它要问"这一批里的其它样本长什么样"。而我们的模型里，一个位置上的 32 个数，本来就是一个词的完整描述 —— 它需要参考别的词吗？不需要。

所以：

> **不要看别人，就看这一个位置自己的 32 个数。**
>
> 把它拉成均值 0、标准差 1。

这就是**层归一化**（LayerNorm）。公式和"最笨的做法"几乎一样，只是均值和标准差是**沿着最后一维、对每一个位置单独算的**：

```text
mu  = 这 32 个数的平均值
var = 这 32 个数的方差
x_hat = (x - mu) / sqrt(var + eps)
y = x_hat * weight + bias

（eps 是个很小的数，比如 1e-5，只为了防止除以 0）
```

`weight` 和 `bias` 是两个可以学的向量。这一步很重要：**归一化之后，模型还能把它缩放平移回去。**我们不希望把"尺度"这条路彻底堵死 —— 我们只是希望**每一层拿到的尺度别失控**，而"我到底想要多大的尺度"这件事，交给权重自己去学。

拿它和"最笨的做法"对比，三件事一起解决了：

```text
  换成 LayerNorm，同样几个批次：
    只它自己一批（1 个样本）             +0.754  +0.372  +0.037  -0.661
    跟第 6 个样本一批（2 个）           +0.754  +0.372  +0.037  -0.661
    跟另外两个一批（3 个）              +0.754  +0.372  +0.037  -0.661
    跟全部 20 个一批                +0.754  +0.372  +0.037  -0.661

    所有批次的结果完全一样：True
```

- 不看邻居 —— 换谁当邻居都一样。
- 一批只有一个也行 —— 因为压根不需要"一批"。
- 训练和用的时候是同一套逻辑。

顺带说一句：后来有人发现，均值那一步其实可以省掉，只除以均方根就够了（叫 RMSNorm）。省一次减法，算得快一点，效果差不多。我们这里不展开，你只要知道"归一化"这个家族里不止一种做法。

## Python 实现

打开 `after.py`。它在第 17 章的模型上只加了一处：

```python
def blocks(self, tokens):
    x = embedding(self.p["tok"], tokens) + self.p["pos"]
    for i, layer in enumerate(self.layers):
        handed = layer_norm(x, self.p["ln%d_w" % i], self.p["ln%d_b" % i])
        x = x + self.attention(handed, layer)
    return x, records
```

注意两件事：

1. `layer_norm` 是 toygrad 里就有的（第 9 章那个引擎里带着它，接口在 `WRITING_SPEC` 里列着）。它沿着最后一维归一化，正好就是我们要的"一个位置自己的 32 个数"。
2. 归一化加在**动手之前**：`x` 本身不动，只是把"送给 attention 去用的那一份"归一化。残差那一条路还是干干净净的 `x + ...`。这样既拉住了尺度，又没破坏上一章那条直通车道。

归一化的参数有两个：`weight` 一开始全 1，`bias` 一开始全 0 —— 也就是"先什么都不做"。它们跟着模型一起训练。

跑起来：

## 它解决了什么

`experiment.py` 第二节同时跑了两种写法，8 层、400 步、超参数完全一样：

```text
  无归一化：第 0 步 29.77  第 1 步 2.541e+09  第 10 步 nan  第 50 步 nan  第 200 步 nan  第 399 步 nan
  有归一化：第 0 步 4.665  第 1 步 3.841  第 10 步 0.9429  第 50 步 0.08215  第 200 步 0.01251  第 399 步 0.005239
```

- 无归一化：第 0 步的 loss 就是 29.77，**走一步涨到 25 亿**，第 10 步变成 `nan`。
- 有归一化：4.665 起步，一路掉到 **0.0052**，两句话一字不差。

再对照第 17 章那张表：那边 4 层 + 残差是好的，8 层就炸；这边 8 层归一化之后就学会了。**残差让"深"变得可能，归一化让"深"真的走得通。**

一句话总结：**归一化管的不是"模型聪不聪明"，而是"每一层拿到手的数，尺度别乱"。** 它把"第几层"这件事从一个变量变成了一个常量 —— 不管你是第 1 层还是第 8 层，拿到的都是均值 0、标准差 1 的东西。这样：
- 学习率可以只用一套（不用为每一层单独调）；
- 深层再也不怕"一路涨上去"；
- 想让尺度变大变小，交给归一化后面那对 `weight`/`bias` 去学。

## 它还解决不了什么

现在，第 17 章的残差和第 18 章的归一化都到位了，我们的模型已经能稳稳地堆 8 层。可是如果你回头看一眼它到底在干什么，会发现一件奇怪的事：

**每一层都在做同一件事 —— 把别的 token 的信息搬过来。**

第 8 层和第 1 层做的是同一件事，只是"搬"的东西不一样。8 层堆下来，token 之间互相看了 8 轮，信息来来回回交换了很多次。

但我们最初的问题是："苹果"这个词在这一句里到底指水果还是公司？要回答这个，光把"苹果"周围的词搬过来是不够的 —— **搬过来的信息，得有人加工一下**。

我们的模型里，有"搬运"，没有"加工"：从词向量到输出，中间的每一步都是"加权平均"和"线性变换"。

所以下一章的问题很具体：

> **一个 token 把别的 token 的信息取过来之后，它在自己这一层里，有没有机会对这些信息做一次自己的运算？如果没有，我们该往哪加？**

带着这个问题，我们进入第 19 章。
