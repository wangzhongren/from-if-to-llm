# 第 22 章：第一个真正的小语言模型

## 本章的问题

上一章结束的时候，我们把零件清单摊开看了一眼：

| 零件 | 哪一章做的 | 第 21 章用了吗 |
|---|---|---|
| tokenizer / 词表 | 第 1 章 | 用 `CHAR_TO_ID` 顶替 |
| embedding | 第 10 章 | 用了 |
| 位置编码 | 第 16 章 | 用了 |
| self-attention | 第 14 章 | 用了（加了掩码） |
| 多头 | 第 15 章 | **没用** |
| 残差连接 | 第 17 章 | **没用** |
| LayerNorm | 第 18 章 | **没用** |
| MLP | 第 19 章 | **没用** |
| 多层堆叠 | 第 19 章 | **没用** |

一半的零件躺在抽屉里。第 21 章那个模型只有一层 attention，后面直接接线性层。

那最直接的想法就是：**加层啊。**

跑 `before.py` 看看会发生什么：

```text
============================================================
把 attention 一层一层叠上去（中间不加任何东西）
============================================================
    层数         参数量       训练集 loss
  ----------------------------------
     1        7265         0.0030
     2       11361         0.0000
     3       15457         2.8491
     4       19553         3.6271

  一两层还行。从第三层开始，loss 直接掉回到头。

  参考一下：33 个字符，如果模型什么都不学、
  每次都在 33 个字符里瞎猜，loss 应该是 3.4965。
  三层、四层那两个数，基本就是这个水平——它什么都没学会。
```

叠到第三层，模型就废了。`before.py` 里解释了为什么：

```python
x = attention(x) @ W     # 直接把 x 换掉
```

这一行有两个毛病。一是它**替换**而不是叠加，每过一层上一层的 x 就被整个扔掉，三层下来"我是谁、我在第几位"这些信息被冲掉三遍。二是**尺度会跑偏**——x 乘一次矩阵长度就变一次，过一个 softmax 又变一次，没有东西把它拉回正常范围。

第 17、18、19 章早就给出过补丁了。现在该把它们装进去。

## 新机制

这一章没有新机制。真的没有。

`after.py` 里的每一个零件，你都能指出它是哪一章的：

| 代码 | 哪来的 |
|---|---|
| `CharTokenizer.encode / decode` | 第 1 章「把一句话拆开」 |
| `embedding(self.token_embedding, token_ids)` | 第 10 章 |
| `x + self.position_table[:length]` | 第 16 章（固定的正弦表，不参与训练） |
| `query @ key.transpose(...)` | 第 14 章 |
| 切成 `heads` 份再拼回来 | 第 15 章 |
| `scores.masked_fill(mask, -1e9)` | 第 21 章 |
| `x = x + self.multi_head_attention(...)` | 第 17 章 |
| `layer_norm(x, self.norm1_weight, self.norm1_bias)` | 第 18 章 |
| `(hidden @ self.fc_weight + self.fc_bias).relu()` | 第 19 章（里面的 ReLU 是第 8 章） |
| `cross_entropy(logits, targets)` | 第 5 章 |
| `Adam(...) / loss.backward() / optimizer.step()` | 第 9 章 + 第 4 章那一行 `w = w - lr * grad` |

这一章唯一的新东西，是**它们装在一起之后跑起来了**。

所以这一章要说的不是"又一个新机制"，而是：**回头看。** 前面 21 章里每一个看起来绕远的弯路，都在这个文件里有了位置。

## Python 实现

模型分两层：`TransformerBlock`（那个积木）和 `TinyLanguageModel`（积木 + 首尾）。

积木里的注意力子层，把第 14、15、21 章叠在一起：

```python
def multi_head_attention(self, x, mask):
    batch, length, _ = x.shape

    def split(tensor):
        # (B, T, D) -> (B*heads, T, D/heads)
        return tensor.reshape(batch, length, self.heads, self.head_dim).transpose(0, 2, 1, 3)

    query = split(x @ self.query_weight)
    key = split(x @ self.key_weight)
    value = split(x @ self.value_weight)

    scores = (query @ key.transpose(0, 1, 3, 2)) * (1.0 / np.sqrt(self.head_dim))
    scores = scores.masked_fill(mask, -1e9)          # 第 21 章
    weights = scores.softmax(axis=-1)
    attended = weights @ value
    merged = attended.transpose(0, 2, 1, 3).reshape(batch, length, self.dim)
    return merged @ self.out_weight
```

两个子层都是同一句话：**先归一化，再加工，再加回自己。**

```python
def __call__(self, x, mask):
    normed = layer_norm(x, self.norm1_weight, self.norm1_bias)
    x = x + self.multi_head_attention(normed, mask)
    normed = layer_norm(x, self.norm2_weight, self.norm2_bias)
    hidden = (normed @ self.fc_weight + self.fc_bias).relu()
    x = x + hidden @ self.proj_weight + self.proj_bias
    return x
```

注意两层 `layer_norm` 都作用在**加之前**的那个 x 上。这个叫"前置归一化"（pre-norm），是第 18 章那个顺序。

整个模型：

```python
def __call__(self, token_ids):
    batch, length = token_ids.shape
    x = embedding(self.token_embedding, token_ids)
    x = x + self.position_table[:length].reshape(1, length, self.dim)
    mask = causal_mask(length)
    for block in self.blocks:
        x = block(x, mask)
    return x @ self.head_weight + self.head_bias
```

七行。七行就是全部。

## 它解决了什么

**第一次，我们有一个能写字的模型了。**

它接出来的东西是 `床前明月光疑是地上霜举头望明月低头思故乡`。这不是模板，不是查表，是 153,441 个浮点数在 toygrad 里算出来的结果。

再回头看那张零件表：第 17、18、19 章那三个补丁不是白加的。`before.py` 里三层 attention 直接堆，loss 是 2.85（等于没学）；装成 Transformer Block 之后，loss 是 0.0162。

不过 `experiment.py` 会给我们泼一盆冷水。它把零件一个个拆掉，量每个零件值多少：

```text
                                       参数量      loss       准确率
  ------------------------------------------------------------
  完整模型                             153,441    0.0189   99.52%
  去掉多层（只剩 1 个 Block）                53,985    0.0124   99.52%
  去掉 MLP                           153,441    0.0177   99.33%
  去掉残差连接                           153,441    0.0270   99.44%
  去掉 LayerNorm                     153,441 4027.3297    4.95%
  去掉多头（只剩 1 个头）                    153,441    0.0116   99.60%
  去掉位置编码                           153,441    0.0523   99.36%
  去掉因果掩码                           153,441    0.0019  100.00%
```

三行值得单独说。

**一、去掉 LayerNorm，loss 是 4027。**

不是"变差一点"，是根本训不起来。8 个零件里只有它的缺失是致命的。

**二、去掉因果掩码，loss 是 0.0019，全场最低。**

那是作弊。位置 i 能看到 i+1，而 i+1 那一格上写的就是答案。第 21 章那件事在这里又出现了一遍：

> 一个模型的 loss 好不好，取决于它被允许看到什么。

**三、剩下的几行，拆掉之后 loss 反而更低。**

这一列数字会让第 17 章和第 19 章的读者不舒服："我们辛辛苦苦造出来的残差和 MLP，拆了反而更好？"

不是零件没用。是这个实验的规模太小了。**我们的语料只有 304 个字符。** 任务简单到一层 attention 就够了。我们拿 153,441 个参数去拟合 304 个字符，多出来的参数在同样的步数里只是更难训而已。

残差和 MLP 的价值，要在更大的数据和更深的模型上才看得见。这件事的规律，第 28 章会正式讲。

## 它还解决不了什么

回头看 `after.py` 第 5 节那段诗。那段诗是怎么出来的？

我们写了一个循环。每次做两件事：

1. 把已经写好的字喂给模型
2. 拿它给出的**概率最大的那个**字，接到后面

模型自己不知道什么叫"写一段诗"。它只会回答一个问题：给你这些字，下一个最可能是什么？

所以严格地说，**这个模型只会预测，不会生成**。那段诗是我们用人肉循环接出来的。

而"人肉循环"里有好几个我们还没回答的问题：

- 每次都挑概率最大的那一个，是唯一的选择吗？如果换成按概率随机挑，会怎样？
- 我们刚才试了三个开头。换成随机挑之后，同一个开头会不会每次都写出不一样的东西？
- 如果每次都挑最大的，会不会永远是同一句话？如果挑了第二大的，是不是就"错"了？
- 我们喂进去的开头越长，它写得越好还是越差？

下一个问题是：**"生成"到底是什么？把预测一个接一个接起来，为什么就能变成"写文章"？**
