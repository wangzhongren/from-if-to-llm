# 《从 If 到 LLM》

### 从一条分类规则开始，亲手造出一个语言模型

---

## 这是一本什么书

大多数讲 Transformer 的材料，一上来就告诉你：

> Transformer 由 Multi-Head Attention、Feed-Forward Network、Residual Connection、
> Layer Normalization 和 Positional Encoding 组成。

然后你记住了这五个词，但你不知道为什么是这五个，而不是别的五个。

这本书反过来走。

**每一章只解决上一章留下的一个问题。**

不提前讲概念。先遇到问题，再发明机制，最后才告诉读者这个机制叫什么。

走完全程之后，你会发现自己"被迫"发明出来的东西，正好就是 Transformer：
你没有被告知 Attention 有哪些组件，你是**不得不**把它们一个个造出来的。

---

## 这条链子

```text
文本
 → 分词
 → if/else 规则
 → 规则数字化
 → 让机器学习规则
 → 学习特征
 → 学习词表示
 → 学习上下文
 → 学习信息关系（Attention）
 → 残差与归一化
 → Transformer Block
 → 预测下一个 token
 → LLM
```

每一个箭头，都是上一章末尾那个"它还解决不了什么"。

## 怎么读

**不要跳章。** 这本书的全部价值在于顺序——每一章都建立在上一章的**缺陷**之上。
跳过第 12 章，你就不明白第 13 章为什么需要 Attention。

每一章的结构是固定的：

| 小节 | 作用 |
|---|---|
| **本章的问题** | 上一章哪里不够 |
| **最简单的尝试** | 先用最直觉（往往是错的）的办法 |
| **实验** | 跑代码，亲眼看到旧方法失败 |
| **新机制** | 只讲这一章真正需要的那个新概念 |
| **Python 实现** | 完整代码 |
| **它解决了什么** | 用实验数据说话 |
| **它还解决不了什么** | 引出下一章 |
| **练习** | 改参数、改数据、改结构 |

**每一章都要动手跑。** 读代码学不会这些东西，看它失败才能。

## 怎么跑

项目自带虚拟环境（Python 3.12 + numpy + pytest + torch）：

```bash
cd from-if-to-llm

# 跑某一章的产物
./.venv/bin/python chapter_03/after.py

# 对比：这一章的问题（旧做法）
./.venv/bin/python chapter_03/before.py

# 关键实验
./.venv/bin/python chapter_03/experiment.py

# 本章测试
./.venv/bin/python -m pytest chapter_03/tests/ -q
```

一键跑通全部章节：

```bash
./run_all.sh          # 全部 30 章
./run_all.sh 13 16    # 只跑第 13 到 16 章
```

### 哪些章节跑得慢

绝大多数脚本几秒内结束。只有下面几个会明显停顿，**不是卡死了**：

| 脚本 | 大约耗时 | 为什么 |
|---|---|---|
| `chapter_22/experiment.py` | ~1.5 分钟 | 逐个拆零件做消融，每个都要重训 |
| `chapter_24/experiment.py` | ~3 分钟 | 训 7 个模型做 2×2 交叉评估 |
| `chapter_22/after.py` | ~20 秒 | 真的在训练那个小语言模型 |

其余章节的脚本基本都在 20 秒以内。所有随机过程都固定了种子，
跑出来的 loss、准确率等数字和书上完全一致；只有**墙钟时间和内存**会随机器浮动。

### 环境说明

| 依赖 | 用在哪 |
|---|---|
| Python 标准库 | 第 1–8 章（**刻意不用任何第三方库**，让机制本身可见） |
| numpy | 第 9 章起 |
| pytest | 全书测试 |
| PyTorch | 第 25 章起 |

第 1–24 章**不使用**任何深度学习框架。第 9 章会有我们自己写的自动求导引擎
（[toygrad/](toygrad/)），第 22 章的语言模型就跑在它上面。
到第 25 章换成 PyTorch 时，你应该会有一种"这不就是我写过的东西吗"的感觉——
这正是这本书想给你的。

重新安装依赖：

```bash
python3.12 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
```

## 每章的目录结构

```text
chapter_XX/
├── README.md        # 正文（八个小节，固定结构）
├── before.py        # 上一章的代码用在这一章的场景下 —— 跑起来会失败
├── after.py         # 本章的产物 —— 跑起来能看到改善
├── experiment.py    # 让"旧方法为什么不行 / 新方法为什么行"变得可见
├── exercises.md     # 练习
└── tests/           # 本章机制的测试
```

`before.py` 是这本书的一个特色：**它刻意是错的**。
看着它失败，你才会真正想要下一章的那个机制。
