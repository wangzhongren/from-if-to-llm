# 第 19 章：Attention 后面为什么还有 MLP

## 本章的问题

到上一章为止，我们的模型已经是一个能堆的模型了：

```text
词向量 + 位置编码 → [ 归一化 → Attention → 加回去 ] × 8 → 输出
```

8 层，稳，能学会。如果现在就把它拿去用，你会发现一个问题 —— 它能做的事，其实只有一件：

**把别的位置的信息搬过来。**

第 8 层和第 1 层做的是同一件事，只是"搬"的东西不一样。8 层堆下来，每个词都看了别的词 8 轮，信息来来回回交换了很多次，但**没有任何一个位置，对搬过来的东西做过一次自己的运算**。

回到我们最早的那个问题：`苹果` 在这一句里到底是水果还是公司？要回答它，光把"苹果"周围的词搬过来是不够的 —— 搬过来之后，得有人**下判断**。

所以这一章要问的是：

> 一个位置把别人的信息取过来之后，谁负责加工？

我们得先造一个任务，把"交换"和"加工"这两件事分开。真实语料上的任务做不到这一点 —— 那里的任务（比如挖空还原）只要"搬运"就够了，所以看不出差别。于是我们造一个最小的探针任务：

```text
每个位置给一个 32 维向量（随机生成，并且先做一次标准化）
要求每个位置输出一个 0/1：
    它自己前两个数，异或一下
    （一个正一个负 → 1；同号 → 0）
```

这个任务的答案**只取决于这个位置自己** —— 不需要任何"交换"，纯粹考"加工"。而且它是第 7 章那个 XOR 的老朋友：一条直线分不开它，加权平均也分不开它。

## 最简单的尝试

最简单的尝试是"再堆几层"。

第 17、18 章刚把"堆层数"修好（残差、归一化），所以我们很自然地想：**交换的次数多了，是不是自然就会加工了？**

打开 `before.py`，它就是第 18 章的模型 —— 残差、归一化、Attention，两个块 —— 只有一个区别：这个模型里没有"加工"的地方。跑 900 步：

```text
  第   0 步    loss = 1.3330
  第 150 步    loss = 0.6997
  第 300 步    loss = 0.6961
  第 450 步    loss = 0.6954
  第 600 步    loss = 0.6875
  第 750 步    loss = 0.6816
  第 899 步    loss = 0.6730

  测试集：loss = 0.7035   准确率 = 50.3%
  （瞎猜是 50%，loss 是 0.6931）
```

**50.3%。** 900 步下来，loss 从 0.699 动到 0.673，就再也没动过 —— 这个模型买彩票和认真答题的成绩一模一样。

## 实验

跑 `experiment.py`。它做三件事，一件比一件更清楚。

**一、在真实语料上把零件拆开。**

用那两句话做"挖空还原"（第 17、18 章那个任务），2 个块、400 步，分别把 Attention 和 MLP 拆掉：

```text
  结构                        loss          被挖空的位置填对
  ----------------------------------------------
  只有 MLP                  0.0621             11/20
  只有 Attention            0.0111             20/20
  Attention + MLP         0.0051             20/20
```

"只有 MLP"这一行的 11/20 就是"瞎猜"的成绩（每个空位有两个可能的答案：它可能是第一句那个词，也可能是第二句那个词）。原因很直白：**没有 Attention，这个位置根本看不到别的词**，它只能靠自己那一个位置的信息去猜。

所以"交换"这一半工作，确实必须由 Attention 来做。

**二、把同一个探针任务交给三种结构。**

```text
  结构                       训练 loss     测试 loss       测试准确率
  --------------------------------------------------------
  只有 MLP                    0.0253      0.1427       94.1%
  只有 Attention              0.6730      0.7035       50.3%
  Attention + MLP           0.0331      0.2304       91.3%
```

- **只有 MLP：94.1%** —— 它压根不看别的位置，但"加工"这件事它做得了。
- **只有 Attention：50.3%** —— 它连"自己身上两个数异或一下"都做不到。
- **Attention + MLP：91.3%** —— 两个都有，就都行。

（顺便说一句，这个探针任务本来就不需要"交换"，所以"只有 MLP"反而比"两个都有"略好一点点 —— Attention 在这儿帮不上忙，只是陪着跑。真实任务两样都要，看第一部分那张表。）

**三、为什么 Attention 做不到？**

我们拿真实的那两句话，喂给 attention 层，把它的权重拿出来看：

```text
  1) 一层 attention：输出的每一行，是不是「值的加权平均」？
     权重矩阵：每行求和 = 1.000000 ~ 1.000000，最小权重 = 0.000142
     手算的平均 vs 库算的输出，最大误差 = 0.00e+00

  2) 堆 8 层：每一层都还是「平均」，只是平均的对象换了
     8 层的权重连乘之后：每行求和 = 1.000000 ~ 1.000000，最小权重 = 0.018808
     8 层输出 vs 输入的一次加权平均：最大误差 = 4.44e-16
     8 层里，输出跑出「这一层的值的范围」的最大越界量 = 0.0000000000

  3) 换成 MLP：输出可以跑到输入范围外面去
     MLP 输出的最大越界量 = 5.597893
     （输入的第 0 维范围是 [-3.087, +1.605]，MLP 输出是 [-4.555, +2.775]）
```

这三行数字是关键，逐条看：

1. 一层 attention 的权重，**每一行加起来精确等于 1，每个数都不是负的**（这是 softmax 的必然结果）。而它的输出，**精确等于"这些权重乘上这些值"**（误差 0.00e+00）。也就是说，这一层没有干别的事 —— 它就是一个加权平均。
2. 把 8 层的权重矩阵乘起来，得到的矩阵**每一行还是加起来等于 1**，还是非负。所以 8 层之后，每个位置拿到的**仍然是输入的一次加权平均**（最大误差 4.44e-16）。平均的平均，还是平均。
3. 加权平均有一个绕不过去的性质：**结果一定落在"被平均的那些数"的范围里**。8 层跑下来，越界量恒等于 `0.0000000000`。而 MLP 不是平均 —— 它的输出越界量是 5.6，跑到了输入根本达不到的地方。

一句话：**Attention 只能在"已有的数"之间重新分配，它造不出新的东西。** 而"两个数异或一下"这种判断，需要的就是一次真正的非线性运算 —— 这正好是第 7 章那条教训：一条直线不够用，得加中间层。

## 新机制

我们需要一个**逐个位置、各自算术**的东西。于是往 Attention 后面接一个小网络：

```text
线性（升维）  →  ReLU  →  线性（降维）
```

就这个。三个细节：

**一、它是"逐位置"的。** 同一个网络，套在每个位置上各算各的 —— 位置 3 算的时候完全看不见位置 5。这和 Attention 刚好互补：Attention 只会看别人，MLP 只会看自己。

**二、中间为什么要升维。** 32 维进来，先变成 128 维，ReLU 一下（把负数抹成 0），再压回 32 维。中间宽一点，是为了给非线性留出地方 —— 不然挤在原来的 32 维里，能做的变换太少。

**三、它和 Attention 用的是同一种接法**：归一化 → 干活 → 加回去。上一章和上上章的东西一个字没改。

```python
x = x + attention(层归一化(x))     # 交换
x = x + MLP(层归一化(x))           # 加工
```

这两个人凑在一起，就是一个完整的块。这个东西有个正式名字 —— 从第 25 章往后你会天天见到它：

> **这一整块，我们叫它 Transformer Block。**

现在我们手里有了全部零件：

```text
        输入（每个位置一个 32 维向量）
          │
          ├──────────────┐
          ↓              │
       层归一化           │
          ↓              │
       Attention（交换）   │    ← 从别的 position 取信息
          ↓              │
          + ←────────────┘
          │
          ├──────────────┐
          ↓              │
       层归一化           │
          ↓              │
       MLP（加工）        │    ← 自己 position 内部做一次非线性变换
          ↓              │
          + ←────────────┘
          │
          ↓
        输出
```

残差连接（第 17 章）、层归一化（第 18 章）、Attention（第 14–16 章）、MLP（本章），一个不多一个不少。

## Python 实现

打开 `after.py`。和第 18 章的模型相比，只多了一个方法：

```python
def mlp(self, x, block):
    """逐位置的小网络：升维 → ReLU → 降维。每个位置各算各的，互相看不见。"""
    hidden = (x @ block["W1"] + block["b1"]).relu()
    return hidden @ block["W2"] + block["b2"]
```

以及 `hidden()` 里多出来的一行：

```python
def hidden(self, x_in):
    x = x_in if isinstance(x_in, Tensor) else Tensor(x_in)
    for block in self.blocks:
        # 交换：这个位置去别的位置那里取信息
        x = x + self.attention(layer_norm(x, block["ln1w"], block["ln1b"]), block)
        # 加工：这个位置自己内部做一次非线性变换
        x = x + self.mlp(layer_norm(x, block["ln2w"], block["ln2b"]), block)
    return x
```

`block["W1"]` 的形状是 `(32, 128)`，`block["W2"]` 是 `(128, 32)` —— 先升维再降维。归一化有两套参数（`ln1` 给 Attention 用，`ln2` 给 MLP 用），因为这两个人拿到手的东西不一样。

跑起来：

```text
  第   0 步    loss = 2.6079
  第 150 步    loss = 0.6298
  第 300 步    loss = 0.4190
  第 450 步    loss = 0.1480
  第 600 步    loss = 0.1017
  第 750 步    loss = 0.0461
  第 899 步    loss = 0.0331

  测试集：loss = 0.2304   准确率 = 91.3%
  （瞎猜是 50%，loss 是 0.6931）
```

## 它解决了什么

把三行数字并排放在一起：

| 结构 | 探针任务（要加工） | 真实任务（要交换） |
|---|---|---|
| 只有 MLP | **94.1%** | 11/20（瞎猜） |
| 只有 Attention | **50.3%**（瞎猜） | 20/20 |
| Attention + MLP | **91.3%** | 20/20 |

两件事各归各的：

- **交换**：一个位置要拿到别的位置的信息，只有 Attention 做得到。MLP 因为"看不见别人"，在这件事上完全无能。
- **加工**：一个位置要对自己拿到的东西做一次运算，只有 MLP 做得到。Attention 因为"只会加权平均"，在这件事上也完全无能（50.3%，就是买彩票）。

而真实语言里，两件事都要：先要把上下文取过来，再要对取过来的东西下判断。

这一章结束后，我们的模型第一次"完整"了 —— 从一个词向量出发，经过交换与加工，最后得到一个能用来下判断的向量。这个结构后来被叫做 Transformer Block，第 25 章之后我们会用 PyTorch 把它重写一遍，你会发现它一个零件都没有变。

## 它还解决不了什么

现在模型输出的东西是什么？还是**一堆向量**：两个块处理完，每个位置拿到一个 32 维的向量。

可我们想要的是什么？是**一个词**。

回头看这个任务：让模型填出被挖空的词 —— 我们之所以能做到，是因为最后接了一个 `(32, 词表大小)` 的输出层，把向量变成了"每个词的分数"。这个输出层是这个任务专用的。

但如果是"预测下一个词"呢？如果我想让这个模型自己往外写句子呢？它现在只会吐向量，不会吐词。而且还有一个更基本的问题：

> **我们现在做的任务，都是"给一句话、挖个空、填回来"。这更像填空，不像说话。一个会自己往下写的模型，应该拿一句话就能接着往下说 —— 而那时，它要输出的不是"从这句话里挑一个词填回去"，而是"下一个词是什么"。**

从一个"填空的模型"到一个"会说话的模型"，中间差的那一步叫什么？第 20 章我们要把第 2 章那个老朋友请回来：**分类器**。
