# 第 21 章：为什么训练时不能偷看答案

## 本章的问题

上一章最后留下了一个疑点，我们把它抄在这里：

> 如果换成「一次喂进整段语料、让每个位置都输出下一个字符」，
> 那就变成：输入 `ids[t : t+T]`，答案 `ids[t+1 : t+T+1]`。
> 对窗口里的第 i 个位置来说，它要预测的是 `ids[t+i+1]`，
> 而这个字符，正好是窗口里第 i+1 个位置上的**输入**。

上一章还有一个没解决的问题。先跑 `before.py` 看看：

```text
============================================================
毛病一：窗口是写死的
============================================================
  第 20 章的模型吃固定 8 个字符。现在给它一段话：
    明月光疑是地上霜举头望明月   （13 个字符）

  窗口是 8，所以只能取最后 8 个：地上霜举头望明月
  前面这 5 个字符被丢掉了：明月光疑是

  「明月光疑是」这几个字对模型来说不存在。
  窗口的位置是固定的，多出来的信息只能扔。

  反过来，给它一段只有 3 个字符的话：明月光
  窗口要 8 个，凑不够。少一格，形状就对不上：
    embedding 之后是 3 × 16 = 48 个数，
    线性层要的是 8 × 16 = 128 个数。
  差的不是一点点。
```

第二个毛病在参数量上：

```text
      窗口          线性层参数        loss        准确率
  --------------------------------------------
       2           1089      0.0870    94.70%
       4           2145      0.0046   100.00%
       8           4257      0.0026   100.00%
      16           8481      0.0016   100.00%
      32          16929      0.0010   100.00%

  窗口从 2 翻到 32，参数从 1089 涨到 16929，16 倍。
  loss 却从 0.0870 掉到 0.0026（窗口 8），后面基本不动了。

  要让它看到 1000 个字符，线性层就是 528,033 个参数。
  我们的语料一共才 304 个字符。
```

所以我们想要的是另一个东西：**不管序列多长都能吃进去，参数量跟长度没关系，而且每个位置能自己决定要看哪里。**

第 14 章我们造出过这个东西，它叫 attention。Q 是"我在找什么"，K 是"我有什么"，V 是"我给出什么"，权重是算出来的，不是写死的。

那就把它加回来。

但加回来之前，先把上一章那个疑点记住：**位置 i 要预测的字符，就是位置 i+1 上的输入。而 attention 会让位置 i 看到所有位置。**

## 最简单的尝试

最简单的做法就是：**什么都不做。**

把窗口拼接换成 attention，别的照旧：

```python
def __call__(self, token_ids, use_causal_mask=True):
    x = embedding(self.token_table, token_ids) + self.position_table[:length]
    query = x @ self.query_weight
    key = x @ self.key_weight
    value = x @ self.value_weight
    attention = (query @ key.transpose(0, 2, 1)) * (1.0 / np.sqrt(self.dim))
    if use_causal_mask:
        attention = attention.masked_fill(causal_mask(length), -1e9)
    weights = attention.softmax(axis=-1)
    return (weights @ value) @ self.head_weight + self.head_bias
```

`after.py` 把 `use_causal_mask=True` 和 `False` 各训一遍。

## 实验

先看训练 loss：

```text
============================================================
对照组一：不做任何遮挡
============================================================
  第  500 步   loss 0.00445
  第 1000 步   loss 0.00159
  第 1500 步   loss 0.00094
  第 2000 步   loss 0.00061
  整个数据集上的 loss   0.00061

============================================================
对照组二：把未来挡住（因果掩码）
============================================================
  第  500 步   loss 0.00541
  第 1000 步   loss 0.00280
  第 1500 步   loss 0.00351
  第 2000 步   loss 0.00595
  整个数据集上的 loss   0.00309
```

不做遮挡那个 **0.00061**，挡住了的 **0.00309**。低的那边赢了 5 倍。

如果你只看这一行数字，你会得出结论："挡什么挡，让它看啊。"

那就让它写两个字看看：

```text
  开头：床前明月光

  不做遮挡：床前明月光低低低红红掌望明绿明月明绿明月明前明绿明绿明绿明月明绿水明月
  因果掩码：床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿水低头
```

**这就是答案。**

不做遮挡的那个，loss 低得多，写出来的东西是垃圾。加了掩码的那个，loss 高一截，写出来的是诗。

`experiment.py` 把这件事做细：给"位置 i 最多能往后看几格"设一个数字，从 0 一步步放到不挡，看每一档的表现。

```text
============================================================
结果
============================================================
  往后看       训练 loss   遮住未来之后   接出来的文字
  --------------------------------------------------------------
      因果掩码     0.00309      0.00309   床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天
       1 格     0.00046      4.87624   床前明月光疑月月明月明月明月明月明月明月明月明月明月明
       3 格     0.00052      5.48393   床前明月光疑上霜故疑故举是举是举歌故故疑是举歌举是疑是
       7 格     0.00059      5.67865   床前明月光疑望明月明月低低低前明月明月明月低举举清望明
        不挡     0.00061      5.71646   床前明月光低低低红红掌望明绿明月明绿明月明前明绿明绿明
```

中间那一列是"**遮住未来之后再测一遍**"。同一个模型，同一个数据集，只是评估的时候把未来挡上。

- 因果掩码那一档：0.00309 → 0.00309，纹丝不动。它本来就只看过去，挡不挡对它没影响。
- 其他三档：从 0.0005 直接炸到 5 左右。

**同一份训练数据，同一个模型结构，同一个 loss 函数。唯一的变化是位置 i 能不能看到 i+1。**

看见 i+1 的那一刻，模型就不再学"预测"了。它学的是"往右边看一眼，抄过来"。抄得又快又准，loss 掉得漂亮极了。

而真到了要写字的时候，右边那一格是空的。没得抄。

所以：

> **训练 loss 低，不代表模型学会了你想让它学的东西。**

这是这一章最值钱的一句话。它适用于后面所有的章节——第 28 章讲规模、第 29 章讲一个会写字的模型怎么变成会聊天的助手，你都会再遇到它。

## 新机制

新机制简单得有点好笑：**把不许看的位置的分数，填成一个很大的负数。**

```python
mask = np.triu(np.ones((length, length), dtype=bool), k=1)
attention = attention.masked_fill(mask, -1e9)
```

`mask` 是一个上三角矩阵，`True` 表示"不许看"。`k=1` 的意思是：对角线留空，从对角线右上方一格开始填。

`-1e9` 这个数，是为了让 softmax 之后那一格正好变成 0。因为 softmax 是 `exp(x) / sum(exp(x))`，`exp(-1e9)` 是 0。不是"很小"，是精确的 0。

它的形状长这样（长度 8 的例子）：

```text
        0  1  2  3  4  5  6  7     <- 被看的位置
   0   .  X  X  X  X  X  X  X    <- 看的位置 0
   1   .  .  X  X  X  X  X  X    <- 看的位置 1
   2   .  .  .  X  X  X  X  X    <- 看的位置 2
   3   .  .  .  .  X  X  X  X    <- 看的位置 3
   4   .  .  .  .  .  X  X  X    <- 看的位置 4
   5   .  .  .  .  .  .  X  X    <- 看的位置 5
   6   .  .  .  .  .  .  .  X    <- 看的位置 6
   7   .  .  .  .  .  .  .  .    <- 看的位置 7

  X = 挡掉   . = 允许
```

**位置 i 看得见的位置，永远只有 0..i。** 一个位置只能被它之前的东西影响，不能反过来。

这个掩码叫**因果掩码**（causal mask）。"因果"两个字的意思是：后面的事不能影响前面的事——就像原因不能发生在结果之后。

注意对角线上的 `.`。位置 i 必须能看到自己，不然它连"我刚刚写了什么"都不知道。

## Python 实现

`after.py` 里只多了一个函数和一行调用：

```python
def causal_mask(length):
    """上三角（不含对角线）为 True 的方阵。"""
    return np.triu(np.ones((length, length), dtype=bool), k=1)
```

```python
if use_causal_mask:
    attention = attention.masked_fill(causal_mask(length), -1e9)
```

`masked_fill` 是 `toygrad` 里就有的接口（第 9 章那个引擎里带着它），做的事是"mask 为 True 的地方填上 value"。第 14 章我们学会了给 attention 加权，这一章我们学会了把某些权重强行按成 0。

模型的其他部分，和上一章相比只有一处换掉了：

| | 第 20 章 | 第 21 章 |
|---|---|---|
| 怎么让位置之间互相看见 | 把窗口里 8 个向量拼起来 | attention（Q / K / V） |
| 参数量跟长度有关吗 | 有关，线性增长 | 无关 |
| 能不能吃变长输入 | 不能 | 能 |
| 训练时能不能偷看 | 看不到（窗口只有过去） | **默认能，必须用掩码挡住** |

还有一个细节：`position_table` 是必须的。attention 本身分不清谁在前谁在后——它做的是加权求和，把输入顺序打乱，结果一模一样。第 16 章讲的位置编码在这里才真正派上用场。

## 它解决了什么

```text
  解决了：
    - 序列多长都能吃（参数量跟长度无关）
    - 每个位置自己决定看哪里，不是固定往前看 8 格
    - 训练的时候不偷看答案了
```

第三件事是这一章的正题。因果掩码让"训练时看到的"和"生成时能拿到的"变成同一件事：

- 训练时，位置 i 只能看 0..i
- 生成时，位置 i 能拿到的也只有 0..i（因为 i 后面的字还没写出来）

两边一致，模型学到的本事才能用在生成上。`after.py` 最后一个实验段里，加了掩码的模型从 `床前明月光` 接出来了：

```text
  因果掩码：床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿水低头
```

一个字都没错。

## 它还解决不了什么

它现在只有**一层 attention**，后面直接接一个线性层。

这样能跑，但堆不深。第 19 章说过 attention 只会**交换**信息，不会**加工**信息——它把各个位置的东西搬来搬去，但不做任何逐位置的变换。第 17、18 章说过，没有残差连接和 LayerNorm，层数一多就学不动。

到这里为止，我们手上有的零件是：

| 零件 | 哪一章做的 | 现在在哪 |
|---|---|---|
| tokenizer / 词表 | 第 1 章 | 用 `CHAR_TO_ID` 顶替 |
| embedding | 第 10 章 | 用了 |
| 位置编码 | 第 16 章 | 用了 |
| self-attention | 第 14 章 | 用了（加了掩码） |
| 多头 | 第 15 章 | **没用** |
| 残差连接 | 第 17 章 | **没用** |
| LayerNorm | 第 18 章 | **没用** |
| MLP | 第 19 章 | **没用** |
| 多层堆叠 | 第 19 章 | **没用** |

一半的零件还躺在抽屉里。而它们被造出来的理由，在这一章里一个都没消失：

**如果我们把第 19 章装好的 Transformer Block 一层一层堆上去，会不会更好？**
