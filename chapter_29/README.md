# 第 29 章：从语言模型到 ChatGPT

## 本章的问题

上一章最后留下了一句话：**会预测下一个词，不等于会聊天。**

这句话不是修辞。我们把一个语言模型训练到 loss 0.46，它预测下一个字已经很准了，
然后你打开对话框，问它：

```text
今天天气怎么样？
```

它不会回答你。它会接着往下写——因为在它的训练数据里，"今天天气怎么样？"
这句话后面跟着的，往往是另一句话，而不是一个答案。

我们先用代码把这件事看具体。

## 最简单的尝试

最直觉的两个修法：**训练更久**，或者**把模型做大**。

但先别急着动手，问一个问题：我们的模型到底"知不知道"苹果是甜的？

`before.py` 做了这个探测。同一个事实，用两种方式问它：

```text
同一个事实，我们用陈述句问它，它接得又快又准：
  苹果很 -> 甜。华为发布新电脑。

用问句问它，它就不会了：
  问：苹果甜吗？答：这个苹果很甜。香蕉很甜。华为发布
```

看出来了吗？它**知道**"苹果很甜"这件事——给它"苹果很"这三个字，
它立刻接"甜"。它甚至在被问句之后，接出来的内容里也提到了"这个苹果很甜"。

但它没有在**回答**。它在**续写**：

```text
  问：苹果甜吗？答：问：这个苹果甜吗？答：苹果很好吃
  问：苹果好吃吗？答：问：华为发布新电脑吗？答：香蕉很
```

它不是答错，而是根本没在答。因为在它的训练语料里，
问句后面跟着的从来不是答案——是另一个问句，或者一句闲聊。它把这一点也学会了。

**所以它缺的不是参数，也不是数据量，而是一种新的数据格式。**

## 实验

`after.py` 做了三个阶段的对比实验。同一个模型（108,032 个参数，一个零件都不改），
依次喂三种数据。

（下面贴的都是实跑输出。**loss、准确率、参数量这些数字是固定的**——我们把随机种子写死了；
**时间会随机器而变**，你跑出来的可能和这里不一样。）

### 阶段一：预训练（预测下一个字）

数据是"一堆没整理过的文本"：陈述句、问句、闲聊混在一起，**只有问句，没有答案**。

```text
  第 200 步  loss = 0.406
  第 400 步  loss = 0.357
  第 600 步  loss = 0.361
用时 2 秒

现在拿一个问题去问它：问：苹果甜吗？答：
它续写出来的东西是：
  问：香蕉甜吗？答：问：这个苹果甜吗？答：
  小米发布新手机。华为发布新电脑。小王在看
```

### 阶段二：指令微调（只在"回答"上算 loss）

数据换成（问，答）配对：`问：苹果甜吗？答：甜。<结束>`

训练目标几乎没变——还是预测下一个字，还是交叉熵。唯一的区别是：
**提示部分（"问：……答："）不算 loss**，只有答案那几个字算。

```text
  第 100 步  loss = 0.079（只在答案那几个字上算）
  第 200 步  loss = 0.074
  第 300 步  loss = 0.067
用时 1 秒

同样的问题，再问一次：
  问：苹果甜吗？答：甜。[结束]
  问：苹果好吃吗？答：苹果好吃吗？好吃。[结束]
  问：香蕉甜吗？答：这个问题问得好。香蕉甜。[结束]
  问：香蕉好吃吗？答：香蕉好吃吗？好吃。[结束]
```

它会答了，也会在答完之后说"结束"（`<结束>` 是我们加进去的一个特殊 token——
预训练语料里从来没有它，模型是在这一阶段才学会"说完了就该停下"的）。

注意里面有两种风格：`甜。[结束]` 和 `苹果甜吗？好吃。[结束]`。
这是故意的：我们喂给它的微调数据里两种都有，就像真实的标注员各有各的写法。
这一阶段之后，模型两种都会，但**还没有"更喜欢哪个"**。

### 阶段三：偏好对齐（让人喜欢的回答概率更高）

数据换成三件套：（问，好回答，差回答）。

```text
回答                        类型      对数概率    概率
----------------------------------------------------------------------
甜。[结束]                  被选中    -0.71       0.491
苹果甜吗？甜。[结束]        被拒绝    -0.75       0.472
```

两个回答现在的概率差不多（0.49 对 0.47）。跑 100 步偏好对齐：

```text
  第  50 步  偏好 loss = 0.6737
  第 100 步  偏好 loss = 0.5214
用时 0 秒

回答                        类型      调之前          调之后
----------------------------------------------------------------------
甜。[结束]                  被选中    0.491           0.968
苹果甜吗？甜。[结束]        被拒绝    0.472           0.011
```

被选中的那个上去了，被拒绝的那个掉下去了。
数据里没有一个字提到"要简洁"，但模型的习惯被这张偏好表改变了：

```text
同一批问题，用同一个随机种子再生成一遍：
  问：苹果甜吗？答：甜。[结束]
  问：苹果好吃吗？答：好吃。[结束]
  问：香蕉甜吗？答：甜。[结束]
  问：香蕉好吃吗？答：好吃。[结束]
```

### 三把尺子量三个分支

`experiment.py` 把同一个预训练模型复制成几份，喂不同的数据，然后用三把尺子量：

```text
模型                      答对率      原始文本 loss   短答比例
--------------------------------------------------------------------------
只做了预训练              0/7         0.396           0%
继续喂原始文本 300 步     0/7         0.412           0%
喂指令数据 300 步         5/7         2.349           46%
指令数据 + 偏好对齐       7/7         2.592           100%
```

三个数字各自说明一件事：

**一、答对率。** 预训练做得再久，一个都答不对；换成指令数据，300 步就对了 5 个，
再对齐一下就是 7 个。同一个模型、同样的步数、差不多的字符量——
差的是数据的**形状**。

**二、原始文本 loss。** 从 0.40 涨到 2.35。它几乎把"怎么续写文本"忘光了。
这是真实世界里"对齐税"（alignment tax）的极端版本：我们的微调数据太少、
步数太多，几百步就把原来的本事冲掉了。真实模型的数据多得多，退得没这么狠，
但"学会了听话、忘掉了别的"这件事一直在发生。

**三、短答比例。** 偏好对齐之前，干脆的回答和绕一圈的回答各占一半；
对齐之后"直接回答"变成默认选择。而我们从来没有写过"要简洁"这条规则。

## 新机制

这一章的新东西**不在模型里，在数据里**。

模型从第 25 章起就没有改过（`after.py` 里那句话是真的：一个零件都没动）。
变的是我们喂给它的文本长什么样，以及**在哪些位置上算 loss**。

三个阶段的名字，以及它们各自的目标：

| 阶段 | 数据长什么样 | 训练目标 | loss 还是交叉熵吗 |
|---|---|---|---|
| **预训练**（pre-training） | 一堆没整理过的文本 | 每个位置都预测下一个字 | 是 |
| **指令微调**（instruction tuning，也叫 SFT） | （问，答）配对 | **只在答案那几个字上**预测下一个字 | 是（换了位置） |
| **偏好对齐**（preference alignment） | （问，好答，差答）三件套 | 让"好答"的概率高于"差答" | 不是，但没有新东西 |

这张表是这一章的全部。我们一个一个说。

**一、预训练：目标就是我们一直在做的那个。**

第 20 章那个目标："给定前面的字，预测下一个字。"预训练和它的关系是：
**同一个目标，喂给它的文本多到没边**。它学到的是语言的规律和世界的事实，
但它学到的"回答方式"是从文本里统计出来的——网上的问句后面跟着的往往不是答案。

**二、指令微调：目标没变，换的是"在哪些位置算 loss"。**

这是整本书里最值得停下来看一眼的一步。指令微调的损失函数是：

```python
per_token = cross_entropy(logits, targets, reduction="none")
loss = (per_token * mask).sum() / mask.sum()
```

`mask` 只在答案那几个字上等于 1。**提示部分被乘成 0 了。**

也就是说：我们不是在教它新知识（"苹果甜"这件事它早就知道），
我们是在告诉它"在这种格式下，你应该把注意力放在产出答案上"。
用一句话概括就是：

> 预训练教它**世界是什么样的**，指令微调教它**在这种场合该干什么**。

顺便说一个细节：`<结束>` 这个 token。它是一个普通的 token，
只是预训练语料里从来没有出现过——所以模型是在微调阶段**才学会**"说完了要停"的。
ChatGPT 里的那些特殊 token（`<|im_start|>`、`<|endoftext|>`）就是干这个用的。

**三、偏好对齐：目标第一次变了。**

前两个阶段，模型都在"预测下一个字"。到了这一步，我们不再问"下一个字是什么"，
而是问：

> **这两个回答，人更喜欢哪一个？**

这是全书里训练目标第一次发生**性质上的**变化。它的实现（我们用的 DPO 的简化版）是：

```python
chosen_ratio  = log P_新(好回答) - log P_旧(好回答)
rejected_ratio = log P_新(差回答) - log P_旧(差回答)
loss = -log sigmoid(β * (chosen_ratio - rejected_ratio))
```

它要的只有一句话：**让"好回答"的概率比"差回答"更高**，而且是相对于
"没有偏好之前的自己"（那个旧模型，叫做 **reference model**）来比。

为什么要那个旧的自己？因为如果只推高好回答，模型会把所有概率都往"最短、最像复读"
的方向堆，最后把话说坏（我们试过：学习率大一点，好回答的概率会从 0.49 冲到 0，
两个回答一起完蛋）。拿"原来的自己"当尺子，推的是"哪一种更好"，不是"哪一种概率更大"。

另外注意：这一步用的数据是**比较**，不是标准答案。
如果我们能用标准答案训练，那就不需要偏好对齐了——
偏好对齐的存在，恰恰是因为"回答得好不好"这件事，很多时候**没有一个唯一正确的答案**，
只有"人更喜欢哪个"。这就是"预测什么"到"预测人想要什么"的那一步。

## Python 实现

`after.py` 里三个函数就是三个阶段。对照着看，差别一目了然。

**预训练**：

```python
def pretrain_step(model, optimizer, batch_size, rng):
    x, y = 随机剪一段语料            # （第 20 章那件事）
    logits = model(x)
    loss = F.cross_entropy(logits.reshape(-1, VOCAB_SIZE), y.reshape(-1))
    ...
```

**指令微调**（只多了两行）：

```python
def sft_step(model, optimizer, batch_size, rng, block_size=32):
    pairs = build_sft_pairs()
    chosen = 随机抽一批（问，答）
    inputs, targets, masks = pad_sequences(make_sequences(chosen, block_size), block_size)
    logits = model(inputs)
    per_token = F.cross_entropy(logits.reshape(-1, VOCAB_SIZE),
                               targets.reshape(-1), reduction="none")
    per_token = per_token.reshape(targets.shape)
    loss = (per_token * masks).sum() / masks.sum()      # <- 只有这一行不一样
```

`make_sequences` 负责生成那个掩码：

```python
mask = [1 if position >= len(prompt) - 1 else 0 for position in range(len(inputs))]
```

第 `p` 个位置预测的是第 `p+1` 个字，所以"答案的第一个字"对应的位置是
`len(prompt) - 1`。从那里往后都是要学的部分。

**偏好对齐**（公式长一点，但做的事很简单）：

```python
def sequence_logprob(model, prompt, answer, differentiable=False):
    """模型给这个回答打了多少分：每个字概率的对数，加起来。"""
    ids = encode(prompt + answer)
    logprobs = model(torch.tensor([ids]))[0].log_softmax(dim=-1)
    return sum(logprobs[position, ids[position + 1]]
               for position in range(len(prompt) - 1, len(ids) - 1))
```

```python
def dpo_step(policy, reference, optimizer, rng, beta=0.1):
    prompt, chosen, rejected = 随机抽一条偏好数据
    chosen_ratio = sequence_logprob(policy, prompt, chosen, differentiable=True) \
        - sequence_logprob(reference, prompt, chosen)
    rejected_ratio = sequence_logprob(policy, prompt, rejected, differentiable=True) \
        - sequence_logprob(reference, prompt, rejected)
    loss = -F.logsigmoid(beta * (chosen_ratio - rejected_ratio))
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

注意 `beta` 这个数（我们用的是 0.1）：它控制"推得有多狠"。
`beta` 越大，越执着于偏好数据；越小，越舍不得离开原来的自己。

还有一个工程细节值得看一眼：**偏好对齐的学习率要比前两个阶段小得多**
（我们用的是 `1e-4`，而预训练和微调都是 `3e-3`）。这一阶段的梯度很"尖"，
推猛一点模型就坏了。

## 它解决了什么

- 同一个模型，**答对率从 0/7 变成 5/7，再变成 7/7**，而模型一个零件都没改。
- **短答比例从 0% 变成 46%，再变成 100%**——偏好对齐真的改变了模型的习惯，
  而数据里没有一条规则说"要简洁"。
- 我们第一次看到：**训练目标可以从"预测下一个字"变成"预测人更喜欢哪个回答"**，
  而后者不是交叉熵。
- 也看到了代价：原始文本 loss 从 0.40 退到 2.35。对齐是有成本的。

现在把三个阶段的共同点说清楚：

> 三个阶段，模型都是"看到一段文本，给出下一个 token 的概率"。
> 变的只是**我们把什么样的文本摆到它面前**，以及**在哪几个位置上要它负责**。

这也解释了一件很多人困惑的事：为什么"提示词"（prompt）有用？
因为模型从头到尾学的就是"给定这样的文本，接下来该是什么"。
你给它的文本不一样，它给出的"接下来"就不一样。**提示词是在改它的输入，
不是在改它的知识。**

## 它还解决不了什么

从第 1 章到这一章，我们走了 29 章：

```text
if/else 规则  →  数字化的规则  →  让机器学习规则  →  学特征  →  学词表示
→  学上下文  →  学信息关系  →  深层组合  →  预测下一个 token  →  回答问题
```

最后这三步（分词、规模化、对齐）走完，我们手上这个东西，已经是 ChatGPT 的形状了。

但有一件事我们一直没做：**回头看看起点。**

第 2 章我们写过一个 if/else 分类器，它会用一堆规则给句子分类：

```python
if "手机" in words:
    return "科技"
```

那是全书的第一行代码。当时我们说它不行——几万个词难道写几万个 if？
于是我们一路把它换成了数字、权重、梯度、多层、注意力、语言模型。

现在，把它拿出来，和 29 章之后的这个模型，**放在同一个测试上比一比**：

- 同一批句子；
- 同一个判断（这句是科技还是食品）；
- 看两者各自怎么说。

不比参数量（一个 0 个参数，一个 10 万个），也不比速度。
比的就是：**30 章的差距，具体是多少。**

这就是最后一章要做的事。
