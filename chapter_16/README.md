# 第 16 章：模型不知道谁在前谁在后

## 本章的问题

上一章最后留下了一个问题：

> 从词向量到输出，哪一步用到了"这个词排第几"？一步都没有。

这一章我们把这个实验做一遍。用的还是三个词，只是换了个顺序：

```text
狗 咬 人
人 咬 狗
```

跑 `before.py`：

```text
  『狗 咬 人』
  --------------------------------------------------
    狗  看谁：人(0.357)、狗(0.329)、咬(0.315)
          输出 = [-0.167, -0.479, +0.242, -0.370, +0.690, +0.431, -0.133, +0.210]
    咬  看谁：人(0.389)、狗(0.348)、咬(0.264)
          输出 = [-0.176, -0.496, +0.257, -0.395, +0.741, +0.434, -0.128, +0.225]
    人  看谁：咬(0.342)、人(0.338)、狗(0.320)
          输出 = [-0.162, -0.471, +0.235, -0.357, +0.663, +0.429, -0.136, +0.201]

  『人 咬 狗』
  --------------------------------------------------
    人  看谁：咬(0.342)、人(0.338)、狗(0.320)
          输出 = [-0.162, -0.471, +0.235, -0.357, +0.663, +0.429, -0.136, +0.201]
    咬  看谁：人(0.389)、狗(0.348)、咬(0.264)
          输出 = [-0.176, -0.496, +0.257, -0.395, +0.741, +0.434, -0.128, +0.225]
    狗  看谁：人(0.357)、狗(0.329)、咬(0.315)
          输出 = [-0.167, -0.479, +0.242, -0.370, +0.690, +0.431, -0.133, +0.210]
```

两句话的输出**一个数都不差**，只是顺序倒了过来。`before.py` 把这件事核对了两遍：

```text
  人咬狗 的第 0 个词（人）的输出 = [-0.162, -0.471, +0.235, -0.357, +0.663, +0.429, -0.136, +0.201]
  狗咬人 的第 2 个词（人）的输出 = [-0.162, -0.471, +0.235, -0.357, +0.663, +0.429, -0.136, +0.201]

  '人'的输出一模一样吗：True
  '狗'的输出一模一样吗：True
```

再把每个位置的输出加起来，当作"整句话的表示"：

```text
  狗咬人 的句子向量 = [-0.504, -1.446, +0.734, -1.121, +2.095, +1.294, -0.397, +0.636]
  人咬狗 的句子向量 = [-0.504, -1.446, +0.734, -1.121, +2.095, +1.294, -0.397, +0.636]

  两句话的句子向量一样吗：True
```

一模一样。

这不是 bug，是这套机制的数学性质。第 14 章那个加权求和 `weights @ value`，
**求和是不管顺序的**；任意两个词的分数 `q · k` 也只跟这两个词是谁有关，
跟它们隔多远毫无关系。

所以在这套机制眼里，句子不是一个"序列"，而是一堆词。

**问题摆在这里：『狗咬人』和『人咬狗』是两件完全不同的事，模型却认为它们是同一件。**

## 最简单的尝试

要修的地方很清楚：**给每个位置也准备一个向量，加在词向量上。**

```python
x[i] = 词向量 + 位置向量[i]
```

第 i 个词现在拿到的不只是"我是什么词"，还有"我排第几"。

那位置向量长什么样？最笨也最直觉的做法：**第几个词，就写几。**

```python
位置 0 → [0, 0, 0, 0, 0, 0, 0, 0]
位置 1 → [1, 1, 1, 1, 1, 1, 1, 1]
位置 2 → [2, 2, 2, 2, 2, 2, 2, 2]
...
```

跑 `after.py` 的第一部分，马上就看见两个问题：

```text
        位置         编号向量的长度        词向量的长度
  ----------------------------------------
         0            0.00          1.02
         1            2.83          1.02
         2            5.66          1.02
         5           14.14          1.02
        10           28.28          1.02
        50           28.28          1.02

    （位置 50 的编号向量长度 = 50 × √8 ≈ 141.4）
```

**问题一：尺度失控。** 词向量的长度一直是 1.02，位置编号却能长到 141.42。
两者一相加，位置那一项把词义完全盖住了——第 50 个位置上的"狗"，
在模型眼里已经不太像"狗"了。

**问题二：没见过的东西没法外推。** 训练时最长见过 10 个词，
遇到第 50 个词，那个数字它从来没见过。这不是"学得不够"，是**这个方案里根本没有
第 50 个位置的参数**。（把编号换成"每个位置一个可以学习的小向量"也一样，
第 50 个位置的那几个参数从没被更新过。）

**问题三：它只有一个尺度。** 一个编号挤在一个数字里，"隔 1 个词"和"隔 8 个词"
这两种关系没法用不同的方式表达——它们只是 1 和 8 的差别。

## 实验

跑 `experiment.py`。第一件事就是回答开头那个问题：

```text
  【不加位置信息】
    『人』在两个句子里的输出一样吗：True
    两句话的句子向量距离：0.0000

  【加了位置编码】
    『人』在两个句子里的输出一样吗：False
    两句话的句子向量距离：0.9995
```

距离从 `0.0000` 变成 `0.9995`。同样的三个词，换个顺序，这次终于不一样了。

第二件事，看位置编码的性质：

```text
           位置对    距离       相似度   同一距离的其他位置对
  --------------------------------------------------------
         0 和 0     0     4.000   1和1(4.000)、2和2(4.000)
         0 和 1     1     3.535   1和2(3.535)、2和3(3.535)
         0 和 2     2     2.564   1和3(2.564)、2和4(2.564)
         0 和 3     3     1.965   1和4(1.965)、2和5(1.965)
         0 和 5     5     3.160   1和6(3.160)、2和7(3.160)
```

**距离一样，相似度就一样。** `0 和 1`、`1 和 2`、`2 和 3` 都是 `3.535`；
`0 和 2`、`1 和 3`、`2 和 4` 都是 `2.564`。

注意它并不是"越远越不像"——距离 5 的相似度（3.160）反而比距离 2（2.564）高一点，
因为不同频率的波会周期性重合。真正关键的是：**相似度只取决于隔多远，
不取决于在第几位**。这正是"相对位置"能被表达出来的原因。

第三件事，两种位置信息的尺度对比：

```text
      位置        编号向量长度        位置编码长度          编号向量还像狗吗          位置编码还像狗吗
  --------------------------------------------------------------------
       0          0.00          2.00             1.000             0.521
       1          2.83          2.00             0.649             0.764
       2          5.66          2.00             0.548             0.781
       5         14.14          2.00             0.473             0.135
      10         28.28          2.00             0.445             0.290
      50        141.42          2.00             0.422             0.380
```

编号向量的长度一路涨到 141.42；位置编码的长度永远是 2.00。

## 新机制

这个位置向量，我们叫它**位置编码（positional encoding）**。

做法：每个位置配一个固定向量，每一维都是一个**不同频率的波**：

```text
第 i 个位置、第 2k 维   = sin(i / 10000^(2k/dim))
第 i 个位置、第 2k+1 维 = cos(i / 10000^(2k/dim))
```

用 `dim = 8` 写出来（跑 `after.py` 打印的就是这张表）：

```text
  位置         第0维       第1维       第2维       第3维       第4维       第5维       第6维       第7维
     0       0.000     1.000     0.000     1.000     0.000     1.000     0.000     1.000
     1       0.841     0.540     0.100     0.995     0.010     1.000     0.001     1.000
     2       0.909    -0.416     0.199     0.980     0.020     1.000     0.002     1.000
     3       0.141    -0.990     0.296     0.955     0.030     1.000     0.003     1.000
     4      -0.757    -0.654     0.389     0.921     0.040     0.999     0.004     1.000
     5      -0.959     0.284     0.479     0.878     0.050     0.999     0.005     1.000
     6      -0.279     0.960     0.565     0.825     0.060     0.998     0.006     1.000
     7       0.657     0.754     0.644     0.765     0.070     0.998     0.007     1.000
     8       0.989    -0.146     0.717     0.697     0.080     0.997     0.008     1.000
     9       0.412    -0.911     0.783     0.622     0.090     0.996     0.009     1.000
    10      -0.544    -0.839     0.841     0.540     0.100     0.995     0.010     1.000
```

盯着这张表看一会儿，能看出三件事：

1. **左边的维度变得快，右边的维度变得慢。** 第 0、1 维（频率高）从上到下大幅摆动，
   第 6、7 维（频率低）几乎不动。
2. **每一维都在 -1 和 1 之间。** 所以位置向量永远不长——长度一直是 `2.000`，
   和词向量（1.020）在同一个量级，加在一起谁也不会盖住谁。
3. **每个位置长得都不一样。** 11 个位置就是 11 个不同的"指纹"。

为什么用一组不同频率的波？因为**位置关系不止一种尺度**。
"隔 1 个词"和"隔 8 个词"是两种不同的关系：前者多半是"挨着的词搭配"
（比如"发布"和"手机"），后者多半是"句子的两头"（比如主语和宾语）。
高频的波负责分辨近处，低频的波负责分辨远处——上面实验二那张表，
就是这件事的读数。

最后一步很简单：**把位置向量加在词向量上**。

```python
x[i] = 词向量 + 位置编码[i]
```

只加不改，词向量那 8 维还是那 8 维，位置信息是"叠"上去的。

## Python 实现

对应 `after.py`。位置编码本身只有几行：

```python
def sinusoidal_positions(length, dim):
    positions = np.arange(length)[:, None]
    dims = np.arange(dim)[None, :]
    angles = positions / np.power(10000.0, (2 * (dims // 2)) / dim)
    table = np.zeros((length, dim))
    table[:, 0::2] = np.sin(angles[:, 0::2])     # 偶数维用 sin
    table[:, 1::2] = np.cos(angles[:, 1::2])     # 奇数维用 cos
    return table
```

`np.arange(length)[:, None]` 把位置变成一列，`np.arange(dim)[None, :]` 把维度变成一行，
两者一除再取 `sin`/`cos`，就得到那张表。

注意力那一头，和上一章比只改了一行：

```python
def attention(words, position_table, seed=16):
    word_vectors = np.array([EMBEDDINGS[word] for word in words])
    vector = Tensor(word_vectors + position_table)      # <- 只多这一行
    query = vector @ w_q
    key = vector @ w_k
    value = vector @ w_v
    weights = ((query @ key.T) / np.sqrt(DIM)).softmax(axis=-1)
    return weights @ value, weights
```

跑 `after.py` 最后那一节，两句话的句子向量终于分开了：

```text

  狗咬人 的第 2 个词（人）的输出 = [-0.789, -1.760, +0.812, -1.942, +1.254, +1.282, -1.728, -0.755]
  狗咬人 的第 0 个词（狗）的输出 = [-0.773, -1.725, +0.801, -1.928, +1.254, +1.272, -1.713, -0.751]

  '人'在两个句子里的输出还一样吗：False

  狗咬人 的句子向量 = [-2.440, -5.418, +2.493, -5.906, +3.824, +3.862, -5.218, -2.260]
  人咬狗 的句子向量 = [-2.053, -4.775, +2.273, -5.464, +3.436, +4.027, -5.336, -2.294]
  两句话的句子向量一样吗：False
  它们之间的距离：0.9995
```

同一个"人"字，在『狗咬人』里和『人咬狗』里，输出不再是同一个向量了——
因为它旁边站着谁、自己排第几，都不一样了。

## 它解决了什么

1. **顺序进去了。** 同一批词换个顺序，句子向量的距离从 `0.0000` 变成 `0.9995`。
2. **尺度稳了。** 位置编码的长度永远是 `2.00`，不管第几位；编号向量在位置 50 时是 `141.42`。
3. **相对距离也进去了。** 距离相同的位置对，相似度完全相同（距离 1 的三对都是 `3.535`，
   距离 2 的三对都是 `2.564`）。

到这里，我们手里终于有了一块**完整的积木**：

```text
词向量 + 位置编码  →  多头注意力  →  输出
```

它知道每个词是什么、有哪些词、谁和谁关系近、谁在前谁在后。

## 它还解决不了什么

现在有一个很自然的想法：**这块积木这么好用，那就多叠几块。**

真实的大模型就是这么干的——不是一层，是几十层。第一层的输出，直接当第二层的输入，
第二层的输出再当第三层的输入……听上去应该越来越强。

但直接叠起来，会出事。而且这个"事"我们其实已经见过一次了。

回想第 14 章那张表：

```text
     d  |          不缩放：最大权重          梯度  |         除以√d：最大权重          梯度
  ----------------------------------------------------------------------
   512  |            0.9510      0.0701  |            0.3163      0.3537
```

分数一大，权重就被压成 `1` 和一堆 `0`，梯度只剩 `0.0701`——学不动了。

多层叠加会把这类问题放大：每一层都会重新算一遍 `softmax`，
重新做一遍加权求和，输出再喂给下一层。第一层的输出是什么尺度、
第二层的输入范围是不是还正常、梯度能不能从最后一层一路传回第一层——
这些都不是"多叠一层"自动就能满足的。

拿我们手上这段代码试一下就很清楚：现在的 `attention` 只有一层。
如果想叠第二层，第二层的输入就是第一层的输出。

**那么，把两层注意力直接首尾接起来，训练会发生什么？**

下一章我们就跑这个实验。
