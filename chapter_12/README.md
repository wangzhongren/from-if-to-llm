# 第 12 章：一个词不能只有一种意思

## 本章的问题

上一章最后留下了一个问题：**一个词只能有一种意思。**

具体是这样的。第 11 章训练完那张表之后，我们看了 苹果 的邻居：

```text
  苹果   → 香蕉 0.82  华为 0.61  好吃 0.61  小米 0.61  甜 0.56
```

香蕉、好吃、甜 是食品那边的；华为、小米 是科技那边的。它被两边同时拉扯。

看起来很合理。可我们的语料里有这两种句子：

```text
苹果 很 好吃          这里说的是水果
苹果 发布 新 手机      这里说的是公司
```

第 11 章的规则是"一个词一个向量"。那么这两句话里的 苹果，
拿到的是同一组数字 —— 不是"差不多"，是同一个东西。

`before.py` 把这件事摆到台面上：

```text
    句子 A：苹果 很 好吃          （水果）
    句子 B：苹果 发布 新 手机     （公司）

  A 句里 苹果 的向量：
    [+0.73  +0.71  +0.04  -0.36  -1.07  +0.23  -0.73  +0.67  -0.10  +0.05  -0.12  +0.17  +1.02  -0.16  -0.75  -0.04]
  B 句里 苹果 的向量：
    [+0.73  +0.71  +0.04  -0.36  -1.07  +0.23  -0.73  +0.67  -0.10  +0.05  -0.12  +0.17  +1.02  -0.16  -0.75  -0.04]

  两个向量的最大差值 = 0.0000000
  余弦相似度 = 1.0000
```

后果是很具体的。问"和 苹果 最像的词是谁"：

```text
  在 A 句里问：香蕉 +0.73  华为 +0.58  甜 +0.57  小米 +0.48  好吃 +0.48  派 +0.48
  在 B 句里问：香蕉 +0.73  华为 +0.58  甜 +0.57  小米 +0.48  好吃 +0.48  派 +0.48
```

两行一模一样。

再具体一点：假设下游要判断"这里的 苹果 是水果还是公司"。
模型能用的信息是 苹果 的向量，以及它和别的词的相似度：

```text
                     好吃    甜      香蕉    发布    手机    芯片
  A 句里的 苹果      +0.48   +0.57   +0.73   -0.05   -0.11   -0.18
  B 句里的 苹果      +0.48   +0.57   +0.73   -0.05   -0.11   -0.18
```

还是两行一模一样。

**问题不在于训练得不够久，也不在于维度不够高。
在于我们把一个词钉死在了一个位置上 —— 一个位置只能装一种意思。**

一个词在两句话里意思不同，那么它在这两句话里的**表示**就该不同。
这一章要造的就是这个"跟着句子变的表示"。

## 最简单的尝试

那怎么给"苹果"算一个跟着句子变的表示？

最笨的办法，也是最先想到的办法：**不用 苹果 自己的向量，改用 苹果 周围那几个词的向量。**

看：

```text
苹果 很 好吃          →  用 (很 + 好吃) / 2
苹果 发布 新 手机      →  用 (发布 + 新 + 手机) / 3
```

第一句话里，苹果 旁边站的是 很、好吃 —— 都是食品那边的词，
平均出来的向量自然就偏向食品那边。
第二句话里旁边站的是 发布、新、手机 —— 都是科技那边的词，
平均出来就偏向科技那边。

我们根本不需要教模型"苹果有两个意思"。**只要别看 苹果 自己，看它旁边站着谁。**

一个词所在位置周围那些词，我们给它起个名字，
以后就叫这个词的**上下文**（context）。

把上下文里所有词的向量平均起来得到的那个向量，
我们叫它这个位置的**上下文向量**（context vector）。

要注意这个方案有多笨：它完全不用 苹果 自己的向量。
哪怕把 苹果 换成一个从没见过的词，只要它周围是 很、好吃，
算出来的上下文向量照样偏向食品那边。

还有一个细节要说清楚：**平均**是这里唯一用到的运算。
它简单到有点可疑 —— 我们马上就会看到它可疑在哪里。

## 实验

`after.py` 里先把第 11 章那张表照原样训练出来（语料扩到了 25 句、
33 个词，因为要加上长句和它带来的新词）。然后做一件事：
给同一个 苹果 算两个不同的表示。

```text
  A 句里 苹果 的上下文向量 = (很 + 好吃) / 2
    [+0.36  -0.67  +0.24  +0.04  +0.31  +0.51  -0.31  -0.14  +0.03  +0.22  -0.21  +0.13  +0.62  -0.37  -0.54  -0.40]
  B 句里 苹果 的上下文向量 = (发布 + 新 + 手机) / 3
    [-0.68  -0.47  -0.79  -0.07  -0.12  +0.16  -0.17  +0.59  -0.27  -0.38  -0.02  -0.08  +0.21  -0.02  +0.58  +0.45]

  两个向量的余弦相似度 = -0.2387
  而两句话里的 苹果 自己的那个向量，余弦相似度 = 1.0000

  A 句里 苹果 最像       → 很 +0.74  好吃 +0.72  甜 +0.63  真 +0.59  这个 +0.45  香蕉 +0.35
  B 句里 苹果 最像       → 电脑 +0.65  新 +0.63  发布 +0.62  的 +0.61  芯片 +0.59  手机 +0.48
```

从 1.0000 变成了 -0.2387。**同一个词、同一个编号、同一个模型，
两个位置的表示现在是两个东西了。**

最像的词也跟着换了：A 句里是 很、好吃、甜，B 句里是 电脑、新、发布、芯片。

`experiment.py` 把这个差别放到一个真实的小任务上量了一遍。

任务是这样：给一个位置，判断它说的是水果还是公司。
做法是算它和一组食品词、一组科技词的平均相似度，谁高算谁。

先看用第 11 章的静态表示（也就是"一个词一个向量"）：

```text
  句子                                       食品分  科技分  判定     正确答案
  --------------------------------------------------------------------
  苹果 很 好吃                             +0.25  +0.06  水果  ✓      水果
  苹果 很 甜                               +0.25  +0.06  水果  ✓      水果
  苹果 发布 新 手机                        +0.25  +0.06  水果  ✗      公司
  苹果 发布 新 芯片                        +0.25  +0.06  水果  ✗      公司
  我 昨天 在 商场 看到 苹果 刚刚 发布 的 新 手机 +0.25  +0.06  水果  ✗      公司

  答对 2 / 5。
  注意「食品分」那一列：五个句子全都是 +0.25，一个字都没变。
  因为静态表示里，这五个「苹果」本来就是同一个向量。
  模型手上只有这一个答案，它只能五句话都答同一个。
```

5 句里蒙对 2 句。**而且注意"食品分"那一列 —— 五句话都是 +0.25，一位小数都没动。**
模型手上只有这一个数，它就只能五句话都答同一个答案。

再换成上下文向量，别的什么都没变：

```text
  句子                                       食品分  科技分  判定     正确答案
  --------------------------------------------------------------------
  苹果 很 好吃                             +0.44  -0.20  水果  ✓      水果
  苹果 很 甜                               +0.45  -0.21  水果  ✓      水果
  苹果 发布 新 手机                        -0.23  +0.50  公司  ✓      公司
  苹果 发布 新 芯片                        -0.17  +0.47  公司  ✓      公司
  我 昨天 在 商场 看到 苹果 刚刚 发布 的 新 手机 -0.39  +0.31  公司  ✓      公司

  答对 5 / 5。
```

把两种表示法并排看，这个"食品分 - 科技分"的差值：

```text
  句子                                     静态表示   上下文表示
  --------------------------------------------------------------
  苹果 很 好吃                             +0.188      +0.634
  苹果 很 甜                               +0.188      +0.666
  苹果 发布 新 手机                        +0.188      -0.729
  苹果 发布 新 芯片                        +0.188      -0.639
  我 昨天 在 商场 看到 苹果 刚刚 发布 的 新 手机 +0.188      -0.696

  静态表示那一列是个常数；上下文表示那一列跟着句子正负翻面。
```

同一张表、同一个任务，只把"苹果"的表示换了一下，从 2/5 变成 5/5。

## 新机制

这一章的新东西就一个：

> **一个位置的表示 = 它上下文里所有词的向量的平均。**

写成公式：

```text
context(i) = (1 / n) * Σ v_j        （j 取遍句子里除第 i 个词之外的所有词）
```

写成 Python：

```python
def context_vector(table_data, sentence, position):
    ids = [VOCAB.index(word) for word in sentence.split()]
    others = [ids[i] for i in range(len(ids)) if i != position]
    return table_data[others].mean(axis=0)
```

三行。这一章真正的新东西就这三行。

它和第 11 章的表示法是**两套东西**，别混起来：

| | 第 11 章的表示 | 第 12 章的表示 |
|---|---|---|
| 一个词有几个表示 | 一个 | 每个位置一个 |
| 表示从哪来 | 查表 | 查表 + 平均上下文 |
| 「苹果 很 好吃」里的 苹果 | `表[苹果]` | `(表[很] + 表[好吃]) / 2` |
| 「苹果 发布 新 手机」里的 苹果 | `表[苹果]` | `(表[发布] + 表[新] + 表[手机]) / 3` |
| 两句话里的 苹果 一样吗 | 一样 | 不一样 |

注意下半张表：**那三个式子里的 表 还是同一张表，一个字都没改。**
我们只是换了个用法 —— 从"查一个词"变成了"查它周围的词再平均"。

还有一点：句子越长，算出来的上下文向量越多地来自那些和当前词无关的词。
这一点马上就会变成问题。

## Python 实现

完整代码在 `after.py`。

**第一步还是训练那张表**，和第 11 章一模一样 —— 因为上下文向量是从表里查出来的，
表不好，平均出来的东西也不会好。

语料扩到了 25 句、33 个词：第 11 章那 13 句短句、第 13-16 章要用的那两句长句，
再加上几句支撑句（让长句里的新词也有足够多的地方出现）。
词表直接从语料里取：

```python
VOCAB = sorted({word for sentence in SENTENCES for word in sentence.split()})
```

```text
  句子 25 条，词 33 个，维度 16
  训练样本 200 条，训练 600 轮之后的 loss = 1.4998
```

**第二步就是上面那三行** `context_vector`。

**第三步，把它用在同一个词的不同位置上。** 关键是"位置"这两个字：

```python
vector_a = context_vector(table.data, FOOD_SENTENCE, 0)   # 苹果 很 好吃
vector_b = context_vector(table.data, TECH_SENTENCE, 0)   # 苹果 发布 新 手机
```

同一个词 苹果、同一个向量表，只因为位置所在的句子不同，
两次调用返回的是两个不同的向量。

## 它解决了什么

| | 第 11 章的表示 | 第 12 章的表示 |
|---|---|---|
| 两句话里的 苹果 余弦相似度 | 1.0000（同一个） | -0.2387 |
| 那个小任务的准确率 | 2 / 5 | 5 / 5 |
| 「和 苹果 最像的词」 | 两句话同一个答案 | 一句话一个答案 |
| 表示和它所在的句子有关系吗 | 没有 | 有 |

这一章真正拿到的是最后一行：**表示第一次和"它所在的句子"挂上了钩。**

这听起来平平无奇，但它解开了一个很硬的结：在这之前，
一个词有多少种意思，模型就只能装下一种。
现在每个**位置**都有了自己的表示 —— 一个词在多少个句子里出现，
就有多少个表示。

而且这个方案笨得出奇：三行代码，没有新参数，没有新训练。
它做的事只是"换个地方查表"。这带来一个额外的好处 ——
**它连没见过的词都能处理**：只要 苹果 周围站着 很、好吃，
这个位置的表示就会偏向食品那边，哪怕表里压根没有 苹果 这个词。

但"笨"是有代价的。代价在下面。

## 它还解决不了什么

回到本章的算法本身：**它把上下文里的词平均掉，也就是一视同仁。**

`after.py` 拿本章那句长句把这件事量了出来：

```text
  我 昨天 在 商场 看到 苹果 刚刚 发布 的 新 手机

  句中除 苹果 之外还有 10 个词：我 昨天 在 商场 看到 刚刚 发布 的 新 手机
  它们的权重是这样的：
    我 0.10  昨天 0.10  在 0.10  商场 0.10  看到 0.10  刚刚 0.10  发布 0.10  的 0.10  新 0.10  手机 0.10

  每个词的权重都一样。「昨天」和「发布」各占一份，一模一样。
```

请看那张权重表。**「我」0.10，「的」0.10，「发布」0.10，全都一样。**

平均法的算盘是：让每个词都出 1/10 的力，合起来就差不多对了。
可这里有个它自己解决不了的问题：

```text
  平均出来的向量，最像哪几个词？
    的 +0.48  电脑 +0.38  新 +0.38  芯片 +0.37  手机 +0.31  小米 +0.29  看到 +0.27  发布 +0.27

  排第一的是「的」。
```

我们把"苹果在这句话里是什么意思"这个问题，交给一堆向量的平均数 ——
结果这个平均数最像的词是**「的」**。

「的」在这句话里对 苹果 的意思有什么贡献？没有。
它凭什么占 1/10？凭它出现在这个句子里。就这样。

再换一个角度，把句中的词一个一个拿掉，看这个上下文向量变了多少：

```text
    拿掉的词    变化量
    ----------------------
    我          0.221
    昨天        0.290
    在          0.310
    商场        0.317
    看到        0.223
    刚刚        0.217
    发布        0.314
    的          0.237
    新          0.311
    手机        0.247
```

如果这个表示真的读懂了这句话，那么：

- 拿掉「我」和「的」，苹果 的意思应该**几乎不变**；
- 拿掉「发布」或者「手机」，苹果 的意思应该**明显变了**。

实际结果是 0.221 和 0.314 —— 差不多。十个数字全挤在 0.2 到 0.3 之间，
最大和最小差不到两倍。**平均法对哪个词都一样敏感，也就是说它分不出轻重。**

（顺带说，这也解释了为什么"到底该看全句还是看窗口"这个问题没法回答。
`after.py` 里换了个取法：不看全句，只看 苹果 左右各两个词。
结果 `商场 看到 刚刚 发布` 平均出来的向量，和全句平均出来的，
余弦相似度只有 +0.5148 —— 差了将近一半。到底哪个对？没有依据。
**换窗口只是换了个"一视同仁"的范围，没有解决"一视同仁"本身。**）

于是问题变得非常具体了：

> 在「我 昨天 在 商场 看到 苹果 刚刚 发布 的 新 手机」里，
> 「发布」和「昨天」对 苹果 这个词的意思，贡献显然不一样。
> 可平均法给它们各 0.10 份，一模一样。
>
> 那么，**这个权重该由谁来定？**
