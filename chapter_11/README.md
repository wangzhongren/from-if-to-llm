# 第 11 章：让相似的词靠近

## 本章的问题

上一章最后留下了一个问题：**这组数字怎么来？随机的吗？**

我们当时不是随便问问。第 10 章结尾的输出是这样的：

```text
和 手机   最像的 5 个词： 派 +0.28  这个 +0.15  电脑 +0.13  做成 +0.09  小米 +0.09
和 苹果   最像的 5 个词： 华为 +0.36  做成 +0.25  发布 +0.24  很 +0.21  小米 +0.19
```

和 手机 最像的词是 派。这不是"差一点意思"，这是胡话。

`before.py` 把这件事查得更细了一点。它拿第 10 章那张随机表，
做了三件事：

（第 10 章那张表每个词用 16 个数字，本章统一改成 8 个，
好和后面训练出来的表对齐。这不影响结论 —— 随机数字有多少个都一样没结构，
两种我们都试过。）

**第一，看看找出来的"相似词"是什么样子。**

```text
  和 手机   最像的 5 个词： 派 +0.72  华为 +0.71  这个 +0.57  真 +0.41  发布 +0.35
  和 苹果   最像的 5 个词： 芯片 +0.78  电脑 +0.62  很 +0.61  甜 +0.59  做成 +0.46
  和 好吃   最像的 5 个词： 电脑 +0.41  香蕉 +0.34  芯片 +0.25  苹果 +0.14  很 +0.05

  和 手机 最像的词是 派（+0.72）。手机 和 派 有什么关系？没有。
  和 苹果 最像的词是 芯片（+0.78），这个看着倒像那么回事 ——
  但那只是运气。随机数偶尔会撞出一个「看起来对」的答案，
  这正是它最会骗人的地方。下面换个种子就知道。
```

**第二，换几个种子，看答案稳不稳。**

```text
  种子  和「手机」最像的 3 个词
  --------------------------------------------
     0  派 +0.72  华为 +0.71  这个 +0.57
     1  电脑 +0.78  新 +0.29  好吃 +0.28
     2  发布 +0.67  华为 +0.43  甜 +0.39
     3  新 +0.57  这个 +0.56  芯片 +0.34
     4  华为 +0.44  香蕉 +0.27  派 +0.17

  每换一个种子，答案就换一批。
  如果这张表里真的装着「意义」，它不该对种子这么敏感。
```

**第三，直接检查这张表里有没有我们要的结构。**

我们要的结构很明确：科技词（发布 新 手机 芯片 电脑 华为 小米）
应该互相靠近，食品词（好吃 很 甜 香蕉 这个 真 做成 派）应该互相靠近，
而这两拨词之间应该离得远一点。

于是算一个数：**组内平均相似度 减去 组间平均相似度**。
有结构的话它应该是正的，而且不小。

```text
  种子    组内(科技)  组内(食品)  组间    组内均值 - 组间
  --------------------------------------------------------
     0    -0.058      -0.032      +0.062   -0.107
     1    -0.092      -0.067      +0.010   -0.089
     2    +0.056      -0.058      +0.059   -0.060

  上面是前三个种子。把 30 个种子都试一遍：
    平均 -0.030    最小 -0.118    最大 +0.071
  不管种子怎么换，这个差距都在 0 附近打转（而且还常常是负的）。
  也就是说：科技词之间并不比科技词和食品词之间更像。
```

负数。组内甚至比组间还低一点。

所以问题不是"这个种子不够好"。**问题是随机数之间本来就没有关系**，
我们没法靠换种子把它修好。要让这张表长出结构，
只有一条路：**把它当成参数，训练它。**

## 最简单的尝试

那用什么任务去训练？我们手里有的是什么？—— 13 句话。

没有任何人告诉我们"手机 和 芯片 是一类"，语料里也从来没有人这么说过。
但语料里有一个东西是现成的：**谁站在谁旁边。**

回看第 1 章那批句子：

```text
苹果 发布 新 手机
苹果 很 好吃
香蕉 很 好吃
```

把每句话相邻的两个词拿出来，就得到一堆小事实：

```text
苹果 旁边是 发布        苹果 旁边是 很
发布 旁边是 新          很 旁边是 好吃
新   旁边是 手机        好吃 旁边是 香蕉
```

"手机"这个词的意思，就藏在这些小事实里：
它旁边站的是 新，而 新 旁边站的是 发布。
把语料里所有相邻的词对都收集起来，我们就得到一批不用人标注的训练样本。

第一个想到的办法是**直接数**：造一张表，数一数每两个词一起出现了多少次。
比如 苹果-发布 出现 4 次，苹果-好吃 出现 2 次。
数完之后呢？这张表是一堆数字，它不会自己变成"谁该靠近谁"。
我们还得再想办法把这堆数变成向量 —— 那又是一层麻烦。

不如反过来。**不要数，直接造一个任务。**

```text
看到 苹果  →  猜 它旁边站的是谁（答案是 发布 或 很 …）
```

这个任务的好处是：它的形状我们在第 5 章就见过了。
给一堆选项打分、算 loss、反向传播、改参数 —— 全套工具第 9 章都已经有了。
而且这个任务**不需要任何人标注答案**，答案就写在语料里。

那就只剩下一个问题：**训练谁？**

## 新机制

这一章的新东西只有一句话：

> **把那张向量表本身当成参数，用「猜邻居」这个任务去训练它。**

具体模型是这样的。给定一条训练样本「看到 `c`，猜 `t`」：

```python
v = 表[c]                        # 查表，拿到 c 的向量，形状 (8,)
logits = v @ 输出层 + 输出层偏置   # 得到 16 个分数，每个词一个
loss = cross_entropy(logits, t)  # 第 5 章那个交叉熵
```

跑 `backward()` 的时候，梯度会一路传回**那张表**，把 `表[c]` 这一行改一点点。

和第 10 章对比一下就很清楚：

| | 第 10 章 | 第 11 章 |
|---|---|---|
| 那张表 | 随机撒的，只读 | 参数，被训练 |
| 谁在学 | 只有 `w` 和 `b`（17 个数） | 那张表自己（16 × 8 = 128 个数） |
| 任务 | 把词分成科技 / 食品 | 看一个词，猜它旁边的词 |

**为什么这样训练，相似的词就会靠近？**

看 手机 和 芯片。在我们的语料里，它们都出现在"新"后面：

```text
苹果 发布 新 手机
苹果 发布 新 芯片
```

于是训练样本里同时有这两条：

```text
看到 手机  →  猜 新
看到 芯片  →  猜 新
```

两条样本都要求"把这个词的向量送进输出层，让 新 的分数最高"。
最省事的满足方式是什么？**让 手机 和 芯片 的向量指得差不多。**
如果它们指向不同方向，输出层就得想办法把两个不同的方向都映射到 新 上，
那要多费力气。

模型不会"想"这些，它只是在往下压 loss。但 loss 往下压的结果，
就是让能出现在同一个位置上的词，越长越像。

我们从来没有告诉过它"手机和芯片是一类东西"。语料里也没有一句话这么说。
**这个"类"，是它自己从"谁能站在同一个位置"里推出来的。**

一个细节：第 10 章我们每个词用 16 个数字，这一章只用了 8 个。为什么？

因为这一章表里的数字要**被训练**，而我们只有 68 个训练样本、16 个词。
数字给多了，模型有足够的空间把 68 个样本原样背下来（背下来等于什么都没学），
结构反而长不出来。数字给少了，又装不下结构。

我们把这四个档都试了一遍（测的是"组内相似度 - 组间相似度"，
越大说明结构越清楚）：

| 每个词用几个数字 | 组内 - 组间 |
|---|---|
| 2 | -0.127（装不下） |
| 4 | +0.130 |
| 8 | +0.576（这一章用的） |
| 16 | +0.452（开始有余力死记硬背了） |

两头都不好，中间最好。**维数从来不是越大越好** ——
这一点在第 28 章讲规模的时候还会再遇到一次，只不过那一次的主角是别的数字。

## Python 实现

完整代码在 `after.py`，核心是三个函数。

**第一步，造训练样本。** 把每条句子扫一遍，每个位置都拿它左右各一个词做样本：

```python
def build_training_pairs(corpus, window=WINDOW):
    seen, guessed = [], []
    for sentence in corpus:
        for position in range(len(sentence)):
            left = max(0, position - window)
            right = min(len(sentence), position + window + 1)
            for neighbour in range(left, right):
                if neighbour == position:
                    continue
                seen.append(sentence[neighbour])
                guessed.append(sentence[position])
    return np.array(seen), np.array(guessed)
```

13 句话，窗口取 1，一共造出 68 条样本。

**第二步，训练。** 注意这里没有单独的 `w`，要学的就是那张表：

```python
table = randn(len(VOCAB), DIM, scale=0.1, requires_grad=True, seed=seed)
out_weight = randn(DIM, len(VOCAB), scale=0.1, requires_grad=True, seed=OUT_SEED)
out_bias = zeros(len(VOCAB), requires_grad=True)
optimizer = SGD([table, out_weight, out_bias], lr=0.3)

for epoch in range(400):
    optimizer.zero_grad()
    seen_vectors = embedding(table, seen)          # (68, 8)
    logits = seen_vectors @ out_weight + out_bias  # (68, 16)
    loss = cross_entropy(logits, guessed)
    loss.backward()
    optimizer.step()
```

`embedding(table, seen)` 就是第 9 章那个查表操作：
`seen` 是 68 个编号，查完变成 68 行向量。
反向传播时，梯度会按编号散回到表里对应的那些行上。

**第三步，看结果。** 把每一行向量变成单位长度，两两点积就是余弦相似度：

```python
def normalise(matrix):
    return matrix / np.linalg.norm(matrix, axis=1, keepdims=True)

def similarity_matrix(table_data):
    unit = normalise(table_data)
    return unit @ unit.T
```

然后再把每个词的邻居排个序印出来。这三步跑完，
就是上面"实验"那一节里的输出。

## 它解决了什么

第 10 章留下的问题，这一章答上了：**那组数字是被训练出来的，不是撒出来的。**

具体拿到了什么：

1. **相似的词真的靠近了。** 手机 和 芯片 的相似度是 0.99，好吃 和 甜 是 0.95。
   而在第 10 章的随机表里，手机 最像的词是 派。
2. **结构是量出来的，不是看出来的。** "组内平均相似度 - 组间平均相似度"
   从 -0.107（训练前）变成 +0.576（训练后）。同一个任务、同一批词、
   同一张表的形状，只把表里的数字训练了一遍。
3. **这件事不需要人标注。** 我们只给了 13 句话。模型没有收到任何一条
   "手机和芯片是一类"的知识 —— 它把每个词旁边站过谁数了一遍，
   就自己推出来了。
4. **"意义可以变成空间结构"这件事，第一次出现在我们手里。**
   词变成了空间里的点，词和词的关系变成了点之间的距离和方向。
   这一点比这一章的任何一个数字都重要 —— 后面所有的路都是从这里开始的。

回到第 1 章那句话：苹果 同时出现在科技句和食品句里。
这一章我们对它做了什么？什么都没做。
它在语料里两边都出现，所以它在空间里被两边同时拉扯，
最后停在了两堆中间。看它的邻居：

```text
  苹果   → 香蕉 0.82  华为 0.61  好吃 0.61  小米 0.61  甜 0.56
```

香蕉、好吃、甜 是食品那边的；华为、小米 是科技那边的。
它们全都算 苹果 的邻居。这个结果很合理 ——
但我们马上要问一个更麻烦的问题。

## 它还解决不了什么

请注意上面那行数字里的一件事：**苹果 只有一个向量。**

可我们的语料里有这两种句子：

```text
苹果 很 好吃          （这里说的是水果）
苹果 发布 新 手机      （这里说的是公司）
```

第一句里的 苹果 和 第二句里的 苹果，在模型眼里是**一模一样的**。
不是"差不多"，是一模一样：同一个编号、同一行、同一组 8 个数字，
余弦相似度是 1.0000。

你可以自己验一下：把这两句话里的 苹果 拿出来，
算一下它们的向量差多少。答案是：一个数字都不差。

所以模型根本没有办法表达"这两个 苹果 不是一回事"。
它甚至连"我现在说的 苹果 跟上一句那个 苹果 意思不同"都表示不出来。

我们来把它逼到墙角：

> 语料里「苹果 很 好吃」和「苹果 发布 新 手机」这两句里的 苹果，
> 明明是两回事。
> 可模型给它们的表示**完全相同** —— 将来无论下游要做什么，
> 只要这件事需要区分这两种 苹果，它都注定做不对。

我们需要的不是"再训练久一点"，也不是"把维度调一调"。
我们需要的是**让一个词的表示随着它所在的句子变一变**：

同一个 苹果，在"很 好吃"旁边是一个样子，在"发布 新 手机"旁边是另一个样子。

那我们手上已经有的原料是什么？是它周围那几个词的向量。
**这几个向量该怎么用，才能算出"这个位置的 苹果 是什么意思"？**
