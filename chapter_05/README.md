# 第 5 章：错误到底有多大

## 本章的问题

上一章最后留下了一个问题：

> 每次到底应该改多少？

要回答它，得先有一个东西：**说得出"错得有多离谱"的数。**

先看看我们手上有什么。`before.py` 把第 4 章的代码原样跑了一遍：

```text
  轮次   这把尺子的读数（答错了几句）
    1      1
    2      4
    3      2
    4      0
    5      0
    6      0
    ...
```

第 4 轮之后，读数一直是 0。程序认为"没有错了"，于是停手。

问题是：**这把尺子只有 11 个刻度（0 到 10），它到顶了。**

训练完的表长这样（还是 `before.py` 的输出）：

```text
  苹果发布新手机     科技   2.0 / 食品  -2.0   赢  4.0
  苹果发布新芯片     科技   3.0 / 食品  -3.0   赢  6.0
  苹果芯片很强       科技   1.0 / 食品  -1.0   赢  2.0
  ...
  这个苹果真甜       科技  -4.0 / 食品   4.0   赢  8.0
```

「苹果芯片很强」只赢了 2.0 分，「这个苹果真甜」赢了 8.0 分。

**一个是勉强答对，一个是稳稳答对。可第 4 章的尺子对它们的读数一模一样：都对。**

于是有三件事我们答不上来：

- 哪一句其实快输了？
- 这个表和另一个同样"0 错"的表，哪个更好？
- 训练还能不能继续变好？

所以要找的是这样一个数：

> **它要能说出"错得有多离谱"。**
> 答错了，它要能区分"差一点"和"差得离谱"；
> 答对了，它也要能区分"勉强对"和"非常确定"。

## 最简单的尝试

最直觉的做法是：**看差多少，差多少就记多少。**

我们手上本来就有两个分数。把它们相减，得到"这句话有多偏向科技"：

```text
分数差 = 科技分数 - 食品分数
```

正数偏向科技，负数偏向食品。（「苹果芯片很强」是 +2.0，「苹果很甜」是 -2.0。）

那"正确答案"就是一个目标值：科技是 +1，食品是 -1。预测离目标差多远，就错了多少：

```python
def signed_error(words, label, table):
    difference = 科技分数 - 食品分数
    target = 1.0 if label == "科技" else -1.0
    return (difference - target) ** 2
```

差多少，平方一下。这叫**平方误差**。

看起来很讲道理：差得越远，数越大，错得越狠。

`experiment.py` 的实验二把它拿去量了几句话，我们看看结果：

```text
  句子                    赢了几分      平方误差       交叉熵   说明
  苹果芯片很强           2.0      1.00     0.127   只赢一点点，最勉强
  苹果发布新手机         4.0      9.00     0.018   赢 4 分，还行
  苹果发布新芯片         6.0     25.00     0.002   赢 6 分，挺稳
  这个苹果真甜           8.0     49.00     0.000   赢 8 分，最有把握
```

看最上面和最下面两行：

- 「苹果芯片很强」**最勉强**（只赢 2 分），平方误差给它 **1.00**，说它最准；
- 「这个苹果真甜」**最有把握**（赢 8 分），平方误差给它 **49.00**，说它错得最狠。

**它把话说反了。**

原因在这一行：

```python
target = 1.0
```

平方误差想让"分数差"**正好等于 1**。于是越过 1 的部分全被它算成了"错误"——
越有把握，错得越多。

这就没道理了。我们想要的尺子是：**越有把握越好**，而不是"恰好 1.0 最好"。

## 新机制

这一章要造的东西，分三步。

### 第一步：把分数变成概率

分数可以是任何数：-21 也行，+12.5 也行。它甚至可以是 1000。
我们需要的是一个 0 到 1 之间、能读作"有多大的可能"的数。

先看最简单的情况：**只有一个类别**。我们要回答"是"还是"不是"，手上只有一个分数。

我们希望这个函数满足：

- 分数是 0 的时候，概率应该是 0.5（两个选项各占一半，等于不知道）；
- 分数越大越接近 1，越小越接近 0；
- 永远不会超出 0 到 1。

有一个函数正好长这样：

```text
概率 = 1 / (1 + e 的 (-分数) 次方)
```

（`e` 约等于 2.718，`e 的 x 次方` 在 Python 里写 `math.exp(x)`。）

代入几个数看看，就是实验三第一张表：分数 0 给 0.5，分数 1 给 0.7311，
分数 -2 给 0.1192，分数 4 给 0.9820。这个函数叫 **sigmoid**。

**两个类别（以后是更多类别）的时候**，我们希望两个概率互相"抢"，
而且加起来正好是 1。做法很自然：把每个分数换成 `e 的分数次方`，
再除以它们的总和。

```text
概率_1 = e 的 分数1 次方 / (e 的 分数1 次方 + e 的 分数2 次方)
概率_2 = e 的 分数2 次方 / (e 的 分数1 次方 + e 的 分数2 次方)
```

分数 [1.0, -1.0] 代进去，就是 `e^1 / (e^1 + e^-1)` 和 `e^-1 / (e^1 + e^-1)`，
也就是 0.8808 和 0.1192。

这个做法叫 **softmax**。

它和 sigmoid 其实是同一件事：分数是 `[d, 0]` 的时候，
softmax 算出来的第一个概率，正好就是 sigmoid(d)——实验三里验证过：

```text
    d = -2.0:  softmax 0.119203   那个式子 0.119203
    d =  0.0:  softmax 0.500000   那个式子 0.500000
    d =  1.0:  softmax 0.731059   那个式子 0.731059
```

### 第二步：从概率到"错误有多大"

现在每一句话都有了一个概率：**正确答案的概率**。

- 它等于 1：非常确定，一点没错；
- 它等于 0.5：完全在猜；
- 它接近 0：错得离谱。

我们要把这个概率变成一个"错误大小"。最直接的想法是 `1 - 概率`，
但那样"错得离谱"的代价太小了：概率 0.01 和概率 0.0001 的差别只有 0.0099，
而这两种情况显然差着量级。

我们用这个：

```text
损失 = -log(正确答案的概率)
```

`log` 是自然对数（Python 里写 `math.log`）。代入几个概率看看：

```text
  概率 1.0     ->  损失 0
  概率 0.99    ->  损失 0.0101
  概率 0.9     ->  损失 0.1054
  概率 0.5     ->  损失 0.6931
  概率 0.1     ->  损失 2.3026
  概率 0.01    ->  损失 4.6052
  概率 0.001   ->  损失 6.9078
```

三个性质正好是我们要的：

1. **答对了但不够肯定，损失不是 0。** 概率 0.9 还有 0.1054 的损失——
   还有进步空间，训练还知道往哪儿走。
2. **错得越离谱，涨得越快。** 概率从 0.5 掉到 0.1，损失从 0.69 涨到 2.30；
   再掉到 0.01，损失是 4.61。它不是线性增长，而是越接近"完全搞错"惩罚越重。
   （这个性质第 6 章还会用上：到时候我们要算"每个参数该往哪个方向改"，
   算出来的答案会取决于"这一句错得有多离谱"。）
3. **概率趋近 1 时损失趋近 0**，永远不会变成负数。

把这个损失对语料里每一句话算一遍、取平均，就得到了**一个数**。
这个数就是我们一直在找的尺子。

它的名字叫**损失**（loss），这种算法叫**交叉熵**（cross-entropy）。

### 第三步：为什么它比"数错句"强

因为它是连续的，而且没有上限。

"10 句里对了几句"只有 11 个取值。两张表都是 10/10 的时候，它就没话说了。
损失不同：它可以一直往下走，0.6931 -> 0.0210 -> 0.00000000001，
每一步的差别它都看得见。

这就是为什么它能回答"哪个表更好"，而正确率不能。

## Python 实现

完整代码在 `after.py`。核心是两个函数。

```python
def softmax(scores):
    biggest = max(scores)
    exponentials = [math.exp(value - biggest) for value in scores]
    total = sum(exponentials)
    return [value / total for value in exponentials]
```

`biggest` 那一行是做保护的：如果分数里有 1000，`math.exp(1000)` 会直接爆炸
（浮点数放不下）。先把所有分数减去最大值，`e` 的指数就都小于等于 0，
结果也不会变——因为分子分母同时乘了同一个数。

```python
def loss_of(words, label):
    correct_index = CATEGORIES.index(label)
    return -math.log(probability_of(words, correct_index))
```

一句话的损失，就是"正确答案的概率"取个负对数。

然后，我们用它做了一件第 4 章做不到的事：

```python
def try_adjust_one_parameter(corpus, word, category_index, amount, current_loss):
    original_value = WEIGHT_TABLE[word][category_index]
    best_value = original_value
    best_loss = current_loss
    for delta in (amount, -amount):
        WEIGHT_TABLE[word][category_index] = original_value + delta
        candidate_loss = average_loss(corpus)
        if candidate_loss < best_loss - 1e-12:
            best_loss = candidate_loss
            best_value = original_value + delta
    WEIGHT_TABLE[word][category_index] = best_value
    return best_loss


def adjust_weights_once(corpus, amount):
    loss = average_loss(corpus)
    for word in VOCABULARY:
        for category_index in (0, 1):
            loss = try_adjust_one_parameter(corpus, word, category_index, amount, loss)
    return loss, changed_count
```

这两个函数一点都不聪明，它们是纯粹的**试**：

- 挨个看每个参数，试着加一点，把整个语料重算一遍，看损失是升了还是降了；
- 再试着减一点，同样算一遍；
- 哪边低就用哪边，两边都高就退回去，原样不动。

它笨，但它**只需要一个东西就能工作：一把能判断"变好了还是变坏了"的尺子。**

第 4 章没有这把尺子，所以它做不到这件事。

跑起来是这样的：

```text
  轮次   损失        这一轮改了几个参数   正确率
    1    0.1329                    30   10/10
    2    0.0443                    30   10/10
    3    0.0144                    29   10/10
    4    0.0053                    28   10/10
    ...
   25    1.00e-11                   2   10/10
   26    1.00e-11                   0   10/10
```

## 它解决了什么

**第一，它给"错误"造出了一把连续的尺子。**

| | 第 4 章的尺子 | 这一章的尺子 |
|---|---|---|
| 长什么样 | 0 到 10 的整数 | 任何正数 |
| 起点（全 0 的表） | 5/10 | 0.6931 |
| 第 4 章训完的表 | 10/10 | 0.0210 |
| 这一章训完的表 | 10/10 | 1.00e-11 |
| 能区分后两张表吗 | 不能 | 能 |

**第二，"哪个表更好"这个问题第一次有了答案。**

第 4 章的最后，我们手上有三张都答对 10 句的表，谁也说不出哪张更好。
现在把它们放在一起量一下：0.0210 和 1.00e-11。这一章训出来的表，
把每一句话都推到了几乎确定的位置上。

**第三，第 4 章留下来的那个问题有答案了。**

每次改多少？实验五：改 0.05 要 229 轮，改 5.0 要 5 轮。

有意思的是，答案本身不重要——重要的是**这个问题现在问得出来了**。
第 4 章问不出来，因为那时候我们连"改得好不好"都测不出来。

## 它还解决不了什么

回头看 `adjust_weights_once` 那个函数。它是这么干活的：

```text
对每一个参数：
    加一点，把 10 句话全算一遍，看损失
    减一点，把 10 句话全算一遍，看损失
    选好的那个
```

数一数：我们的表有 32 个参数，每个参数要试 2 次，每次试都要把整个语料重算一遍。
**一轮就是 68 次完整计算。** 上面那次训练跑了 26 轮，一共一千七百多次。

32 个参数还行。一千多次计算也就是一眨眼的事。

但要是参数多起来呢？

- 我们的表：32 个参数 -> 一轮 68 次计算。
- 一个真实的模型（你用过的那种）：**几亿到几千亿个参数**。
- 按同样的做法，一轮要算几百亿次。而且这还是"一轮"。

更麻烦的是这个方法**很浪费**：试第 1 个参数的时候，
另外 31 个参数一动不动，干等着。它们之间明明是有关系的
（比如"苹果"和"芯片"要一起使劲才能把「苹果芯片很强」推过去），
可我们的做法永远是"一次只动一个"。

所以问题很具体：

> **参数很多以后，一个个试着改太慢了。**

我们需要一种办法，能**一次算出"每个参数该往哪个方向改、改多少"**，
而不是一个一个去试。

下一章我们就来造这个东西。
