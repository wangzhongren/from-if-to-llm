# 第 3 章：把 if 变成数字

## 本章的问题

上一章最后留下了一个问题：

> 几万个词，难道写几万个 if？

这不是夸张。第 2 章我们手工补了 8 条规则，覆盖 **16 个词**。按这个比例，
5 万个词的词表要写两万多条规则，而且实验二已经告诉我们：**这些规则的顺序一条都不能错。**

所以这一章要找的不是"更好的规则"，而是**一条不用手写规则的路**。

先看一眼第 2 章那些规则到底在做什么。把它们排在一起，会发现它们其实是同一个形状：

```python
if "手机" in words:
    return "科技"
if "芯片" in words:
    return "科技"
if "好吃" in words:
    return "食品"
```

每一条规则都在说同一件事：**句子里出现这个词，就把它算作某一类的证据。**
不同的规则之间，唯一的区别是"这个词算哪一类"。

那就别写 if 了。做一张表：

```text
手机 -> 科技
芯片 -> 科技
好吃 -> 食品
```

新句子来了，把里面的词逐个查表，看哪一类拿到的词多。

## 最简单的尝试

这张表也不用我们填。**让程序自己数**：每个词在语料里更常出现在哪一类，
就把它归到那一类。

```python
def build_word_to_category(corpus):
    technology_count, food_count = count_appearances(corpus)
    table = {}
    for word in VOCABULARY:
        if technology_count[word] > food_count[word]:
            table[word] = "科技"
        else:
            table[word] = "食品"
    return table
```

9/10。错的偏偏是第 2 章里我们特意留了兜底规则的那一句。

原因在票数上：

- "苹果"被归到食品（食品 4 句，科技 3 句）；
- "很"也被归到食品（食品 3 句，科技 1 句）；
- 只剩"芯片"给科技投了一票。

于是「苹果芯片很强」拿到 **科技 1 票、食品 2 票**，答成了食品。

问题不在"苹果"被归错了。问题在于：**每个词只能选一边，而"苹果"本来就是两边都有的。**

## 实验

跑 `experiment.py`。我们摆出三种"数票"的摆法。

```text
==================================================================
先找一找：哪些词在两个类别里都出现过？
==================================================================
  苹果、很
  这些词没法'归到某一边'，而每个词恰恰只能写一个类别。

==================================================================
三种摆法
==================================================================
  A. 按多数派自动归边      正确  9/10   错的是「苹果芯片很强」，答成了食品
  B. 把'苹果'改成科技      正确 10/10
  C. 两边都有的词弃权      正确 10/10

  摆法 A 和 B 的区别，只是'苹果'这个词放在哪一边。
  一个词的位置，决定了整体对错——而这个位置是我们随手定的。
  摆法 C 也全对了，但它是靠'把两个词从票箱里拿出来'做到的：
  它等于承认了这两个词没法归类，只好不让它们说话。

==================================================================
加权分数：一个词不需要选边
==================================================================
  加权分数               正确 10/10

  关键在系数表里的这一行：
    '苹果' -> 科技 +0.2   食品 +0.9
  它同时给两边分量，食品那边多一点，科技那边少一点。
  不用做「这个词归谁」的决定，也就没有摆法 A/B/C 的差别。
```

再看一件票数表达不了的事：

```text
  在数票法里，每个词的分量都是 1：
    '芯片' 1 票   '电脑' 1 票   '新' 1 票   '派' 1 票
  '苹果芯片很强'这句里，'芯片'顶了 1 票；
  可它明显比'新'这种词更能说明问题。票数说不出这件事。

  换成系数之后：
    芯片     科技 +1.5   食品 +0.0
    电脑     科技 +1.0   食品 +0.0
    新       科技 +0.5   食品 +0.0
    手机     科技 +1.2   食品 +0.0
  每个词的分量可以不一样，都是我们自己填的。
```

## 新机制

这一章的转变只有一句话：

> **不给词"归类别"，给词"记分量"。**

具体说，每个词后面跟两个数字：

```text
        这个词每出现一次，给"科技"加多少分，给"食品"加多少分
苹果  ->  (0.2, 0.9)
芯片  ->  (1.5, 0.0)
很    ->  (0.0, 0.3)
```

一句话的得分，就是把它的词挨个加起来：

```text
苹果发布新手机 = 苹果 + 发布 + 新 + 手机
科技分数 = 0.2 + 0.8 + 0.5 + 1.2 = 2.7
食品分数 = 0.9 + 0.0 + 0.0 + 0.0 = 0.9
```

两个分数一比，谁高算谁。这个数，我们叫它**分数**（score）。

每个词前面乘上去的那个数字，我们叫它**系数**。系数表的每一行都是一对系数，
一个字对应"科技"这边，一个字对应"食品"这边。

句子拆出来的这些词（以及它们的出现次数），就是这句话的**特征**。
以后我们会一直用这个词：**分数是特征和系数的乘积之和。**

它解决了两件事：

1. **"苹果"不用选边了。** 0.2 给科技，0.9 给食品，一个词同时是两边的证据。
   实验里摆法 A/B/C 的差别，在这里根本不存在。
2. **分量可以不一样。** "芯片"给 1.5，"新"给 0.5。票数做不到这件事——
   在数票法里，每个词的票都是 1。

## Python 实现

完整代码在 `after.py`，核心就两张东西：一张表、一个求和。

```python
COEFFICIENT_TABLE = {
    "苹果": (0.2, 0.9),     # 两边都喂一点，但食品那边多一点
    "发布": (0.8, 0.0),
    "新":   (0.5, 0.0),
    "手机": (1.2, 0.0),
    # ...
}
```

```python
def score(words):
    technology_score = 0.0
    food_score = 0.0
    for word in words:
        if word not in COEFFICIENT_TABLE:
            continue
        technology_coefficient, food_coefficient = COEFFICIENT_TABLE[word]
        technology_score += technology_coefficient
        food_score += food_coefficient
    return technology_score, food_score
```

三个注意点：

- `COEFFICIENT_TABLE` 里没有的词（比如 `<UNK>`）直接跳过。它在表里没有位置，
  也就投不了票——这一点和上一章的"规则看不见词表外的词"是一样的。
- 每出现一次就加一次。所以"苹果"如果在一句话里出现两次，两个系数都要加两次。
- `judge` 里的比较用的是 `>=`：分数一样高的时候先算"科技"。
  打平这件事本身就不正常（说明这句话没有任何倾向），先随便定一个，
  第 5 章我们会回过头来算它到底有多不靠谱。

## 它解决了什么

| | 数票法（`before.py`） | 加权分数（`after.py`） |
|---|---|---|
| 正确率 | 9/10 | 10/10 |
| 每个词的作用 | 1 票 | 两个系数，可以不同大小 |
| "苹果"怎么办 | 必须选一边 | 两边都给分量 |

10 句全对，而且过程看得见：

```text
  [对] 苹果发布新手机     科技  2.7 / 食品  0.9   答：科技   真实：科技
  [对] 苹果芯片很强       科技  1.7 / 食品  1.2   答：科技   真实：科技
```

比"对/错"多出来的东西是**差多少**：

- 「苹果发布新手机」赢 1.8 分，很稳；
- 「苹果芯片很强」只赢 0.5 分，勉强。

数票法也有票数，但它只有整数票，而且"1 票"和"1 票"之间没有区别。
分数是连续的数，可以很大，也可以只赢一点点。

**但有个地方必须说清楚：这张表里的 32 个数字，是我们一个个手填的。**

不是程序算出来的，不是数据里长出来的——是我们看着这 10 句话，一边试一边填的。
填的时候我们心里想的是"芯片看起来挺重要，给 1.5 吧"。这就是这一章真正的代价。

## 它还解决不了什么

回到 `COEFFICIENT_TABLE`，数一数：

```text
16 个词 × 每个词 2 个系数 = 32 个数字
```

32 个数字，我们填了多久？而且这只是 16 个词的玩具词表。

- 词表 5 万个词，就是 **10 万个数字**。谁填？
- 就算有人肯填，他凭什么知道"芯片"该是 1.5 而不是 1.4？
- 更麻烦的是：**我们是怎么知道这些数字"填对了"的？**
  我们反复跑这 10 句话，看到全对就停了。也就是说，
  这些数字是**照着答案调出来的**——换一批句子，全部作废。

实验里那个"苹果 -> (0.2, 0.9)"尤其说明问题。为什么不填 (0.5, 0.5)？
为什么不填 (0.1, 0.8)？我们其实不知道。我们只是试了几个，看哪个能全对。

所以问题很具体：

> **这些 1.2、0.8、1.5 谁来决定？**

我们不想再当那个填数字的人了。下一章我们试试：
**让程序自己修改这些数字。**
