# 第 14 章：我找什么、你有什么

## 本章的问题

上一章最后留下了这么一句话：

> 它只知道"像不像"，不知道"我在找什么"。

先把这个问题的现场摆出来。跑 `before.py`：

```text
实验一：分数矩阵是对称的吗？
------------------------------------------------------------
  整个矩阵 S 和它的转置相等：True
  苹果 -> 手机     1.600
  手机 -> 苹果     1.600

  两个方向是同一个数。'苹果有多想问手机'和'手机有多想问苹果'，
  在第 13 章里根本无法区分——因为只有一把尺子。
```

"我想问你什么"和"你想问我什么"，在上一章里是**同一个数**。这不是巧合——
分数就是 `v_i · v_j`，点积是对称的。

第二个毛病更麻烦。假设"苹果"想换一个关注点：

```text
  现在'苹果'问谁，是被它自己的向量锁死的：
  苹果 = [0.  0.  0.  0.  0.7 1.  0.  0. ]
  于是它最想问的是'手机'（1.600）和'发布'（1.210）。

  我们试着改一改它：把'科技与商业'这一维从 1.0 改成 0.0。
  苹果' = [0.  0.  0.  0.  0.7 0.  0.  0. ]

  分数                   改之前       改之后
  ----------------------------------------
  苹果 -> 手机         1.600     0.700
  苹果 -> 发布         1.210     0.210
  苹果 -> 苹果         1.490     0.490
  手机 -> 苹果         1.600     0.700

  最后一行是重点：手机一个字都没改，可是'手机怎么看苹果'变了。
```

我们只是想让"苹果"少看点手机，结果"手机怎么看苹果"也跟着变了。
因为"苹果"只有一个向量，它同时要干两件事：

- **我去问别人的时候**，用的是它
- **别人来问我的时候**，用的还是它

一个向量，两个角色。这就是为什么"我在找什么"没法单独表达。

**问题摆在这里：一个词应该有三个身份——"我在找什么"、"我有什么"、"我能给你什么"。**
现在只有一个。

## 最简单的尝试

先把这三个身份想清楚。拿"苹果"为例：

| 角色 | 说的是什么 | 谁来用 |
|---|---|---|
| 我在找什么 | 我现在想问的是"谁跟我一样是科技公司" | 只有"苹果"自己有 |
| 我有什么 | "苹果"身上贴着"科技""物品"这些标签 | 别人来问的时候看这个 |
| 我能给你什么 | 如果别人来看"苹果"，它实际贡献出去的向量 | 被看到的时候用这个 |

第 13 章把前两个角色塞进了同一个向量里，所以才会出现刚才那种"一动全动"。

最直觉的修法：**给每个角色配一个自己的矩阵，三个角色用三次不同的投影。**

投影这件事我们第 3 章就干过了——`x @ W`，把一组数变成另一组数。
那时候 `W` 是我们手写的权重，现在我们让它变成要被学出来的参数：

```python
query = x @ W_q     # 我在找什么
key   = x @ W_k     # 我有什么
value = x @ W_v     # 我能给你什么
```

为什么这样就分开了？因为 `W_q` 和 `W_k` 是两个**各自独立的矩阵**。
"苹果"的 query 是什么样，和它的 key 是什么样，从此不再绑在一起。
前一节那个"手机一个字没改，分数却变了"的毛病，也就没有了。

分数怎么算？第 13 章是 `v_i · v_j`，现在两个角色不一样了，那就用
**"我的问题"和"你的标签"有多合**来算：

```python
score[i][j] = query[i] · key[j]
```

最后，加权求和的**对象**也要换一下。第 13 章混的是词向量本身，现在混的是 value：

```python
output[i] = sum_j weights[i][j] * value[j]
```

权重决定"看谁"，value 决定"看到什么"。这两件事本来就该分开：
一个词可以很值得看，但它能给你的东西未必就是它自己的那个向量。

## 实验

先别急着写代码。上面那个 `score[i][j] = query[i] · key[j]` 埋了一个坑，
跑一下 `experiment.py` 就知道了。

Q 和 K 都是 8 维、16 维、几十维的向量。两个向量逐维相乘再相加，
维度越高，加起来的东西越多，分数自然越大。我们在真实数据上量了一下
（`苹果`那一行，每档随机初始化 20 次取平均）：

```text

  ----------------------------------------------------------------------
     8  |     2.57      0.91  |    0.540     0.271  |     3.88      8.05

    32  |     5.54      0.98  |    0.780     0.317  |     1.92      7.35
```

（"有效词数"是"注意力平均摊在几个词上"：11 个词都一样重要就是 11，只盯着一个词就是 1。）

不缩放的话，维度一高，分数就大得离谱。分数一大，`softmax` 会变成什么样？

```text

    看到  0.00000000
    新    0.00000000
    ...

    看到  0.22377703
    新    0.05033896
    刚刚  0.02469449
    手机  0.02412959

    商场  0.00171199
    的    0.00106865
    在    0.00073927
    我    0.00046779
    最大权重 = 0.63569118   有效词数 = 3.10   梯度 = 0.3639007455
```

不缩放的那一行，权重被压成了"1 和十个 0"。这不是"注意力很集中"，
这是**退化了**：softmax 变成一个只会挑最大的操作，剩下的词一律归零。

更坏的是最后那个"梯度"：

```text
     d  |          不缩放：最大权重          梯度  |         除以√d：最大权重          梯度
  ----------------------------------------------------------------------
     8  |            0.5404      0.3489  |            0.2706      0.3338
    32  |            0.7801      0.2102  |            0.3168      0.3399
   128  |            0.8833      0.1341  |            0.2996      0.3391
   512  |            0.9510      0.0701  |            0.3163      0.3537
```

"梯度"这一栏说的是"分数变一点，权重跟着变多少"——它就是反向传播要用的那个数。
被压成 1 和 0 之后，这个数变成了 0.0000000001，约等于没有。
**权重不再对分数有反应，那些被压成 0 的词就永远翻不了身。**

这个坑的解法简单得有点好笑：**把分数除以 √d。**

d 是 512 就除以 22.6，d 是 8 就除以 2.83。看上面两张表：除以 √d 之后，
无论维度多高，分数标准差都稳在 1 附近，有效词数都稳在 7 上下，梯度也一直有。

为什么偏偏是 √d 而不是 d 或者 1？因为随机初始化时，`query · key` 是 d 个
随机数相加：**加起来的东西越多，和就越容易跑偏，标准差正比于 √d**。
除回去，尺度就回到 1。这是一个能把尺度"钉住"的除数，不是拍脑袋来的。

## 新机制

把前面所有东西拼起来，就是这一章的新机制：

```python
query = x @ W_q        # 我在找什么
key   = x @ W_k        # 我有什么
value = x @ W_v        # 我能给你什么

scores  = query @ key.T / sqrt(d)     # 我的问题和你身上的标签有多合
weights = softmax(scores, axis=-1)    # 归一化成权重
output  = weights @ value             # 按权重把 value 混起来
```

写成一行就是：

```text
Attention(Q, K, V) = softmax(Q Kᵀ / √d) V
```

三个角色的名字，从今天起我们就这么叫：

- **Query（查询）**：我在找什么
- **Key（键）**：我有什么
- **Value（值）**：我真正能提供出去的信息

注意 Q、K、V 是**同一批词向量投三次影**得到的，所以这套做法叫
**self-attention（自注意力）**——一句话自己看自己。

还有一个细节：权重矩阵的行还是"谁在看"，但列变成了"看谁身上的标签"，
而最后被混合的是 value。所以 `weights` 和 `output` 的关系，
不再是"把原向量揉一揉"，而是"**按需取货**"。

## Python 实现

对应 `after.py`。实现和公式一一对应：

```python
def project(vectors, weight):
    """把每个词向量投影到另一个空间：x @ W。"""
    return vectors @ weight


def split_into_qkv(vectors, w_q, w_k, w_v):
    """同样一批词向量，投三次影，得到三个角色。"""
    query = project(vectors, w_q)
    key = project(vectors, w_k)
    value = project(vectors, w_v)
    return query, key, value


def attention_scores(query, key):
    """分数 = Q Kᵀ / √d_key。"""
    return (query @ key.T) / np.sqrt(key.shape[-1])


def attention(query, key, value):
    """单头 self-attention 的完整流程。"""
    weights = attention_weights(attention_scores(query, key))
    return weights @ value, weights
```

## 它解决了什么

三件事，都有上面的数字撑着：

1. **"我问你"和"你问我"分开了。** 第 13 章两个方向共用 `1.600` 这一个数；
   这一章是 `-0.798` 和 `-0.897`，两个独立的数。改自己的 query，不再影响
   别人眼里的 key。
2. **同一个词可以问不同的问题。** 问"科技与商业"，`苹果` 关注 `发布`(0.261)；
   问"物品"，它关注 `手机`(0.348)。这是"我在找什么"第一次能被单独表达出来。
3. **尺度稳了。** 除以 √d 之后，维度从 8 涨到 512，分数标准差一直在 1 附近
   （0.91~1.18），有效词数一直在 7 附近（6.98~8.05）。不缩放的话，
   d=512 时权重被压成 `1.00000000` 和十个 `0.00000000`，梯度只剩 `0.0000000001`。

## 它还解决不了什么

看 `after.py` 打印的"苹果"那一行：

```text
  在    0.2621  ############################
  商场  0.2483  ###########################
  看到  0.1683  ##################
  的    0.1557  #################
```

（这些数字现在是随机的，因为投影还没训练。但它们暴露的结构是真的。）

**每个词只有一行权重。** 一行就是一组数，加起来等于 1。
这意味着注意力是一笔**固定预算**：给这个多分一点，就必须从别人那里扣。

现在换一句话来看这件事：

```text
小王 把 书 给了 小李 因为 他 明天 考试
```

"他"这个字身上，同时挂着好几件事：

- **指代**：他 = 小王还是小李？——得看 `小王`、`小李`
- **时间**：他明天要干嘛？——得看 `明天`、`考试`
- **因果**：为什么说这句话？——得看 `因为`

"他"只有一行权重，加起来等于 1。如果它把 0.5 分给了 `小王`（指代），
那就只剩 0.5 分给 `明天` 和 `考试`（时间）——**这两件事在抢同一笔预算**。

这不是"训练得不够好"能解决的问题。就算训练到完美，一行权重也只能表达
一种偏好：要么更偏向指代，要么更偏向时间，或者两边各让一步、都不专注。

**那么，如果一句话里同时有好几种关系需要看，一个词只有一行权重——怎么办？**

## 练习

见 `exercises.md`，这里列最关键的几条：

1. **三个矩阵换成同一个会怎样**——把 `W_q`、`W_k`、`W_v` 都设成单位矩阵，
   跑一遍，看它是不是又退化成第 13 章了。
2. **把 √d 去掉**——让 `attention_scores` 直接返回 `query @ key.T`，
   把 `d` 从 8 改到 64，看权重矩阵变成什么样。
3. **只缩放不换 V**——把 `weights @ value` 改回 `weights @ vectors`，
   看输出有什么不同。
4. **自己造一个问法**——把 `W_q` 手工设成"只问时间"（第 1 维），
   看 `苹果` 会去问谁。它问得到东西吗？为什么？
5. **让两个角色的长度不一样**——把 `QUESTION_STRENGTH` 从 4.0 调到 0.1，
   再调到 20，看权重是变平了还是变尖了。
