## 1. 温度的两个极端

`generate` 里有一个参数叫 `temperature`。试试这两个值：

```python
generate(model, tokenizer, "床前", 20, temperature=0.01, seed=0)
generate(model, tokenizer, "床前", 20, temperature=100, seed=0)
```

- 第一个和贪心的输出一样吗？为什么？
- 第二个的输出是什么样子？还像中文吗？
- 再试试 `temperature=0.0`。`pick_next_token` 会直接抛一个 `ValueError`。想清楚：它为什么不干脆帮读者把 0 换成"贪心"？（提示：温度等于 0 的时候，`p ** (1 / 0)` 是多少？）

## 2. 用温度来实现贪心，行不行

`after.py` 里贪心是用 `top_k=1` 实现的。如果换成 `temperature=0.0001`（不设 `top_k`）：

- 输出和 `top_k=1` 一样吗？
- 为什么能"差不多一样"？
- 算一下：如果最大概率是 0.9998，第二名是 0.000119，温度 0.0001 之后两者的比值是多少？（提示：`(0.9998 / 0.000119) ** 10000`。）
- 那么这两种实现方式哪个更"稳"？为什么 `pick_next_token` 里 `top_k=1` 那一支更可靠？

## 3. 找那个"还能看"和"不能看"的分界点

`experiment.py` 的温度表最高只到 8.0。把它加到 12、16、20：

```python
for temperature in (0.2, 0.5, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0, 8.0, 12.0, 16.0, 20.0):
```

重跑，看"最长复读"那一列。

- 它一路掉到多少？掉到 1 的时候是什么意思？
- 从第几个温度开始，写出来的东西你就读不出"中文的感觉"了？
- 如果把"最长复读"当成"它在背书"的指标，这个指标有没有毛病？
  （提示：想想"最长复读 = 1"意味着什么——那几乎是随机的 33 个字符。）

## 4. top-k 和温度一起拧

在 `experiment.py` 的温度表里，给每一行都加上 `top_k=3`：

```python
texts = [generate(model, tokenizer, PROMPT, LENGTH,
                  temperature=temperature, top_k=3, seed=seed)
         for seed in range(6)]
```

重跑。

- 温度拧到 8 的时候，"6 次里有几种"和"最长复读"分别是多少？
- 和上面那个不设 top-k 的温度 8 比，哪个更像中文？哪个更有变化？
- 为什么加了 top-k 之后，温度拧高也不会写出太怪的东西？
- 想一想：真实产品里为什么同时提供这两个旋钮，而不是只留一个？
