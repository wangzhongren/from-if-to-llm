# 第 23 章：模型为什么会"生成"

## 本章的问题

上一章结尾的时候，我们让模型写出了诗：

```text
  床前明月光疑是地上霜举头望明月低头思故乡
  鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前
  明月光疑是地上霜举头望明月低头思故乡鹅鹅
```

但那段诗是我们用一个人肉循环接出来的。而且那个循环里藏着一件事，我们一直没提：

**每一步，我们都把概率最大的那个字符拿走，把剩下 32 个概率全扔了。**

先跑 `before.py`，看看一直扔着它们会怎样。

毛病一：同一个开头，跑多少次都一样。

```text
  开头：举头望明月低头
    第 1 次：举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清
    第 2 次：举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清
    第 3 次：举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清
```

三次完全一样。不是巧合——`before.py` 里那个 `greedy_continue` 一个随机数都没有。给定同一个开头，它是**算出来的**。

毛病二：开头一离开语料，很快就崩。

```text
    故乡故乡故乡故乡...
      -> 故乡故乡故乡故乡故乡故乡故乡故乡鹅鹅鹅曲疑项鹅拨低鹅绿鹅歌曲歌水绿浮明光清拨床乡乡毛

    月月月月月月月月...
      -> 月月月月月月月月月月月月月月月月光光项地是是头天上霜床前是头举清乡地向地上举月歌疑乡
```

前面几个字还算正常，越走越散。贪心每一步只看"现在最像什么"，错一步也回不了头。它没有"退一步再看"这种选项。

毛病三：它写出来的永远是那 38 个字的循环。

```text
    床前明月光疑是地上霜举头望明月低头思故乡
    鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前
    明月光疑是地上霜举头望明月低头思故乡鹅鹅
    鹅曲项向天歌白毛浮绿水红掌拨清波床前明月
    光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲
    项向天歌白毛浮绿水红掌拨清波床前明月光疑
```

这一条不能全怪贪心——语料总共只有 38 个字。但前两条是它自己的毛病。

**模型在每个位置给出的是 33 个概率，不是 1 个字符。** 我们刚才做的事情是：把最大的那个拿走，剩下的 32 个全扔了。

被扔掉的 32 个里面，装着什么？

## 最简单的尝试

先给那个循环起个名字。

我们一直在做的事是这样的：

1. 把已经写好的字喂给模型
2. 拿到下一个字的概率分布
3. 挑一个，接到后面去
4. 回到第 1 步

"把输出接回输入、再预测下一个"这个动作，叫**自回归**（autoregressive）。第 22 章我们一直在用它，只是当时还没给它起名字。

而第 3 步——"挑一个"——就是这一章的正题。

最直觉的做法是**贪心**（greedy）：每次挑最大的。它是第 22 章那个版本。`before.py` 已经证明它不够用了。

那么剩下的选择是：**在那 33 个概率上抽一次。**

## 实验

抽之前，先装两个旋钮。

**旋钮一：temperature（温度）。**

```python
adjusted = probabilities ** (1.0 / temperature)
adjusted = adjusted / adjusted.sum()
```

温度做的事就是**重新分配概率**：

- 温度 = 1，什么都不改
- 温度 < 1，大的更大、小的更小（模型变保守）
- 温度 > 1，大家被拉平（模型变冒险）

同一个开头，只改温度：

```text
    开头：举头望明月低头思

    温度  0.2  -> 故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月光疑
    温度  0.5  -> 故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月光疑
    温度  1.0  -> 故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月光疑
    温度  2.0  -> 故头思故乡鹅乡鹅曲项向天歌白毛浮绿水红项向天项向天红
    温度  3.0  -> 故望明月低头乡鹅鹅鹅歌天歌毛毛毛鹅拨清鹅拨向拨思头是
    温度  4.0  -> 故望明月低头上霜霜故故乡望明月头霜故故鹅举向天低向是
    温度  6.0  -> 故浮望明月月乡鹅鹅明故低头故前明鹅曲项白向向故乡举头
```

等一下。前三个温度（0.2、0.5、1.0）写出来的东西**一模一样**。

温度 0.2 和温度 1.0 之间差了五倍，怎么可能没区别？

`experiment.py` 把这件事量了出来：

```text
     温度       有效候选数       6 次里有几种      最长复读
  --------------------------------------------
    0.2        1.00             1        32
    0.5        1.00             1        32
    1.0        1.00             2        32
    1.5        1.02             3        32
    2.0        1.11             6        32
    3.0        1.62             6        24
    4.0        2.77             6        12
    6.0        6.98             6        11
    8.0       12.09             6         9
```

"有效候选数"是把温度作用到概率上之后，`exp(熵)` 是多少。1 表示它实际上只认真考虑一个候选，33 表示它在 33 个候选之间完全瞎猜。

这个开头，模型给的最大概率是 **0.9999**，第二大的是 **0.000086**。

所以温度 0.5 之后的分布是 `0.9999² : 0.000086²`，也就是 `0.9998 : 0.0000000074`。第二名还是抽不到。

要让它抽到，温度得拧到 2 以上。而那时候写出来的东西已经不太像话了（最长复读掉到 12）。

**这不是温度这个旋钮坏了，是模型太自信了。** 它给出的分布太尖，尖到温度拧不动。而它为什么这么自信——因为语料只有 304 个字符，它几乎把语料背下来了。这件事第 24 章会专门回来看。

**旋钮二：top-k。**

它做的事和温度不一样：

```python
keep = np.argsort(-adjusted)[:top_k]     # 只留最大的 k 个
```

固定温度 4.0，只改 k：

```text
    top-k  1  -> 故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月光疑
    top-k  2  -> 故乡波前波是明月歌明月低歌上鹅曲白红
    top-k  3  -> 故乡思头望明月低故故故乡鹅曲项向清故
    top-k  5  -> 故乡头前明鹅地是明月是地歌头故乡鹅曲
    top-k 10  -> 故乡前举鹅鹅歌浮是曲项向明上鹅拨清明
```

`k=1` 就是贪心。

两个旋钮管的不是同一件事：

- **温度管"敢不敢冒险"**。它把 33 个候选全部留着，只是重新分配概率。温度拧大之后，那些本来几乎不可能的字也会被抽中，有时候会抽到特别离谱的。
- **top-k 管"最多在几个候选里挑"**。它先把尾巴砍掉，剩下的还是按原本的比例分。所以它既给了多样性，又不会写出太怪的东西。

## 新机制

这一章有两个新东西，一个是动作，两个是旋钮。

**动作：自回归。**

```python
ids = list(tokenizer.encode(prompt))
for _ in range(length):
    window = np.array(ids[-CONTEXT:])[None, :]
    logits = model(window).data[0, -1]
    ids.append(pick_next_token(...))          # 挑一个，接到后面
return tokenizer.decode(ids)
```

四行。整个"生成"就是这四行。

它为什么能工作？因为模型被训练成"给定前文，输出下一个 token 的分布"（第 20 章）。所以只要你给它一段前文，它就能给你下一格。你把下一格接上去，前文就变长了，它又能给你再下一格。

**"生成"不是模型的一个能力，是一个循环。** 模型只会预测一格。是循环让一格变成了一段。

**旋钮一：temperature。**

```python
adjusted = probabilities ** (1.0 / temperature)
adjusted = adjusted / adjusted.sum()
```

**旋钮二：top-k。**

```python
keep = np.argsort(-adjusted)[:top_k]
```

这两个旋钮今天几乎所有语言模型都带着。你在网页版里看到的那个"温度"滑块，就是第一个。

## Python 实现

三个策略其实共用同一段代码，区别只在参数：

```python
def pick_next_token(probabilities, temperature=1.0, top_k=None, rng=None):
    # 1. 温度：重新分配概率
    adjusted = probabilities ** (1.0 / temperature)
    adjusted = adjusted / adjusted.sum()

    # 2. top-k：砍掉尾巴
    if top_k is not None and top_k < len(adjusted):
        keep = np.argsort(-adjusted)[:top_k]
        cut = np.zeros_like(adjusted)
        cut[keep] = adjusted[keep]
        adjusted = cut / cut.sum()

    # 3. 抽一次
    return int(rng.choice(len(adjusted), p=adjusted))
```

于是：

| 策略 | 怎么调 |
|---|---|
| 贪心 | `top_k=1` |
| 温度 | 只给 `temperature` |
| top-k | 两个都给 |

`after.py` 里把它们摆在一起跑：

```text
  同一个开头：「举头望明月低头思」

  贪心（每次都取最大）
    第 1 次：故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月
    第 2 次：故乡鹅鹅鹅曲项向天歌白毛浮绿水红掌拨清波床前明月

  温度 4.0
    第 1 次：故乡明思望明月低思是明光疑前明故前故乡头乡地歌明
    第 2 次：故浮望明月低头思故乡绿明月头思故乡头思故白毛疑霜

  top-k 3 + 温度 4.0
    第 1 次：故乡波前波是明月歌明月低歌上鹅曲曲曲曲曲向拨明月
    第 2 次：故望明月低头曲项向天歌毛拨毛疑是掌拨波床月月月月
```

上面两组，两次都不一样。第一组，两次一模一样。

## 它解决了什么

模型本身一个字都没改，参数量一模一样，权重一个数都没动。改的只是"拿到那 33 个概率之后怎么办"。

但我们拿到的能力完全不同了：

**从"预测"到"生成"。** 第 22 章我们说"它只会预测，不会生成"。现在这句话可以改掉了：把预测接起来，就是生成。接的动作叫自回归，是循环给了它这个能力。

**从"一条路"到"一片路"。** 贪心每次只走一条路。现在我们可以在一大堆可能的续写里挑。换成 `床前` 这个开头，看 `experiment.py` 的最后一段：

```text
  贪心
    第 1 次：床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿
    第 2 次：床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿
    第 3 次：床前明月光疑是地上霜举头望明月低头思故乡鹅鹅鹅曲项向天歌白毛浮绿

  温度 4
    第 1 次：床前明月低上鹅月地思故故乡向天地歌明歌歌白歌举头明明光白鹅鹅曲掌
    第 2 次：床前明月光疑是地地上霜举头望明月低头乡波头思明月低头望故前故低水
    第 3 次：床前明月光地光是地上霜举头望明月低头歌思故乡鹅曲项向天白毛浮毛歌
```

同一个模型，同一个开头。第一种写法每次都一样，后两种每次都不一样。

**而且"有多不一样"是可以调的。** 温度、top-k 就是那两个旋钮。

`experiment.py` 里还有一个数字值得一提。它量了"最长复读"——写出来的东西和语料的最长公共子串有多长：

```text
    2.0        1.11             6        32
    3.0        1.62             6        24
    4.0        2.77             6        12
    6.0        6.98             6        11
    8.0       12.09             6         9
```

温度越高，最长复读越短。也就是说，**让模型"自由"一点，它反而没那么像在背书了**。

不过要小心：温度 8 的时候它已经不太像中文了。我们在"像中文"和"有变化"之间做了一次交换。

## 它还解决不了什么

这一章我们拿到了两个旋钮，也搞清楚了"生成"这个词到底指什么。

但有一个问题，我们从第 22 章拖到现在都没正面回答：

**这个模型到底会什么？**

我们知道的只有一件事——它写出来的字"像中文"。可是"像"是一个很弱的证据。

具体地说，有三个问题我们一个都没回答过：

1. 它写出来的东西，有多少是它**背下来**的？我们把语料重复了 8 遍，它完全可以把 304 个字符全部记住。如果是这样，那它写的不是诗，是复读机。
2. 给它一段**语料外面**的文字（但用词表里的字），它会怎样？`before.py` 里我们已经看到它会崩，但那是贪心的问题还是模型的问题？
3. 我们的语料里没有"亮"字，所以它不认得"月亮"。那它认得"明月"和"月光"是一回事吗？它有没有学到"月"这个字该跟什么字待在一起？

还有一个更基础的问题：**温度拧到 3 才动，是因为这个模型太自信了。它为什么这么自信？**

下一章我们不加任何新零件，也不改架构。只做一组探测实验，去看看它里面到底装了什么、缺了什么。

## 练习

见 `exercises.md`，这里列 4 条最关键的：

1. 把 `temperature` 设成 `0.01`、`100`，跑 `generate`。分别会发生什么？为什么温度必须大于 0？（`pick_next_token` 会直接报错，想清楚它为什么该报错。）
2. `after.py` 里 `greedy` 用的是 `top_k=1`。如果改成 `temperature=0.0001`（不设 top_k），效果一样吗？为什么？（提示：`0.9999 ** 10000` 是多少？）
3. 在 `experiment.py` 的温度表里加一行 `temperature=20`。最长复读会掉到多少？写出来的东西还像中文吗？找到那个"还能看"和"不能看"的分界点。
4. 把 `top_k` 固定成 3，温度从 0.2 拧到 8。你会发现有效候选数最多只到 3。为什么？
