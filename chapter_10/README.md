# 第 10 章：数字编号没有意义

## 本章的问题

上一章最后留下了一个问题：**词还只是编号，编号没有意义。**

先把这句话拆开看，它到底在说什么。

第 1 章我们把句子拆成词，然后给每个词发了一个整数：

```text
苹果 = 0    发布 = 1    新 = 2    手机 = 3    芯片 = 4    …    派 = 15
```

这个整数叫 token id。它让我们能区分"这是第几个词"，就这一个用处。

现在第 9 章的引擎已经造好了，可以把它喂进模型、让模型自己学了。
但我们喂进去的是这个整数。于是有两个麻烦。

**麻烦一：编号自带一种"大小"和"远近"，而这是我们随手定的。**

编号里有 `3 > 2 > 1`。可"手机 > 新 > 发布"是什么意思？
再看距离：苹果 的编号是 0，香蕉 是 11，手机 是 3。
按编号算，苹果 离 手机 近（差 3），离 香蕉 远（差 11）。
但在意义里，苹果 和 香蕉 是一类东西，跟 手机 不是。
编号里的距离是我们排词表时留下的影子，它跟词的意思没有半点关系。

**麻烦二：编号是我们发的。词表顺序一换，编号全变。**

15 个词一共有 15! 种编号方式，也就是一万三千多亿种。
我们当初只是随手把词表写成了"先科技词、再食品词"，编号才长成现在这样。
换一种排法，第 9 章辛苦训练出来的东西就得从头再来。

这两条都不是猜测。下面我们就跑给你看。

## 最简单的尝试

最直觉的办法是：**不管它，接着用。**

第 3 章我们就是这么干的 —— 把输入换成数字，乘上权重加起来，得到分数。
现在无非是把"一个词在不在句子里"换成了"这是第几个词"。

先给模型一个再简单不过的任务：

```text
只在科技句里出现过的词：发布 新 手机 芯片 电脑 华为 小米
只在食品句里出现过的词：好吃 很 甜 香蕉 这个 真 做成 派
```

这 15 个词的分组是第 1 章那 10 句话里数出来的，不用我们另编。
（苹果 两边都出现，本章先把它放在一边，第 12 章专门讲它。）

模型还是那个模型，只有两个参数：

```python
score = w * token_id + b      # 分数低的算科技词，分数高的算食品词
```

`w` 和 `b` 用 toygrad 训练。这看起来很合理 —— 第 3 章、第 6 章我们都是这么干的。
让我们跑一下。

## 新机制

编号的问题是它太穷了：一个词只分到一个数字，这个数字还要同时承担
"第几号"和"它是什么"两件事。这两件事本来就无关，挤在一起只会互相干扰。

那就不挤了。**一个词不是一个数字，而是一组数字。**

```text
苹果 = [+0.13, -0.13, +0.64, +0.10, -0.54, +0.36, +1.30, +0.95, …]
香蕉 = [-1.47, +1.03, -1.93, -0.24, -0.20, -1.04, +0.61, -0.20, …]
手机 = [+1.80, +1.32, +0.36, -1.21, -0.00, +0.66, -1.29, +0.40, …]
```

（这里每个词给了 16 个数字。为什么是 16，等一下说。）

为什么这样就好了？看两件事。

**第一，每个词有了自己的方向。** 模型不再只能说"谁的编号大"，
它说的是：

```python
score = 向量 · w + b
```

`w` 也是 16 个数字。一个词分数的高低，取决于它的这 16 个数字和 `w` 的这 16 个数字
"合不合得来"。想让 手机 分高、香蕉 分低？把 `w` 指向 手机 那个方向就行了。
这跟它们排在第几号完全无关 —— 编号根本没有进到模型里去。

**第二，编号被从模型里拿掉了。** 向量是跟着词走的，不是跟着位置走的。
词表换个顺序，我们只需要把表里的行跟着词搬一下，模型看到的东西一模一样。

这个东西，以后我们叫它 **embedding**，中文叫**词向量**。

有一点必须说清楚：**这一章我们不训练这组数字。**
它一开始就是随机撒的，之后一动不动。被训练的只有 `w` 和 `b`。
之所以这么做，是因为这一章只想回答一个问题：

> 一组**随机**数字，难道比一个精心安排的编号还好用？

如果这样都比编号好用，那就说明问题确实出在"编号"上，
而不是出在"随机数不够好"上。

## Python 实现

完整代码在 `after.py`。核心就两段。

第一段，造一张只读的表。表的形状是 `(词数, 每个词几个数字)`：

```python
DIM = 16   # 每个词用几个数字

def build_vector_table():
    return randn(len(VOCAB), DIM, requires_grad=False, seed=SEED)
```

`randn` 是 toygrad 里的正态分布初始化。注意 `requires_grad=False` ——
这张表是只读的，反向传播不会碰它。

为什么是 16 个数字？两个原因。
一是这个数字本来就可以随手调（真实模型里是几百到几千）。
二是我们这里只有 15 个词，16 个数字已经比词还多了 ——
随机撒的 15 个点放在 16 维空间里，想让它们被一个平面按任意方式分成两堆，
几乎总是能做到的。练习 2 会让你把维数调到 2 和 4，亲眼看看维数不够时会怎样。

查表直接用第 9 章的 `embedding`，或者像这里一样简单地按下标取：

```python
vectors = {word: table.data[i] for i, word in enumerate(VOCAB)}
```

第二段，训练。**任务和 `before.py` 一模一样**，只是把"编号"换成了"向量"：

```python
def train_scores(vectors, labels, steps=STEPS, lr=LR):
    x = Tensor(np.stack(vectors))            # (15, 16)，每个词一行
    w = randn(DIM, requires_grad=True, seed=123)
    b = Tensor(0.0, requires_grad=True)
    ...
    score = x @ w + b
```

`x @ w` 是矩阵乘向量：`(15, 16) @ (16,) -> (15,)`。
每个词的分数就是它那 16 个数字和 `w` 的点积。

## 它解决了什么

把两章并排放在一起看：

| | 编号（第 10 章之前） | 一组数字（第 10 章） |
|---|---|---|
| 词表顺序 A 下的准确率 | 100.0% | 100.0% |
| 词表顺序 B 下的准确率 | 53.3% | 100.0% |
| 词表顺序 C 下的准确率 | 66.7% | 100.0% |
| 方案 A 的模型搬到方案 B | 60.0% | 100.0%（本来就一样） |
| 一共有多少参数在控制这 15 个词 | 2 个（`w` 和 `b`） | 17 个（`w` 和 `b`）+ 每个词自己的 16 个数字 |
| 分数是不是被编号锁死 | 是，只能是编号的一条直线 | 否，每个词有自己的方向 |

具体说，这一章拿到了三件东西。

1. **编号不再影响结果。** 三种编号方案下准确率都是 100%，
   因为模型从头到尾没有见过编号 —— 它见到的是向量。
2. **"谁离谁近"这件事从编号里被拿走了。** 编号的距离是排词表的副产品，
   现在它不进模型了，也就没法再捣乱。
3. **每个词有了自己的方向。** 模型能表达的关系从一个数字变成了 16 个数字，
   给 手机 高分和给 派 高分不再是互相冲突的事。

第 1 章那个"苹果 在两类句子里都出现"的老问题还悬着。
这一章的成果是：我们终于有了一个**可以装下多个侧面**的容器 ——
每个词有 16 个数字，装得下比一个数字多得多的东西。

## 它还解决不了什么

回到 `after.py` 的输出里最后一段，我们做了一件很自然的事：
既然每个词现在是一组数字，那就**比一比谁跟谁像**。

比的办法叫**余弦相似度**：两个向量的方向越一致，它就越接近 1；
互相垂直是 0；方向相反是 -1。它跟向量的长短无关，只看方向。

```text
==============================================================
用余弦相似度找「最像的词」
==============================================================
  和 手机   最像的 5 个词： 派 +0.28  这个 +0.15  电脑 +0.13  做成 +0.09  小米 +0.09
  和 苹果   最像的 5 个词： 华为 +0.36  做成 +0.25  发布 +0.24  很 +0.21  小米 +0.19
```

和 手机 最像的词是 派。和 苹果 最像的词是 做成。

这是胡话。而且不是"差一点"的那种胡话 —— 相似度最高的也才 +0.28，
说明这 16 个数字之间根本没有可比性，谁排第一全靠运气。

问题出在哪？回到本章那句话：**这组数字是随机撒的。**

我们只是把"词是一组数字"这个**容器**造了出来，
至于往里面装什么数字，我们完全是掷骰子决定的。
模型没有办法，它只能在这堆随机数里硬挑出一个方向来用 ——
就像在一堆乱码里找规律，找到的那点东西当然不是词的意思。

于是很自然的一个问题：

> **这组数字到底该怎么来？**

有两种可能。

- 一种可能是：随机就够用了，多撒几个数字、多训练一会儿就行。
  那我们得说清楚"够用"是够用到什么程度 —— 至少得让它能回答"谁跟谁像"。
- 另一种可能是：这组数字不该是撒出来的，而应该**从语料里学出来**。
  毕竟一个词的意思，本来就体现在"它通常跟哪些词一起出现"上。

`after.py` 里的相似度表已经告诉我们第一种可能不成立：
随机数字之间没有结构，再怎么训练 `w` 也变不出结构，
因为 `w` 只有 16 个数，它是**读**这张表的，不是**改**这张表的。

所以只剩一条路：**把这张表本身变成可训练的参数。**

那就要问一个更具体的问题了：**拿什么任务去训练它？**
一张随机的表，要喂它吃什么，它才会把 香蕉 和 苹果 摆到一起、
把 手机 和 芯片 摆到一起？

## 练习

见 `exercises.md`。这里列 5 条最关键的：

1. 把 `before.py` 里方案 C 的随机种子换几个，看看准确率在什么范围里跳。
   这说明了什么？
2. 在 `after.py` 里把 `DIM` 改成 2、4、8，各跑一遍。维数小了以后，
   向量为什么也会分不开？这和"编号分不开"是同一个原因吗？
3. `before.py` 里模型只有 `w`、`b` 两个参数。如果给每个编号再加一个专属的偏移量
   （也就是 `score = w * id + b_id`），方案 B 能不能学会？这 15 个 `b_id` 是什么？
4. `after.py` 的相似度表里，和 手机 最像的是 派。把种子换成 1 到 5，各跑一遍，
   看看和 手机 最像的变成了谁。这些答案里有规律吗？
5. 不改变模型、不改变词，只改编号顺序，试着造出一个
   **准确率比方案 A 低、但比方案 B 高** 的编号方案。这样的方案存在吗？
