# 第 15 章：为什么需要多个头

## 本章的问题

上一章最后留下了一句话：

> 一个词只有一行权重，加起来等于 1。这一行是笔固定预算。

这一章我们换一句话来看这件事：

```text
小王 把 书 给了 小李 因为 他 明天 考试
```

"他"这个字身上，同时挂着好几件事。

先跑 `before.py`，看第 14 章的做法在这里给出什么：

```text
第 14 章的做法：'他'这个字拿到的权重（只有这一行）
------------------------------------------------------------
  小王  0.1157  #####
  把    0.0890  ####
  书    0.1058  ####
  给了  0.1173  #####
  小李  0.1098  ####
  因为  0.0937  ####
  他    0.1065  ####  <- 自己
  明天  0.1326  #####
  考试  0.1295  #####
  权重和 = 1.0000
  （投影是随机初始化的，所以具体数字没意义；有意义的是：它只有一行。）
```

**只有一行。** 这一行要同时回答"他 = 小王还是小李"和"他明天要考试"。

把这两个需求写成两组理想权重（这只是为了把冲突算清楚）：

```text
  需求 A（指代）：'他'是小王还是小李？
    理想的权重应该是：小王 0.5，小李 0.5

  需求 B（时间）：'他'明天要考试
    理想的权重应该是：明天 0.5，考试 0.5

  需求 A 要花掉的权重：1.0
  需求 B 要花掉的权重：1.0
  两个加起来：2.0
  一行权重一共只有：1.0
  → 超出预算 1.0
```

一行权重只有 1 块钱，两个需求加起来要 2 块。这不是"训练得不够好"，
这是**账算不过来**。一个头能做到的最好情况是两边各让一步：

```text
  一行权重能做到的最好情况，是两边各让一步：
  小王  0.25  小李  0.25  明天  0.25  考试  0.25

  离需求 A 还差：0.50（有 50% 的权重放错了地方）
  离需求 B 还差：0.50
  两个需求都只做到一半。
```

**问题摆在这里：一句话里的关系不止一种，一行权重不够分。**

## 最简单的尝试

修法很直接：**一行不够，那就多来几行。**

第 14 章我们已经会给一个词造一组 Query / Key / Value 了。现在造几组——
每一组用一个**自己的投影矩阵**：

```python
第 1 组：q1 = x @ W_q1    k1 = x @ W_k1    v1 = x @ W_v1
第 2 组：q2 = x @ W_q2    k2 = x @ W_k2    v2 = x @ W_v2
第 3 组：q3 = x @ W_q3    k3 = x @ W_k3    v3 = x @ W_v3
```

每一组各自算一套权重、各自把 value 混一遍：

```python
第 1 组的输出 = softmax(q1 k1ᵀ / √d) v1
第 2 组的输出 = softmax(q2 k2ᵀ / √d) v2
```

然后把这些输出**拼起来**：

```python
输出 = 拼起来(第1组输出, 第2组输出, 第3组输出) @ W_o
```

每一组就叫一个 **head（头）**。这套做法，我们叫它
**多头注意力（Multi-Head Attention）**。

注意一个细节：**每个头的投影矩阵是不一样的**。如果几个头用同一套 `W_q`/`W_k`/`W_v`，
那它们算出来的权重一模一样，多了也没用。这也是"多"字的意义所在——
不是把同一件事算几遍，而是**同时用几种不同的方式去看同一句话**。

还有一个细节：每个头的维度要小一点。第 14 章一个头用满 24 维，
现在 4 个头各分 6 维。这样参数总量基本没变，只是把它切成了 4 份。

## 实验

跑 `experiment.py`（对照组：1 个头 vs 4 个头，同一个任务、同样的参数量）。

```text
      步数          1 个头          4 个头
  ----------------------------------
       0       11.5659        8.2376
      50        0.2932        0.0672
     100        0.1924        0.0176
     200        0.0176        0.0058
     400        0.0044        0.0022

  两边最后都把这两句话背下来了（数据只有两句，这是必然的）。
  差别不在损失，在于每个位置能拿出几套权重。
```

损失看不出区别——两句话太少了，一个头也背得下来。真正要看的是"他"那一行：

```text

    给了  0.0671  ###
    小李  0.0019
    因为  0.0012
    他    0.0019

【4 个头】四行，各看各的：
  头 0：最大值 0.675   前三个：明天(0.675)、考试(0.134)、把(0.054)
  头 1：最大值 0.484   前三个：书(0.484)、因为(0.149)、把(0.079)
  头 2：最大值 0.263   前三个：明天(0.263)、因为(0.163)、把(0.161)
  头 3：最大值 0.482   前三个：考试(0.482)、给了(0.434)、小王(0.043)
```

四行放在一起看：

```text
  1 个头：只有一行，0.852 压在'考试'上，剩下 0.148 留给 8 个词。
           它想再表达点别的（比如'他 = 小王'），就只能从这 0.852 里往外抠。

  4 个头：每一行各自挑自己的词——
           头 0 最关注 明天（0.675）
           头 1 最关注 书（0.484）
           头 2 最关注 明天（0.263）
           头 3 最关注 考试（0.482）

  注意 4 个头并没有比 1 个头'更尖'——它们做的事情是：把一份注意力拆成 4 份，
  各挑各的词。1 个头押了'考试'就押不了'书'；4 个头里，头 1 押'书'，头 3 押'考试'和'给了'。
  同样的参数预算，能同时表达的东西多了几倍。
```

还有一件事要老实说：**我们不能给这几个头贴标签。** 数据只有两句话，
谁学到什么是有一半运气的。你可以把 `seed` 换成 7 再跑一遍，四个头关注的东西就变了。
我们确定能说的是：**同一个位置，4 个头给出了 4 套不同的权重。**

## 新机制

多头注意力，就是把第 14 章那一套原样复制 h 份，再拼起来：

```python
for 每个头 h:
    q_h = x @ W_q[h]                          # 我在找什么（第 h 种问法）
    k_h = x @ W_k[h]                          # 我有什么（第 h 种标签）
    v_h = x @ W_v[h]                          # 我能给你什么（第 h 份信息）
    头_h = softmax(q_h k_hᵀ / √d_h) v_h        # 第 h 种看法的结果

输出 = 拼起来(头_1, 头_2, ..., 头_h) @ W_o
```

写成一行：

```text
MultiHead(Q, K, V) = Concat(头_1, ..., 头_h) W_o
   其中  头_i = Attention(Q W_q[i], K W_k[i], V W_v[i])
```

三个新东西，各有各的道理：

- **每个头一套自己的投影**：这是"看的方式"能被分开表达的原因。
- **每个头维度变小（d_h = d / h）**：总参数基本不变。4 个头不是把代价乘 4，
  而是把同样的钱分成 4 份花。
- **拼起来之后再投一次影（W_o）**：几个头各管一摊，最后总要把它们的信息
  混到一起，输出也要回到原来的维度，后面的层才接得上。

`W_o` 这个名字里的 o 是 output（输出），`W_q`/`W_k`/`W_v` 里的 q、k、v
就是上一章的 Query / Key / Value。

## Python 实现

对应 `after.py`。核心是 `multi_head_attention`：

```python
def multi_head_attention(vectors, params):
    head_dim = params["w_q"].shape[-1]

    # 三个投影一次算完所有头：矩阵乘法会自动在"头"这一维上广播
    query = vectors @ params["w_q"]          # (头数, 词数, HEAD_DIM)
    key = vectors @ params["w_k"]
    value = vectors @ params["w_v"]

    # 每个头自己算一套分数、一套权重
    scores = (query @ key.transpose(0, 2, 1)) / np.sqrt(head_dim)
    weights = scores.softmax(axis=-1)        # (头数, 词数, 词数)

    # 每个头自己混一遍 value
    head_output = weights @ value            # (头数, 词数, HEAD_DIM)

    # 把几个头拼起来
    joined = head_output.transpose(1, 0, 2).reshape(num_words, DIM)
    return joined @ params["w_o"], weights
```

三个形状要盯住：

- `params["w_q"]` 的形状是 `(头数, 维度, 每个头的维度)`，也就是
  **4 个 24×6 的矩阵叠在一起**。
- `weights` 的形状是 `(头数, 词数, 词数)`。`weights[0]` 就是第 0 个头的
  那张注意力矩阵——和第 14 章那张表长得一样。
- 最后那个 `transpose(1, 0, 2).reshape(...)` 做的事情就是"把 4 个头拼起来"：
  从 `(4, 词数, 6)` 变成 `(词数, 4, 6)` 再拉平成 `(词数, 24)`。

跑 `after.py`，会训练 400 步，然后打印每个头的注意力矩阵。热力字符里
`.` 最轻、`@` 最重（每个头按自己的最大值画的，看形状）：

## 它解决了什么

1. **同一个位置能同时有好几套权重。** 4 个头给"他"的答案是
   `明天(0.675)`、`书(0.484)`、`明天(0.263)`、`考试(0.482)+给了(0.434)`——
   四套完全不同的分布，同时存在。
2. **预算不再是一个人的事。** `before.py` 里算得很清楚：两个需求加起来要 2.0，
   但一行权重只有 1.0，折中的结果是两边各差 0.50。分成两个头以后，每个头各有
   1.0 的预算，两边都能做到 0.00。
3. **代价没有变大。** 4 个头每个 6 维，加起来还是 24 维。1 个头 vs 4 个头的
   损失曲线（第 50 步 `0.2932` vs `0.0672`，第 400 步 `0.0044` vs `0.0022`）
   说明这不是靠堆参数换来的。

## 它还解决不了什么

现在把这一章的代码从头看一遍，问一个问题：

**从词向量到输出，哪一步用到了"这个词排第几"？**

- `vectors @ W_q`：每个词自己投自己的影，跟位置无关。
- `scores = q kᵀ / √d`：任意两个词的分数，只跟这两个词有关，跟它们隔多远无关。
- `weights @ value`：加权求和。求和是不管顺序的。

**一步都没有。** 这套机制看到的不是一个"句子"，而是一堆词——
它知道有哪些词、谁和谁关系近，但完全不知道谁先谁后。

后果很具体。下面这两句话：

```text
狗 咬 人
人 咬 狗
```

用的是同样的三个词。"狗"在两个句子里都会去看"咬"和"人"，
"咬"也都会去看"狗"和"人"——因为这套机制里，任何一对词的分数
只取决于这两个词是谁。

**那么，"狗咬人"和"人咬狗"到底差在哪？模型怎么才能知道？**

下一章我们把这个实验真的跑一遍：把输入词的顺序打乱，看注意力输出会不会变。

## 练习

见 `exercises.md`，这里列最关键的几条：

1. **只留一个头**——把 `NUM_HEADS` 改成 1，看"他"还剩几行权重，损失还能不能降下来。
2. **让几个头共用一套 Q/K/V**——把三个投影都改成 `params["w_q"][0:1]`，
   看 4 个头的权重矩阵还一不一样。
3. **把头开得更多**——改成 8 或 12；再试试 5（想想 `24 // 5 = 4` 之后，
   剩下的 4 维去哪了）。
4. **换个种子**——`train(steps=400, seed=7)`，看四个头是不是每次都在看同样的词。
   这一题是为了让你自己确认：数据这么少，**别给头贴标签**。
5. **把拼接换成相加**——`head_output.sum(axis=0)`，看形状对不对得上，
   再想想拼接和相加哪个保留的信息多。
