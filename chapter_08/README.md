# 第 8 章：为什么需要激活函数

## 本章的问题

上一章我们做了一件事：在输入和分数之间，塞进了一层"中间结果"。

结果它一点用都没有。加了中间层之后，loss 还是 0.693147，
和只有一条直线的时候一模一样 —— 连小数点后六位都没变。

中间层明明多出了一整排可以调的权重，凭什么一点用都没有？

这个问题有两个可能的答案，而它们的后果完全不同：

- **答案 A**：中间层还不够宽、不够深，学不动。那就堆宽一点、堆深一点。
- **答案 B**：中间层天生就做不了这件事。那堆多少层都是白堆。

在搞清楚是哪一个之前，我们做什么都是瞎猜。

## 最简单的尝试

最直觉的反应是 A：**一层不够，那就堆。**

`before.py` 把这件事做到底了。我们写了一个能堆任意多层的网络：

```python
def forward(params, x):
    """一层接一层，中间不加任何别的东西。"""
    current = x
    for layer in range(len(params["ws"])):
        current = [加上偏置的加权求和 ...]
    return current
```

每一层都是纯加权求和：拿上一层的输出，乘权重、加偏置、交给下一层。
中间不加任何别的东西。

梯度这里我们直接用第 6 章的数值法 —— 堆几层就要重推几遍链式法则，
太麻烦了，而数值法换什么结构都能用。

跑出来是这样：

```text
  层数      每层宽度      参数个数          每步要跑几次前向       训练后的 loss
   1         4         6                12        0.693147
   2         4        22                44        0.693147
   3         4        42                84        0.693147
   5         2        30                60        0.693147
  10         2        60               120        0.693147
```

1 层、2 层、3 层、5 层、10 层 —— loss 全部停在 0.693147。

10 层的网络有 60 个参数，是 1 层的十倍。这十倍参数一点用都没有。

**答案 A 被排除了。现在我们要证明答案 B。**

## 实验

跑 `experiment.py`。

### 第 1 步：把训练好的两层网络乘开

我们要让中间层自己招供。

办法很土：把中间层那一层的式子，代进输出层的式子里。
两层就是"先算 `h`，再由 `h` 算分数"：

```text
h    = w1 * x + b1
分数 = w2 * h + b2
```

把第一行代进第二行，括号乘开，只剩下 `某个数 * x + 某个数`。

我们把上一层那个训练了 400 步的网络拿来乘开，然后逐点比对：

```text
      输入                     两层网络的输出                     等效直线的输出           差
  [0, 0]   +0.00069280 / +0.00087466   +0.00069280 / +0.00087466    0.00e+00
  [0, 1]   -0.07086816 / -0.07011921   -0.07086816 / -0.07011921    1.39e-17
  [1, 0]   -0.09196347 / -0.09269373   -0.09196347 / -0.09269373    0.00e+00
  [1, 1]   -0.16352442 / -0.16368759   -0.16352442 / -0.16368759    2.78e-17

最大的差是 2.78e-17 —— 这不是接近，这是完全相同。
```

这不是巧合，也不是"差不多"。两层网络和一条直线，
在数学上是**同一个东西**。

### 第 2 步：换成 3 层、5 层、10 层呢

```text
    层数      参数个数           和等效直线相差
     2        22          5.55e-17
     3        42          0.00e+00
     5        53          3.47e-18
    10        60          8.13e-20
```

随便取几组随机权重，这个乘法都成立 —— 它和训练无关，也和权重是多少无关。
**任何一叠"纯加权求和"的层，永远等于单独一层。**

所以中间层做的事情，不是"加工"数据，它只是把数据重新摆了一遍。
摆多少次，还是一根直的东西。

### 第 3 步：加上那个会拐弯的函数

现在我们在中间层后面加一个小函数：

```python
def relu(value):
    """负数变成 0，正数原样留下。"""
    return value if value > 0.0 else 0.0
```

只有一个 `if`。然后我们换一个角度来测：直线都有一个性质 ——

```text
分数(u + v)  =  分数(u) + 分数(v) - 分数(0)
```

随便取几组 `u`、`v` 代进去，如果模型是直线，两边必须相等。

```text
没有 relu 的两层网络：
               u               v          两边相差
  [-0.384, -1.2][-1.285, -1.006]      5.55e-17
  [1.04, -0.995] [-0.468, 0.737]      1.04e-17
  ...

加上 relu 的两层网络：
               u               v          两边相差
  [-0.384, -1.2][-1.285, -1.006]      3.17e-02
  [1.04, -0.995] [-0.468, 0.737]      4.38e-02
  ...
  -> 差得最远的一次差了 0.0438。它已经不是直线了。
```

只多了一个"负数变 0"，这个式子就再也对不上了。

### 第 4 步：加完之后，XOR 被解决了

```text
模型                             训练后的 loss       准确率
两层，中间不加东西                       0.693147      0.50
两层，中间加 relu                   0.00039921      1.00
```

上一章那个"怎么训练都分不开"的任务，4 个点全部分对了，
概率都在 0.99 以上。

## 新机制

这一章引入的东西有两个名字。

### 激活函数

> 每一层算完之后，先别急着交给下一层。
> 让它过一个简单的函数，再交出去。
> 这个插在层与层之间的小函数，叫**激活函数**。

我们用的是 ReLU（负数变 0）。它简单到可以写在一行里，
但它是整件事成立的关键：

- 没有它，一叠层就是在互相"乘开"，怎么堆都是同一根直线。
- 有了它，每一层算出来的结果会被**掰弯**一下，掰过弯的东西再叠起来，
  就再也乘不成一个简单的式子了。

那个实验看得很清楚：中间层里的值被 ReLU 掐掉了几个，
再往后算，输出就不再满足直线的性质。

### 非线性

给这个"拐弯"的性质取个名字。

> 一条直线加上一个拐弯，出来的就不再是直线了。
> 这种"不能化简成一条直线"的性质，叫**非线性**。

回过头看这三种模型：

```text
第 6 章    输入 → 分数                          一条直线
第 7 章    输入 → 中间层 → 分数                  还是一条直线（乘开就没了）
第 8 章    输入 → 中间层 → 拐一下 → 分数          不是直线了
```

**要拐弯，必须有一个不是直线的函数插在中间。**
这句话是这一章的全部内容。

## Python 实现

`after.py` 里的 `forward`，改的只有一行：

```python
z = [...]                                   # 中间层的原始输出
h = [relu(value) for value in z]            # 拐一下

scores = [...]                              # 再由 h 算分数
```

`relu` 本身是：

```python
def relu(value):
    return value if value > 0.0 else 0.0
```

梯度也要跟着改。中间层的梯度传回去的时候，
**被 ReLU 掐掉的那部分，梯度也要一起掐掉**：

```python
# 新加的一行：relu 把负的掐成了 0，那部分梯度也传不回去
dz = [dh[j] if z[j] > 0.0 else 0.0 for j in range(hidden_size)]
```

`z[j] <= 0` 意味着这个单元这次的输出是 0，它对最终的分数没有任何影响 ——
所以这次也就别给它记功。

这一行如果写漏了，程序**不会报错**，训练也照样会跑，
只是会慢一点、差一点。我们是用第 6 章的数值梯度回头验出来的
（`tests/test_chapter_08.py::test_hand_written_gradient_matches_numeric_gradient`）。

跑起来是这样：

```text
前 5 步的 loss：0.685748  0.683558  0.681219  0.678840  0.678241
第 5000 步的 loss：0.00039921
准确率：1.00
```

中间层里的值长这样：

```text
      输入              中间层（过 relu 之前）                     过完 relu                两个分数
  [0, 0]  +2.51  +0.00  -0.00  +0.00  +2.51  +0.00  +0.00  +0.00  -4.541 / +3.933
  [0, 1]  -0.00  -0.24  -1.92  -3.62  +0.00  +0.00  +0.00  +0.00  +3.398 / -3.398
  [1, 0]  +5.07  -0.08  +1.92  +3.62  +5.07  +0.00  +1.92  +3.62  +3.998 / -5.100
  [1, 1]  +2.56  -0.32  -0.00  +0.00  +2.56  +0.00  +0.00  +0.00  -4.682 / +4.063
```

看第二列：有的值被掐成了 0，有的原样留下。
输入是 `[0, 1]` 的时候，四个中间单元全被掐成了 0 ——
模型干脆用"一个都不亮"来表示这一种情况。

## 它解决了什么

- XOR 解决了：准确率 1.00，loss 从 0.693147 降到 0.0004。
- 两个类别的分数被彻底拉开了（`-4.54 比 +3.93`），不再是"各 0.5"。
- 我们第一次有了一个**能画出折线**的模型，而不是只能画一条直线。

还有一件更重要的事：我们搞清楚了第 7 章到底哪里出了问题。

不是层数不够，不是宽度不够，也不是学习率没调好。
是**中间层和输入之间，缺了一个拐弯**。

有了这个认识，"神经网络"这四个字才真正成立：
一层一层的加权求和负责"搬运和混合"，中间那些拐弯负责"加工"。
少了拐弯，前面那部分工作全白做。

## 它还解决不了什么

回头看这一段代码，它是这一章最关键的一行：

```python
dz = [dh[j] if z[j] > 0.0 else 0.0 for j in range(hidden_size)]
```

这一行是**我拿着链式法则推出来的**。推它的时候，我心里得清楚：

- 分数对中间层求导是 `w2`；
- 中间层对 `z` 求导，是"正数保留、负数归零"；
- 两段乘起来，才是 `dz`。

这是两层。写出来 20 行，还行。

可是我们已经知道，一层不够用 —— 第 7 章试过了。
真实的任务要十几层、几十层。而且每加一层，就要：

1. 重推一遍链式法则（多一个下标就多一处可能错的地方）；
2. 重写一段索引代码；
3. 用数值梯度回头验一次 —— **因为写错了不会报错。**

第 4 步那个实验里，我们堆到 10 层的时候用的是数值梯度，
就是因为手推十层的链式法则实在写不动了。而数值梯度自己也有硬伤：
参数有多少个，每走一步就要跑两倍那么多次前向。

十层就写不动了。那 GPT 有多少层？GPT-3 有 96 层。

**下一章要问的是：这些梯度，能不能让机器自己算？**
