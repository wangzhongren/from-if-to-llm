# 第 20 章：把分类器重新拿回来

## 本章的问题

上一章我们把 Transformer Block 装了起来。它能做的事仍然是：把一串向量变成另一串向量。

但我们要的是一台能写字的机器。

一个字一个字地写。给它 `床前`，它接 `明`；给它 `床前明`，它接 `月`。

我们先别急着往上堆东西。先回到最简单的地方看一眼，因为这里有一个可能会让你愣一下的事实。

第 2 章我们干的事是**分类**：

```text
"苹果发布新手机"  ->  科技
"苹果很好吃"      ->  食品
```

第 20 章我们要干的事是：

```text
"床前明"          ->  ?
```

答案是"月"。但"月"不是一个类别标签吗？——**它就是。** 只不过我们的候选从 2 个（科技 / 食品）变成了 33 个（每个字符一个）。

如果词表是几万个词，这一步的输出长这样：

```text
"今天天气很" ->   好 0.52
                  冷 0.21
                  热 0.12
                  苹果 0.0001
```

看出来了吗？**GPT 在做的最后一步，就是第 2 章那个东西。** 给一堆候选打分，挑一个。

我们绕了 18 章，从 if/else 走到了 attention，最后又回到了 `score = w · x` 加一个 softmax。

这一章我们就把这个"新的分类器"实现出来。先不用 attention，就用最简单的模型，看看它行不行，不行在哪。

## 最简单的尝试

先把第 3 章那个分类器原样搬过来。它长这样：

```python
score = W[当前字符]
```

给每种输入配一组分数。输入有 33 种（33 个字符），类别也是 33 个，所以就是一张 33×33 的表。

92.23%。这个数字不高不低，正好卡在一个让人不舒服的位置上。

## 实验

它答错了哪些地方？`before.py` 把每一种错误都列了出来：

```text
============================================================
它答错了哪些地方
============================================================
  语料里的 '头' 后面跟着 '思'，它却猜了 '望'
  语料里的 '鹅' 后面跟着 '曲'，它却猜了 '鹅'
  语料里的 '月' 后面跟着 '光'，它却猜了 '低'
```

只有三种错误，但它错了 23 次（语料重复了 8 遍）。

原因看语料就明白了：

```text
...举头望明月...      '头' 后面是 '望'
...低头思故乡...      '头' 后面是 '思'
```

两个 `头`，后面跟的字不一样。可这个分类器**只看得到 `头` 这一个字符**。它没有任何办法知道这一次的 `头` 是哪一个 `头`，于是它每次都押同一个答案，押对一半，押错一半。

`月` 也是一样：

```text
...床前明月光...      '月' 后面是 '光'
...举头望明月...      '月' 后面是 '低'
```

所以问题很清楚：**它不知道"这句话现在说到哪了"。** 它只知道"这个字符后面最常跟什么"。

第 12 章我们说过，"一个词的意思要看它的上下文"。现在我们要说的其实是同一件事的另一面：**下一个字符是哪一个，也要看上下文。**

## 新机制

我们改两件事。

第一件，**别再用编号了**。第 10 章我们说过，编号没有意义——`头` 是 10 号、`低` 是 2 号，这个 10 和 2 之间没有任何关系。给每个字符一组数字（embedding 表），这组数字是可以学的：

```python
vectors = embedding(table, char_ids)     # (B, 33) -> (B, 33, D)
```

第二件，**别只看一个字符了，看它前面的一整段**。

这里会有个问题：前面的字符有几个？如果我们说"看 8 个"，那输入就是 8 组数字。怎么把它们变成一个能喂给线性层的东西？第 7 章我们干过同样的事——**拼起来**：

```python
flat = vectors.reshape(B, WINDOW * DIM)  # 8 个 16 维的向量 -> 一个 128 维的向量
```

然后就是第 3 章那个线性层：

```python
logits = flat @ weight + bias             # (B, 128) -> (B, 33)
probabilities = logits.softmax(axis=-1)   # 33 个候选，各自一个概率
loss = cross_entropy(logits, answer)      # 第 5 章那个"错得有多离谱"
```

整个模型就这么多东西。没有 attention，没有 MLP，没有残差，没有 LayerNorm。

还有一件事顺便说一下。上面这个流程的第一步，是"把一段文字变成一串编号"：

```python
CHAR_TO_ID = {char: i for i, char in enumerate(VOCAB)}
CORPUS_IDS = np.array([CHAR_TO_ID[char] for char in CORPUS])
```

第 1 章我们干的就是这件事——把一句话拆成一个个 token，再给每个 token 编个号。当时我们没给它起名字，现在可以了：**这个把文本变成编号的东西，叫 tokenizer。** 反过来的那一步叫 decode。

我们这一章用的 tokenizer 是最笨的一种：一个字符就是一个 token，词表就是所有出现过的字符。真正的 tokenizer 要复杂得多（第 26 章会自己造一个），但它要做的三件事今天就已经定下来了：**编码、解码、知道自己的词表有多大。**

**现在可以给它起名字了。**

一个"给一段文字、输出下一个字符的概率分布"的模型，我们叫它**语言模型**（language model）。它做的事叫**下一个 token 预测**。

这个词你早就听过。但今天你要记住的不是这个词，而是它背后那件很朴素的事：

> 语言模型 = 分类器。类别数量 = 词表大小。

第 2 章的类别是 2 个，第 20 章的类别是 33 个，GPT 的类别是十几万个。区别只在数量，不在性质。

## Python 实现

`after.py` 里的模型只有三个参数张量：

```python
class NextCharModel:
    def __init__(self, vocab_size, dim=DIM, window=WINDOW, seed=SEED):
        self.table = randn(vocab_size, dim, scale=0.3, requires_grad=True, seed=seed)
        self.weight = randn(window * dim, vocab_size, scale=0.3, requires_grad=True, seed=seed + 1)
        self.bias = zeros(vocab_size, requires_grad=True)

    def __call__(self, windows):
        vectors = embedding(self.table, windows)          # (B, 窗口, 维度)
        flat = vectors.reshape(windows.shape[0], self.window * self.dim)
        return flat @ self.weight + self.bias
```

训练数据的切法，这一章要盯紧了看：

```python
for position in range(window, len(ids)):
    inputs.append(ids[position - window:position])   # 窗口是 [position-window, position)
    targets.append(ids[position])                    # 答案是 position 上的那个字符
```

**答案所在的那个位置，不在窗口里。** 现在这句话看起来天经地义，但下一章它就变成主角了。

## 它解决了什么

准确率从 92.08% 变成 100%，loss 从 0.3619 掉到 0.0026。那三种错误全没了。

但更重要的是，我们终于**命名了目标**。前面 19 章我们做了一堆零件：embedding、attention、MLP、残差、LayerNorm。它们各自的动机都很清楚，但拼起来到底是为了什么，一直没说。现在说了：

> 所有这些零件，最后都是为了让一个分类器分得更准。

而且这个分类器有个特别之处：**它的类别就是词表本身**。也就是说，模型输出的那 33 个概率，是一种"接下来该写哪个字"的完整猜测。

不过得小心一件事：**我们的语料只有 304 个字符，而且它全都见过。** 这个 100% 说明的是它把语料背下来了，不是它学会了中文。这一点第 24 章会专门回来看。

## 它还解决不了什么

`after.py` 的最后留了一段话：

```text
  我们这个模型的输入是语料的 [t-8, t)，答案是 t 位置上的字符。
  答案不在输入里。这 600 步训练，它一直是诚实的。

  但是回头看看我们的训练数据是怎么切的：
    输入：ids[t-8 : t]     答案：ids[t]
  如果换成「一次喂进整段语料、让每个位置都输出下一个字符」，
  那就变成：输入 ids[t : t+T]，答案 ids[t+1 : t+T+1]。
  对窗口里的第 i 个位置来说，它要预测的是 ids[t+i+1]，
  而这个字符，正好是窗口里第 i+1 个位置上的**输入**。
```

问题就在这里：

**下一章我们要把 attention 加回来。attention 干的事情，正是"让每个位置看到所有位置"。位置 t 会看到位置 t+1 —— 也就是它要预测的那个字符本身。**

这不是一个抽象的担心。`experiment.py` 把它摆出来了。三组模型，结构完全一样、窗口一样、训练步数一样，只有输入格子里的内容不同：

```text
  A 组（最后一格是当前字符）
      loss 0.0870      准确率 94.70%      抄答案 3.0%

  B 组（最后一格是答案）
      loss 0.0075      准确率 100.00%      抄答案 72.7%

  C 组（最后一格是答案，上下文随机）
      loss 0.0137      准确率 100.00%      抄答案 100.0%
```

"抄答案"的意思是：输出正好等于输入的最后一格。看探测结果最清楚：

```text
  C 组（最后一格是答案，上下文随机）
    上->上  举->举  乡->乡  低->低  光->光  前->前  向->向  地->地  天->天  头->头  床->床  思->思
    拨->拨  掌->掌  故->故  明->明  是->是  曲->曲  月->月  望->望  歌->歌  毛->毛  水->水  波->波
    浮->浮  清->清  疑->疑  白->白  红->红  绿->绿  霜->霜  项->项  鹅->鹅
```

33 个探测，33 次原样吐出来。

C 组最刺眼：它的上下文是**随机字符**，一个正经的模型在那种输入上应该什么也学不到。可它的准确率还是 100%。

**只要答案出现在输入里，模型就一定能找到它。而且它会让 loss 变低，让你以为模型变好了。**

所以我们下一章要面对的是这么一个局面：

把 attention 加回来，模型就能看到整段序列。可是我们的训练数据是"输入 `ids[t:t+T]`、答案 `ids[t+1:t+T+1]`"——位置 t 的答案就是位置 t+1 的输入。于是每一个位置都能看到自己的答案。

它会学得飞快，loss 会掉得比谁都低。

**我们要怎么挡住它？**
